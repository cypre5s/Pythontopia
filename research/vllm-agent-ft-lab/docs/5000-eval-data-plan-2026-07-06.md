# 5000-Case Evaluation Data Plan

Date: 2026-07-06

## Goal

Build a 5000-case evaluation pack for the Pythontopia Qwen fine-tuning story. The pack must test whether high scores such as `1.000` indicate real generalization or only memorization/template fitting.

## Open Dataset Search

I checked public computing-education datasets before synthesizing the final pack.

- CSSPLICE Dataset Catalog lists many computing-education datasets, including CSEDM Python tutoring data, CodeWorkout, Blackbox, KC Modeling for Python, FalconCode, CS1QA, and other programming-learning logs: https://splice.cs.vt.edu/datasetcatalog/
- Google Research PRE provides Python Runtime Errors derived from Project CodeNet, with 2.4M Python submissions and runtime-error labels under a permissive community data license: https://github.com/google-research/runtime-error-prediction
- BlueJ Blackbox is explicitly for academic research by computing-education researchers, and the project page states that no new access is granted as of January 2026: https://bluej.org/blackbox/
- Figshare hosts a large Python/Bash programming-submission dataset for several courses, but its shape is code submissions and grades rather than Chinese tutoring dialogue: https://figshare.com/articles/dataset/_5_Million_Python_Bash_Programming_Submissions_for_5_Courses_Grades_for_Computer-Based_Exams_over_3_academic_years_/12610958
- CodeWorkout/DataShop data is useful for novice programming behavior, but access/export is DataShop-oriented and does not directly provide Pythontopia-style Chinese Web workshop requests: https://pslcdatashop.web.cmu.edu/DatasetInfo?datasetId=3458

Decision: do not directly mix these datasets into the 5000-case Pythontopia evaluation. They are still useful as references for noise categories and novice-error taxonomy. The final evaluation pack remains deterministic and project-grounded so every row can be audited against Pythontopia agents, KC, evidence rules, and safety rules.

## Generated Pack

Generated file:

- `research/vllm-agent-ft-lab/cases/domain_cases_5000_v1.jsonl`

Manifest:

- `research/vllm-agent-ft-lab/outputs/datasets/domain_cases_5000_v1_manifest.json`

Slice distribution:

- `new_question`: 2000
- `new_chapter_slice`: 1000
- `new_student_expression`: 1500
- `web_workshop_input`: 500

Course boundary: Pythontopia only has the official 7 chapters of `Python语言基础`. `new_chapter_slice` means new task contexts inside the official chapters; it does not invent non-existent chapters.

## Noise Coverage

The student-expression slice includes:

- vague references
- fragmented sentences
- mixed natural-language/programming terminology
- incomplete traceback memories
- low-confidence help requests
- anxious answer requests
- typo + pinyin + English/Python mix
- mobile short messages
- copy-pasted partial code fragments
- teacher-assignment context
- wrong KC guesses
- post-failure reflection

These patterns cover new-student typo noise, colloquial naming, Chinese-English mixing, inconsistent terminology, partial code/error context, and unsafe “give me the answer” pressure.

## Evaluation and Recording

The runner now records:

- `events.jsonl`: case start/finish events
- `metrics.csv`: per-case metrics plus `eval_slice`, `source_kind`, `chapter`, `kc`, noise profile, and Web input type
- `progress_snapshots.jsonl`: realtime progress summaries every N cases
- `summary.json`: fold-level summary
- `extended_summary.json`: slice/agent/chapter/noise/Web aggregations
- `charts/*.svg`: fold, noise, slice, chapter, Web input, latency, and progress charts

Manual blind-review export:

- `scripts/export_blind_review_pack.py`
- reviewer-facing CSV/JSONL hides automatic scores
- answer key stores automatic metrics for later agreement analysis
