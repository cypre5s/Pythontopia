# 阶段 02 — 账号、班级与小镇基础后端

## 1. 时间窗口与定位

- 建议日期：2026-05-23 ~ 2026-05-25（第 1 周第 3-5 天，3 天，可与阶段 03 部分并行）。
- 角色：2 名后端 + 1 名安全/权限把关人。
- 定位：搭建 Pythontopia 用户、班级、画像、世界状态的**最小后端契约**，让前端阶段 03 之后能在真实数据上跑通。

## 2. 本阶段目标

- 建立真实的注册/登录体系（学生、教师两种角色），不做社交登录、不做找回密码。
- 建立轻量班级架构最小可用版本：班级 CRUD、学生加入班级、班级绑定 `packId=43`。
- 建立画像 schema 的**表结构**（具体 Agent 在阶段 04 实现）。
- 建立小镇世界状态 schema：世界会话、玩家状态、NPC 状态、天气状态、作物状态（具体玩法在阶段 03、05 实现）。
- 全部接口必须有 DTO、Bean Validation、统一错误返回与基础测试。
- 不做：学习路径、任务、资源、判题、Bug 矿洞、看板（属于后续阶段）。

## 3. 上下游关系

- 上游：阶段 01（课程包数据）。
- 下游：
  - 阶段 03 的前端登录、人物初始化、地图加载会消费本阶段 API。
  - 阶段 04 的画像 Agent 会写入 `learner_profile` 等表。
  - 阶段 05 的作物系统会写入 `crop_tile_state`。
  - 阶段 08 的任务系统会扩展 `quest` 表（本阶段只占位 schema）。
  - 阶段 12 的班级看板会扩展班级表与新增 `classroom_kc_snapshot`。

## 5. 任务清单

### 5.1 账号与角色

- T02-01 新增 Flyway 迁移 `V010__auth_users_roles.sql`：
  - 表 `users`：`id BIGSERIAL`、`username VARCHAR(64) UNIQUE NOT NULL`、`display_name`、`password_hash VARCHAR(128) NOT NULL`、`email VARCHAR(128) UNIQUE`、`role VARCHAR(16) NOT NULL CHECK (role IN ('STUDENT','TEACHER'))`、`status VARCHAR(16) DEFAULT 'ACTIVE'`、`created_at`、`updated_at`。
  - 索引：`idx_users_role_status`。
- T02-02 `com.pythontopia.auth.security`：
  - `PasswordEncoderConfig`：`BCryptPasswordEncoder`，强度 10。
  - `JwtProperties`、`JwtService`：HS256，签名密钥从环境变量 `PYT_JWT_SECRET` 读取，启动时空值直接 `fail fast`。
  - `SecurityConfig`：开放 `/api/auth/**`、`/healthz`、`/v3/api-docs/**`、`/swagger-ui/**`；其他 `/api/**` 必须携带有效 JWT。
- T02-03 `com.pythontopia.auth`：
  - `controller/AuthController`：
    - `POST /api/auth/register`：DTO `RegisterRequest{username, password, displayName, role, email?}`，返回 `UserDto`。教师注册需要邀请码（从 `PYT_TEACHER_INVITE_CODE` 校验），未提供或不匹配直接 403。
    - `POST /api/auth/login`：DTO `LoginRequest{username, password}`，返回 `LoginResponse{token, expiresAt, user}`。
    - `POST /api/auth/refresh`（可选，Beta 内允许返回 501）。
  - `service/AuthService`：注册写入 `users`；登录校验密码；签发 JWT。
  - `dto/UserDto`：暴露 `id`、`username`、`displayName`、`role`，**不**暴露 `passwordHash`、`email`。
- T02-04 在 `com.pythontopia.common` 增加 `CurrentUser` 解析器：从 Spring Security `Authentication` 拿到 `userId`、`role`，供后续 Controller 注入参数使用。

### 5.2 班级架构

- T02-10 Flyway 迁移 `V011__classroom_core.sql`：
  - 表 `classrooms`：`id`、`name`、`description`、`teacher_id`（FK to `users`，role=TEACHER）、`pack_id`（默认 43，CHECK = 43）、`join_code`（6 位随机字符串，UNIQUE）、`status`（`ACTIVE`/`ARCHIVED`）、`created_at`。
  - 表 `classroom_members`：`id`、`classroom_id`、`student_id`、`status`（`ACTIVE`/`REMOVED`）、`joined_at`，唯一约束 `(classroom_id, student_id)`。
- T02-11 `com.pythontopia.classroom`：
  - `controller/ClassroomController`：
    - `POST /api/classrooms`（教师）：DTO `CreateClassroomRequest{name, description?}`，自动生成 `joinCode`。
    - `GET /api/classrooms/mine`：教师返回自己创建的班级；学生返回自己加入的班级。
    - `POST /api/classrooms/join`（学生）：DTO `JoinClassroomRequest{joinCode}`，加入成功返回班级 DTO。
    - `GET /api/classrooms/{id}/members`（仅教师）：返回学生 DTO 列表。
    - `DELETE /api/classrooms/{id}/members/{studentId}`（仅教师）：软删除。
  - `service/ClassroomService`：限制教师只能操作自己班级；学生只能加入未归档班级。
  - `dto/ClassroomDto`、`ClassroomMemberDto`：禁止暴露密码哈希、邀请码（仅教师才能看到 `joinCode`）。
- T02-12 班级 schema 约束在 Service 层做：教师角色才能创建班级、学生角色才能加入班级，违反返回 `403`。

### 5.3 画像 schema（仅表结构）

- T02-20 Flyway 迁移 `V012__learner_profile_schema.sql`：
  - 表 `learner_profile`：`id`、`user_id UNIQUE`、`pack_id`（=43）、`major`、`base_level`（JSONB，结构在阶段 04 锁定）、`learning_goal`、`cognitive_style`、`learning_preference`（JSONB）、`error_patterns`（JSONB）、`practice_capability`（JSONB）、`emotion_persistence`（JSONB）、`narrative_summary`、`updated_at`。
  - 表 `profile_interview`：`id`、`user_id`、`session_id`（UUID）、`status`（`OPEN`/`COMPLETED`/`ABORTED`）、`started_at`、`completed_at`。
  - 表 `profile_revision`：`id`、`user_id`、`source`（`INTERVIEW`/`SUBMISSION`/`DEBUG`/`RESOURCE_FEEDBACK`/`QUEST`/`CLASSROOM`）、`diff`（JSONB）、`created_at`。
- T02-21 本阶段**不**提供画像写入 API。只提供：
  - `GET /api/learner/profile`：当前学生的画像；未生成时返回 `204 No Content`。
  - 其他写入 API 与对话路由由阶段 04 实现。

### 5.4 小镇世界 schema

- T02-30 Flyway 迁移 `V013__world_state_schema.sql`：
  - 表 `world_session`：`id`、`user_id`、`day_index INT`、`weather VARCHAR(16)`、`in_game_minutes INT`、`started_at`、`last_active_at`，约束 `(user_id) UNIQUE`（同一学生只保留一个会话）。
  - 表 `player_state`：`id`、`user_id UNIQUE`、`avatar_key`、`map_key`、`tile_x INT`、`tile_y INT`、`direction VARCHAR(8)`、`updated_at`。
  - 表 `npc_state`：`id`、`world_session_id`、`npc_key`、`mood`、`last_talk_at`，`(world_session_id, npc_key) UNIQUE`。
  - 表 `weather_state`：`id`、`world_session_id UNIQUE`、`current_weather`、`forecast`（JSONB），保留以便阶段 05 接入真实天气。
  - 表 `crop_tile_state`：`id`、`user_id`、`tile_x`、`tile_y`、`kc_code`、`growth_stage`、`mastery_score`、`last_watered_at`、`updated_at`，`(user_id, tile_x, tile_y) UNIQUE`。本阶段仅建表，不写入数据。
- T02-31 `com.pythontopia.world`：
  - `controller/WorldController`：
    - `GET /api/world/session`：返回当前学生的世界会话；不存在时自动创建（`day=1`, `weather=SUNNY`, `inGameMinutes=480`）。
    - `PATCH /api/world/player`：DTO `PlayerStatePatch{tileX, tileY, direction}`，更新位置；坐标范围校验在阶段 03 地图大小确定后补齐，本阶段只校验为整数。
  - `service/WorldService`：写入 `world_session`、`player_state`；NPC、天气、作物的写入在后续阶段。
  - `dto/WorldSessionDto`、`PlayerStateDto`、`NpcStateDto`。

## 7. 验收标准

### 7.1 功能验收

- 学生 A 注册 → 登录 → `GET /api/world/session` 返回新建会话，`day=1`、`weather=SUNNY`。
- 教师 T 用正确邀请码注册 → 创建班级 → 学生 A 用 `joinCode` 加入 → 教师 T 通过 `GET /api/classrooms/{id}/members` 看到学生 A。
- 学生 B 在未登录情况下访问 `/api/world/session` 返回 401，`ApiError.code=UNAUTHORIZED`。
- 学生 A 尝试 `POST /api/classrooms` 返回 403，`ApiError.code=FORBIDDEN`。
- 学生 A 当前未生成画像时 `GET /api/learner/profile` 返回 204。

### 7.2 数据验收

- `users.role` 只接受 `STUDENT`、`TEACHER`，写入其他值数据库报错。
- `classrooms.pack_id` 强制为 43，写入其他值数据库报错。
- `(classroom_id, student_id)` 唯一约束在重复加入时返回 409。

### 7.3 工程验收

- 所有 Controller 至少 1 个集成测试。
- 所有 DTO 与实体彻底分离；`UserDto` 不含 `passwordHash`、`email`，`ClassroomDto` 仅对教师返回 `joinCode`。
- `GlobalExceptionHandler` 覆盖 4 类异常并通过测试断言响应字段。
- `mvn test` 100% 通过。
- `application.yml` 中无明文密钥、无明文邀请码。

## 9. 风险与回滚

- 风险：JWT 密钥未设置导致启动失败；缓解：`application.yml` 在 `local` profile 提供示例命令而非默认值，CI 在 `test` profile 使用临时密钥。
- 风险：Testcontainers 在评审机器无法拉取镜像；缓解：在 `deploy/README.md` 给出 mirror 配置方法。
- 风险：邀请码硬编码或泄漏；缓解：通过环境变量并在文档强调演示前重新生成。
- 回滚：本阶段所有迁移都是 `V010`-`V013`，可单独删除迁移并清空对应表实现回滚（注意班级表存在外键，先 `DELETE FROM classroom_members → classrooms → users` 顺序清空）。
