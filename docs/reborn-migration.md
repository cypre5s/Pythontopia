## 接下来值得验证的事项

| 条件出现时 | 要做什么 | 保留的边界 |
| --- | --- | --- |
| 配置真实判题服务 | 在兼容的隔离Linux环境复验Judge0实际执行与异常对账 | 旧基础设施故障和最后轮跳过仍有效；未知送交不盲重发 |
| 准备真实AI/S3/转换部署 | 分别做授权、故障、隔离和真实外部服务验证 | 概念题、零模型调用和PDF导入不能替代这些live检查 |
| 修改生产能力开关 | 用独立生产 QA 复验普通学生开发菜单与普通重置路由保持关闭，并检查体验重置权限 | 重玩只影响认证学生当前授权存档，验收使用新建身份 |
| 原GPU问题再次出现 | 在原设备记录复现条件并复查地图显示 | 现有截图不能证明间歇黑线已根治 |
| 确定真实用户规模或新增设备支持 | 做对应容量或设备验收 | 当前CI仅1080P桌面，旧读取负载不代表AI/判题容量 |
| 补齐素材授权资料 | 对照保留来源核对书面材料与许可 | 功能完成不能替代来源证据 |

这些是有条件的后续验证，不是新增产品功能或必须恢复的旧系统。详细历史失败和证据见[验收边界](acceptance.md#失败跳过与未覆盖项)。

## 每轮接续

开始时复核requirements；结束时记录需求是否变化、修改的当前规范、实际验证和剩余事项。新增需求先更新对应约束及拥有文档；无新增需求也要在requirements的本轮记录中写明影响范围与保持结论。开发说明只维护可执行的当前流程，验收只保留摘要与证据，详细历史统一归档。按[文档维护流程](README.md#每轮维护流程)检查后使用中文提交。
