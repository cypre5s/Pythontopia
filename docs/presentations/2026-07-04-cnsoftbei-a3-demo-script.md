# Pythontopia 中国软件杯 A3 6 分钟演示脚本

适用视频: 中国软件杯 A3 初赛演示视频, 建议时长 5 分 50 秒到 6 分 20 秒, 不超过 7 分钟。

演示目标: 让评委在短时间内看到 Pythontopia 的完整学习闭环: 画像生成, 多智能体资源生成, GraphRAG 证据链, 正式判题, Bug 调试, 个性化路径更新, 教师班级补救。

录制建议:

1. 提前启动全栈服务, 保证前端、后端、graph、rag 都健康。
2. 浏览器缩放 90% 或 100%, 分辨率建议 1920 x 1080。
3. 提前登录学生账号和教师账号, 避免视频时间消耗在登录。
4. 如果现场 LLM 响应慢, 可先生成一条资源, 录制时点击同一资源详情, 但仍展示 run id、证据页和 Agent 时间线。
5. 录屏时保持鼠标移动干净, 每个页面停留 4 到 8 秒, 关键卡片放大或停顿。

## 1. 00:00 到 00:35 开场: 小镇首页与主线地图

### 画面操作

1. 打开浏览器访问演示地址。
2. 进入 `/world` 或系统首页, 展示像素小镇主界面。
3. 点击或切换到 `/mainline-map`。
4. 鼠标停留在当前章节节点, 展示学生当前进度。
5. 再点击一个章节进入 `/mainline/stage/:stageId`, 快速展示看、学、练三段任务。

### 逐字旁白

大家好, 我们的作品是 Pythontopia, 面向高校 Python 初学者的个性化学习小镇。它不是一个普通的课程网站, 也不是简单套了游戏皮肤的聊天机器人。我们的核心目标是把大模型、多智能体、课程 RAG、学习者画像和真实代码判题放进同一个学习闭环里。

在这个小镇里, 学生每一章都要完成看、学、练、测。看是课程视频和课件, 学是 AI 工坊生成的个性化资源, 练是训练场里的 Python 正式判题, 测是微测和章末测试。系统会根据这些真实行为持续更新学生画像和学习路径。

## 2. 00:35 到 01:20 画像馆: 8 维动态学习者画像

### 画面操作

1. 点击导航进入 `/profile`。
2. 展示画像雷达图。
3. 鼠标依次指向 8 个维度: 专业背景、知识基础、学习目标、认知风格、学习偏好、易错模式、实践能力、情绪与坚持度。
4. 展示画像修订或维度说明区域。
5. 如果页面有自评入口, 点击一个维度但不一定提交。

### 逐字旁白

这里是学生画像馆。赛题要求至少 6 个画像维度, 我们实现了 8 个维度, 包括专业背景、知识基础、学习目标、认知风格、学习偏好、易错模式、实践能力和情绪与坚持度。

画像不是一次问卷后就固定。学生和 ProfileAgent 对话会形成画像草稿, 学生做题、看资源、调试错误、完成任务也会产生 LearningEvent。后端的被动画像服务会把这些事件转成画像修订。例如学生多次在循环边界出错, 易错模式会变化; 如果失败后通过 Bug 矿洞修复并重交成功, 实践能力和坚持度都会上升。这样系统理解的是一个持续变化的学习者, 而不是一个静态标签。

## 3. 01:20 到 02:35 百晓工坊: 多智能体资源生成

### 画面操作

1. 进入 `/workshop`。
2. 在知识点选择区选择一个适合演示的 KC, 推荐 `for 循环`、`列表` 或 `input 函数`。
3. 展示资源类型选择, 依次用鼠标扫过讲义、思维导图、练习、代码实验、拓展阅读、动画分镜。
4. 选择一个最稳定的资源类型, 推荐讲义或思维导图。
5. 点击生成按钮。
6. 等待生成时展示进度、流式日志或工具时间线。
7. 生成完成后打开资源详情。

### 逐字旁白

接下来进入百晓工坊。这里是本项目最符合赛题 A3 的核心页面。学生不是自己去翻所有资料, 而是选择当前薄弱知识点和想要的资源类型, 由多智能体系统生成个性化学习资源。

赛题要求至少 5 类资源, 我们实现了 6 类, 分别是讲义、思维导图、练习、代码实验、拓展阅读和动画分镜。每一种资源背后都有对应的 Agent, 例如 MindMapAgent 负责知识结构, PracticeAgent 负责练习, CodeLabAgent 负责代码实验, StoryboardAgent 负责动画分镜。

请注意这里的生成输入不只是一个知识点。系统会同时读取学生画像、掌握度、最近提交、最近资源消费、班级任务和课程证据。所以同样是 for 循环, 基础弱的学生会得到更细的分步解释, 实践能力强的学生会得到更接近项目任务的代码实验。

## 4. 02:35 到 03:25 资源详情: GraphRAG 证据链与安全审查

### 画面操作

1. 在资源详情页展示生成出的标题、内容结构和资源卡片。
2. 滚动到引用或证据区域, 展示课件页引用或 evidence page ids。
3. 展示 Agent 时间线或工具调用区, 重点停留在 evidence fetcher、grounding critic、hallucination detector、safety critic。
4. 如果有检查按钮, 点击资源检查或微测区域, 展示资源不是生成完就算掌握。

### 逐字旁白

这里展示的是生成结果。Pythontopia 并不是直接把大模型输出展示给学生。每个资源在发布前都会走 GraphRAG 和反幻觉流水线。

首先, RAG 服务会从 Python 语言基础课程包中检索证据。我们的课程底座包含 7 份文档、561 页课件、7 章、65 个知识点、46 个示例和 39 道题。检索时会结合向量检索、BM25 关键词检索和知识点前置关系扩展。

然后资源图会执行多个审查节点, 包括证据扎根、幻觉检测、语义一致性和安全审查。后端会把 run id、Agent 名称、输入摘要、输出 artifact、证据页、安全结果和 grounding result 都保存下来。这样评委可以看到, 我们不是展示一个不可解释的 AI 文本框, 而是把大模型变成了可审计的教学生产线。

## 5. 03:25 到 04:25 训练场与 Bug 矿洞: 正式判题和调试补救

### 画面操作

1. 进入 `/training`。
2. 选择一个 Python 基础题。
3. 展示代码编辑区和题目描述。
4. 粘贴或输入一个有小错误的代码, 点击正式提交。
5. 展示 verdict 为 WA 或 Runtime Error。
6. 点击进入 `/bug-mine` 或错误详情中的调试入口。
7. 展示 Bug 矿洞里的诊断卡片、反例、变量轨迹或修复提示。

### 逐字旁白

个性化学习必须能验证学生是否真的会了。所以我们把 Python 练习分成两条轨道: 前端 Pyodide 只做即时预览, 正式成绩必须走服务端判题。正式提交会进入后端 SubmissionService 和 JudgeService, 完成静态检查、测试用例执行和 verdict 归档。

现在这个提交失败了, 系统不会只告诉学生错了。它会把失败提交带入 Bug 矿洞。这里 DebugAgent 会结合判题反例、变量轨迹、当前知识点和学生历史错误模式生成调试卡片。提示是分层给出的, 目的是帮助学生自己修复, 而不是直接泄露可以复制提交的完整答案。

这个失败和调试过程同样会回写学习事件。它会影响知识点掌握度、易错模式和实践能力, 也会影响下一步推荐。

## 6. 04:25 到 05:10 路径和推荐: 学习状态回流

### 画面操作

1. 回到 `/mainline-map` 或推荐面板。
2. 展示当前章节进度、掌握度或今日推荐。
3. 如果有资源推荐卡片, 展示推荐理由, 如弱 KC、失败题、画像偏好。
4. 点击一个推荐卡片, 展示可以跳回工坊、训练场或章节页。

### 逐字旁白

刚才的学习行为不会停留在单个页面。系统会把页面阅读、资源检查、正式提交、Bug 调试、章测结果都转换为 LearningEvent, 再由 MasteryEvaluator 更新知识点掌握度, 由被动画像服务更新 8 维画像。

路径规划服务会读取画像、掌握度、课程知识点、前置关系、班级任务、近期提交和失败模式, 生成可执行的学习路径。推荐系统给出的不是泛泛的猜你喜欢, 而是下一步最应该做的学习动作。例如现在如果学生在 for 循环边界条件上失败, 推荐就会优先出现相关讲义、练习或 Bug 矿洞复盘。

## 7. 05:10 到 05:50 教师端: 班级热力图和一键补救包

### 画面操作

1. 切换到教师账号或直接打开 `/teacher`。
2. 进入某个班级详情页。
3. 展示 KC 热力图、任务完成率、高频误区、资源使用情况。
4. 鼠标停留在一个低掌握度 KC 上。
5. 点击一键补救或生成补救包按钮。
6. 展示系统生成讲义和练习的入口或结果。

### 逐字旁白

最后看教师端。对于真实高校课堂, 只有学生端是不够的。教师需要知道全班在哪些知识点上卡住, 哪些任务没完成, 哪些错误最集中。

这里的 KC 热力图、任务摘要、高频误区和资源使用情况, 都来自学生真实学习事件和正式判题数据。教师可以对薄弱知识点一键生成补救包。补救包同样调用资源工坊, 生成讲义和练习, 并保留证据页、安全结果和 Agent 运行记录。这样 AI 不只是学生的聊天助手, 也成为教师的课堂补救生产力工具。

## 8. 05:50 到 06:10 收束: 架构和赛题符合性

### 画面操作

1. 切到 PPT 架构页, 或在系统页面中展示技术架构图。
2. 用鼠标指出前端、后端、graph、rag、PostgreSQL、Redis。
3. 最后回到小镇或项目 Logo 页。

### 逐字旁白

从技术架构上, Pythontopia 前端使用 Vue 3、TypeScript 和 Phaser, 后端使用 Java 21 和 Spring Boot, AI 微服务使用 FastAPI, 数据层使用 PostgreSQL、pgvector 和 Redis。系统支持 SSE 流式输出、GraphRAG 证据引用、多智能体资源生成、多模态分镜和正式 Python 判题。

总结来说, Pythontopia 对 A3 赛题的回答是: 用大模型生成资源, 但不止于生成。我们把画像、证据、资源、练习、路径、补救和教师干预连成一个闭环, 让 AI 真正参与 Python 学习全过程。谢谢大家。

## 10. 备用处理

| 问题 | 处理 |
|---|---|
| LLM 生成太慢 | 展示提前生成好的资源, 但保留生成入口和运行记录 |
| 多模态视频合成太慢 | 展示 STORYBOARD 分镜和媒体任务进度, 不强求完整播放 |
| 判题服务响应慢 | 使用已存在的失败提交进入 Bug 矿洞 |
| 教师端数据不足 | 使用预置演示班级或已有测试数据 |
| 公网网络波动 | 使用本地环境录制, 片尾补充 ECS 部署验收截图 |
