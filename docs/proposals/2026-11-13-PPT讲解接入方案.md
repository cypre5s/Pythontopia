## 0. 一句话

把「一份 PPT → 每页一段可审校的讲解稿 → 学生在阅读材料时按页看讲解」接进 reborn，**只借 `ppt-wxy` 的产品思路和提示词经验，不复用它的代码和流水线**。

## 1. `ppt-wxy` 现在是怎么做的（我读到的）

| 步骤 | 实现 | 位置 |
| --- | --- | --- |
| 上传 | 一章 = 一个 PPTX，落到 `uploads/<课程>/<章节>/` | `backend/app/api/v1/endpoints/file.py` |
| 转图片 | LibreOffice → PDF → `pdf2image` 150dpi → `images/slide_1..N.png` | `services/fileservice.py` |
| 写讲义 | **逐页把图片喂给 VLM**（DashScope `qwen3-vl-plus`，关思考）生成"授课文案"；隔页用 `Qwen2.5-72B` 提主题；`PageRelaAgent` 用前后页主题加过渡句 | `services/PageAgent.py`、`aiAgent.py`、`PageRelaAgent.py` |
| 配音 | 逐页 Sambert（`sambert-zhinan-v1`）合成 wav → pydub 转 mp3 → 合并 `merged_output.mp3`，记录每页起始秒 | `services/AudioAgent.py`、`sambert_compat.py` |
| 字幕 | 按**每 40 字一段、把音频总时长平均分**生成伪字幕 | `services/SubtitlesAgent.py` |
| 视频 | ffmpeg 两遍合成带字幕 `merged_output.mp4` | `file.py`（`generate_video`） |
| 任务状态 | 进程内 `TASK_STATUS` dict + 线程 + 前端轮询 | `file.py:53-110` |

它自己的代码审阅（`../CODE_REVIEW.md`（在 ppt-wxy 仓库，不在本仓库））结论是：**44 个端点里 43 个没有鉴权、密码明文、两把真实 API Key 提交过**。所以：**代码一行都不要拿**，只拿"产品形态"和"提示词约定"。

## 2. 我们不走的那套流程，以及为什么

| 他们的做法 | 为什么不走 | 我们改用什么 |
| --- | --- | --- |
| 一次点完「讲义 → 语音 → 字幕 → 视频」全链路 | 中间结果不可审校；任一页失败全链路重来；成本一次付清；教师没有否决权 | 每页一条讲解草稿，教师逐页接受/编辑，缺页可单独重试 |
| 用 VLM 读幻灯片图片 | 贵且不稳定（一张图一次调用）；我们**已经有 PDF 文本层**，先文本后图像 | 先只用 `material.content.pages[i].text`（现成的），纯图片 PPT 二期再议 |
| 任务状态放进程内 dict | 重启即丢，无法对账，多进程打架 | 复用现有的 material worker：`queued → processing → ready/failed` + 重启恢复 + 按 storage_key 认领 |
| 视频是唯一交付物 | 学生真正需要的是"这页在讲什么"；视频成本高、不可检索、不能引用 | 讲解稿是主产物；音频/视频是可选导出（二期决策） |
| 字幕按时长平均切 | 时间轴是假的，读起来违和 | 宁可先不做字幕；要做就用真实 TTS 时间戳 |
| 一章 = 一个 PPT、页 = 幻灯片 | 我们的模型是"材料 + 页 + 章节关联"，且要能进课程包 | 讲解挂在**材料页**上，跟着课程包走 |

## 3. 目标设计（推荐方案）

### 3.1 产物
每页一段**讲解稿（文本）**，状态三档：`draft`（AI 生成待审）→ `accepted`（教师接受）/ `rejected`。**只有 accepted 会出现在学生端和课程包里。** 可选第二产物是音频，二期再定。

### 3.2 数据落在哪（两个方案，推荐 A）

| | A：放进 `Material.content.pages[i]` | B：新表 `PageNarration` |
| --- | --- | --- |
| 迁移 | **零**（`content` 是 JSON，已随包走：`course_exchange.FIELDS` 里 Material 带 `content`） | 需要 Alembic 迁移 + 包格式扩展 + 版本兼容 |
| 审校轨迹 | 只能存"当前值" | 可存模型版本、审校人、时间、历史 |
| 实现成本 | 1 天级 | 3–5 天级 |
| 风险 | 后续想要历史/多人审校要再迁一次 | 前期就扛住长期需求 |

**推荐 A**，理由：先验证产品价值（老师到底会不会用、审校成本能不能接受），把"目录交换 + 课程包 + 学生阅读"这条主链跑通；等真的出现"要回溯某页是谁改的"再升级。要给 A 留后路：字段命名带版本（`narration: {schema_version, text, status, source, generated_at}`）。

### 3.3 生成怎么触发、怎么防重复

- **教师显式触发**：单页"生成本页讲解"，或整份"逐页生成"。默认**不**自动跑（保住 AI-02 的"零附带模型调用"）。
- **复用 material worker**：材料状态机里新增第二种任务（或 `narration_status` 队列），仍然串行、可重启恢复。
- **幂等键** = `sha256(页文本 + 提示词版本 + 模型名)`。重跑同输入不重复计费、不覆盖教师的编辑。
- **不留半成品**：一页成功才写一页；整份失败时已成功的页保留，失败页可单独重试。

### 3.4 审校（这是和 `ppt-wxy` 最大的区别）
- 后台材料编辑器里逐页展示：左"原文页文本"，右"待审讲解"，带 diff 高亮。
- 三个动作：接受 / 直接编辑后接受 / 丢弃。支持"批量接受剩余页"（否则 40 页逐页点会劝退老师）。
- 学生端与包导出都只认 `accepted`。

### 3.5 学生端形态
- 阅读工作区里，页面旁边（桌面）或下方（窄屏）显示当前页讲解稿；PDF/PPT 材料按 `pdfPage` 同步翻页。
- **讲解稿不是阅读证据**：完成阅读仍然按页计（现有 `required_page_ids`），不能因为看了讲解就算完成。
- 讲解稿标注来源：`AI 生成 · 教师已审校`（不伪造"老师亲自写的"）。

### 3.6 预算与凭据
- 教师侧生成用**单独配额**（每班每日 / 每份材料上限），不占学生的助教预算（学生预算是 `REBORN_AI_USER_DAILY_*` / `CLASS_DAILY_*`）。
- 没有 `REBORN_AI_API_KEY/MODEL` 时按钮明确不可用并说明原因（沿用现有"真实不可用"约定）。
- 单页输入按现有 40000 字符上限截断；输出长度设硬上限（例如 800 字/页）。

### 3.7 与课程包、班级隔离
- 讲解稿属于课程内容 → 随完整包导入/导出（方案 A 天然满足）。
- 不同班级对同一材料各自审校互不影响（包是每班一份实例）。
- 调用日志、模型名、密钥**不进包**。

### 3.8 音频（二期，需要决策）
| 路线 | 成本 | 质量 | 存储/授权 |
| --- | --- | --- | --- |
| 浏览器 `speechSynthesis` | 0 | 机械，但可用 | 无 |
| 服务端 TTS（需新凭据） | 按字计费 | 好 | 要存音频文件、要确认音色授权 |
| 不做音频 | 0 | — | — |

推荐：一期只做文本；音频等文本被接受率 > N 之后再谈。

## 5. 分阶段（每阶段都要能独立验收，也可以随时停）

### P1：数据与契约（0.5–1 天）
- 材料页 schema 加 `narration`（方案 A），定义 `schema_version/status/source`。
- 包导入导出、`write_package` 的往返测试。
- **不做**：生成、AI、UI。

### P2：生成任务（1–2 天）
- 教师接口：`POST /teacher/classrooms/{id}/materials/{mid}/narration`（单页/整份），凭配额。
- 复用 material worker 的队列与恢复；幂等键；失败可重试。
- 后端测试：配额、无凭据、幂等、部分失败、不写半成品。
- **不做**：审校 UI、学生端。

### P3：审校与教师界面（2 天）
- 后台材料页：逐页 diff、接受/编辑/丢弃、批量接受、状态筛选。
- **不做**：音频、视频。

### P4：学生端（1–2 天）
- 阅读工作区显示已接受讲解；PDF 页同步；窄屏布局；200% 字号可读。
- 浏览器回归：讲解不构成阅读完成证据。
- **不做**：讲解内联提问（那是把讲解纳入助教检索，另立需求）。

### P5（可选，需单独立项）：音频 / 视频 / 纯图片 PPT 的 VLM

## 6. 成本与风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 模型成本 | 一份 40 页材料 = 40 次调用；重跑一次就是又一笔 | 幂等键 + 教师配额 + 整份生成前显示"约 N 次调用" |
| 纯图片 PPT | PDF 文本层为空（截屏式 PPT 很常见），讲解只能靠看图 | 一期检测"页文本 < 阈值"就明确标记"本页无法生成，需人工或二期 VLM" |
| 审校负担 | 40 页逐页审 = 老师的真实工作量，可能直接劝退 | 批量接受 + diff 高亮 + 只高亮改动句子 |
| 质量与幻觉 | 讲解会"补充"页上没有的内容 | 提示词约束"只依据本页 + 明确可引用页"，并在审校界面提示"以下内容原文未出现" |
| 服务器压力 | 2C4G；生成是外部 API 调用，本地压力可控 | 串行队列，同一材料同时只跑一份 |
| 版权/授权 | AI 生成的讲解属于衍生内容 | 学生端标注来源；随包导出保留 `source.model` |

## 7. 需要你拍板的 5 件事

1. **音频做不做？** 不做（推荐）/ 浏览器朗读 / 服务端 TTS。
2. **是否允许"整份一键生成"？** 允许（省事，但要配额）还是必须逐页点（省成本、可控）。
3. **讲解稿风格**：口播稿（适合朗读，句子短）还是讲义稿（适合阅读，可以有结构）？两者提示词不同。
4. **要不要"学生就讲解继续提问"**？等于把讲解纳入助教检索范围，会改 AI-03 的引用边界。
5. **纯图片 PPT 是否值得上 VLM？** 不上则这类 PPT 无法自动生成讲解。

## 8. 我建议的最小可行范围（MVP）

> 只做「文本讲解 + 教师审校 + 学生阅读」，挂在现有 `presentation` 材料上，方案 A 存 JSON，复用 material worker，一期不碰音频、视频、VLM。约 4–6 天。先把"老师愿不愿意审、学生看不看"这件事验证掉，再决定要不要加音频和视频——那才是真正贵和重的那部分。
