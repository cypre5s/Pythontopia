# ZONOS3-Mini 语音接入方案（评估稿，未实施）

> 状态：评估/提案。**没有安装、没有构建、没有改代码。** 本文事实均来自官方仓库与 HF 模型卡（2026-11-13 抓取），标注了哪些我没验证到。

## 1. 这个模型是什么（已核实）

| 项 | 事实 | 来源 |
| --- | --- | --- |
| 类型 | 文本转语音（TTS），可零样本克隆音色 | HF 模型卡 |
| 许可 | **权重 Apache-2.0；运行时仓库 MIT**（可商用） | 模型卡 + GitHub LICENSE |
| 规模 | 800M 总参数 / ~100M 活跃（MoE），11 层、dim 1024 | 模型卡 |
| 音频 | 44.1 kHz 单声道，15 Hz 帧率，**单次最长 10 分钟** | 模型卡 |
| 语言 | 43 种，**含中文**（中文走 NeMo 文本规范化） | 模型卡 |
| 中文音色 | **只有 2 个**：`Haoran`（男，energetic）、`Meilin`（女，energetic） | `gguf/voices/README.md` |
| 默认音色总数 | 27 个（按语言分组，随模型一起发布，含 `.codes.npy` 与 `.embedding.npy`） | 同上 |
| 接口 | 官方服务端都实现同一套 HTTP：原生 `/v2/*` + **OpenAI 兼容 `POST /v1/audio/speech`** | GitHub README |
| 返回格式 | `pcm`（默认）或 `wav`，**没有 mp3** | ggml 服务端文档 |
| 鉴权 | 设 `ZONOS3_ACCESS_TOKEN` 后要求 `Authorization: Bearer` | 同上 |
| CPU 可行性 | 有 C++/ggml 服务端，CPU 可跑，**运行时不需要 Python**；官方称"手机和笔记本上实时" | 模型卡 + README |
| 模型体积 | 默认骨干 `backbone-ptq.gguf` **0.66 GB**（Q4_0 experts / Q8_0 mixers）；整 `gguf/` 目录 9.3 GB（含全尺寸解码器、浏览器分片） | ggml 文档 |
| 构建依赖 | CMake + **Rust 工具链**（文本规范化要 cargo 编译）+ git submodules | ggml 文档 |
| HF 托管推理 | **没有**（模型卡的 `inferenceProviderMapping` 为空）→ HF 的 serverless 不能直接调 | HF API |
| 官方托管 | 有 **Zyphra Cloud**（cloud.zyphra.com） | 模型卡 |

## 2. 三条接入路线

| | A. 自托管 CPU（ggml 服务端） | B. Zyphra Cloud API | C. 浏览器 WebGPU |
| --- | --- | --- | --- |
| 成本 | 0（自有机器） | 按调用计费（价格未知） | 0 |
| 运维 | 要建镜像（Rust+CMake）、灌模型、守内存 | 只要一个 key | 无 |
| 生产服务器（48 核） | **可以**（内存见 §2.1） | 可以 | 可以 |
| 延迟 | CPU 上未知，需实测；48 核可用线程多 | 取决于网络 | 首次要下 ~0.66GB 模型 |
| 学生设备要求 | 无 | 无 | 要 WebGPU + 显存 |
| 数据外流 | 无 | 只有待朗读文本 | 无（但模型进浏览器） |
| 音色可控 | 27 个 + 克隆 | 同 | 同 |
| 结论 | **推荐：自托管** | 备选（价格未知） | 不推荐（首屏包袱、设备差异） |

### 2.1 48 核机器上的资源核算

实测（`master`，2026-11-13 `free -h`）：**总内存 92 GB，可用 28 GB，无 swap**；CPU 约 48 核。

| 项 | 估算 | 结论 |
| --- | --- | --- |
| 常驻内存/实例 | **1.5–2.5 GB**（未实测）；容器给 `mem_limit: 4g` | 28 GB 可用 → **完全够**，可跑 1 个实例并留大余量 |
| CPU 线程 | 4–8 线程/实例 | 48 核上用 `cpus: 8`，不挤占其他人的负载 |
| 磁盘 | 最小 1–2 GB 模型 + 镜像 ≈ 3–4 GB；整 `gguf/` 9.3 GB | 需确认 `/var/lib/docker` 所在盘余量 |
| 构建 | Rust + CMake 编译一次，CPU 峰值高 | 优先用官方 release 预编译包；否则非高峰时段构建 |

**关键风险不是不够，而是"共享机 + 无 swap"**：
- 必须给容器设 `mem_limit`，否则模型加载峰值可能触发内核 OOM，被杀的可能是别人的进程；
- 不发布端口到公网，只走 internal 网络 + `ZONOS3_ACCESS_TOKEN`；
- 不 `docker image prune -a`，不动别人的容器/网络/证书。

### 2.2 仍建议的形态：**作者期生成，运行期只发文件**

即使机器够了，也不建议做成"学生点播放就实时合成"：
- 语音是**课程内容**，不是运行时产物：老师后台点生成 → 音频进私有存储 → 跟着课程包走；
- 学生端只播放已授权文件（`<audio>` + Range），**不触发任何模型调用**（守住 AI-02）；
- 同一段文本重复生成命中缓存，不重复计算；
- 好处：生成慢一点无所谓（作者期）；课堂高峰不碰 TTS；课程包导出后换机器也能放。
- 与产品流程对齐：**老师上传/生成 → 审核 → 发布章节 → 学生可见**，讲解稿和音频都参与这道审校门。

### 2.3 成本对比（决定用哪条）

我们的量级很小：一门课约 40 页、每页讲解 200–300 汉字 → **约 1 万汉字/门课**。按这个算：

| 方案 | 单价 | 一门课 1 万字 | 100 门课 | 备注 |
| --- | --- | --- | --- | --- |
| **自托管 ZONOS3** | 0 | ¥0 | ¥0 | 要 ~2GB 内存 + 构建/运维 |
| **SiliconFlow CosyVoice2-0.5B** | **¥0.05/千字符（UTF-8 字节）**，中文约 ¥0.15/千字 | **≈ ¥1.5** | ≈ ¥150 | 价格已从官方价格页核实；OpenAI 兼容 `/v1/audio/speech`（旧工程里调过这个地址） |
| 阿里 DashScope（qwen-audio-3.1-tts-flash / cosyvoice） | 按量计费，具体单价需登控制台看 | — | — | 官方页是 JS 渲染，没抓到数字 |
| Azure / OpenAI / ElevenLabs | 数量级更贵（$15/1M 字符级） | — | — | 中文可用，但没必要 |

结论：**钱不是选型理由**（最贵也百元级）。真正决定的是三条：能不能调音色、要不要运维一个服务、要不要多一个供应商。

### 2.4 两条都能"调声色"，自由度不同

| | ZONOS3-Mini（自托管） | CosyVoice2（API） |
| --- | --- | --- |
| 情绪/语速 | `controls`（`delivery.tempo`、`mood.*`、`identity.gender`）+ accent 适配器；需 `steer.gguf` | 一般有 instruction/情绪参数，以供应商文档为准 |
| 音色设计 | 参考音频、192 维说话人向量，或按年龄/口音/音质"设计" | 以零样本克隆为主 |
| 音色数量 | 27 个默认 + 克隆 | 看供应商上架 |
| 自主性 | 完全自主：改语速、重生成、缓存都自己控 | 受供应商限流/价格/下线影响 |

## 3. 集成设计（无论选 A 还是 B，接口一样）

### 3.1 配置（沿用"缺凭据即不可用"）
```
REBORN_TTS_BASE_URL=        # 例如 http://zonos:1919（自托管）或云 API 地址
REBORN_TTS_API_KEY=         # 自托管时对应 ZONOS3_ACCESS_TOKEN；云 API 时是他们的 key
REBORN_TTS_MODEL=zonos3
REBORN_TTS_VOICE_ZH_MALE=default_d8a9b688b64e638d     # Haoran
REBORN_TTS_VOICE_ZH_FEMALE=default_eaee7325255d4783   # Meilin
REBORN_TTS_TIMEOUT_SECONDS=120
```
没配 `BASE_URL` 或 `KEY` → 后台按钮明确显示"未配置语音服务"，不生成假音频。

### 3.2 生成与缓存（幂等）
- 幂等键 = `sha256(文本 + 音色 id + 模型名 + 采样参数)`；命中直接复用，不重复计费/重复生成。
- 分段：单请求上限 `max_tokens` 默认 2000 行 ÷ 15 Hz ≈ **133 秒音频**，按句号/换行切段，段间插 150–250ms 静音拼回；每段都按幂等键缓存。
- 转码：服务端只给 `pcm|wav`。44.1kHz 16bit 单声道 wav ≈ **5.3 MB/分钟**，课程里放不下，落库前转 mp3/opus（需要 API 镜像里加 ffmpeg，或在生成端转）。
- 失败：单段失败只重试该段；不写"半份音频"。

### 3.3 存储与播放
- 走现有私有存储（`LocalStorage` / S3），key 形如 `narration-audio/<sha256>.mp3`；
- 播放走现有的授权媒体接口（带 Range），**不给公开静态路径**；
- 课程包导出/导入时，音频作为材料资源一起走（`assets/` + `index.jsonl`），这样换班/换机器不丢。

### 3.4 音色分配（现在不是问题了）

能讲课的 NPC 只有 1–2 个，中文默认音色正好两个：
- 讲解旁白固定 `Meilin`（`default_eaee7325255d4783`）；
- 讲课 NPC 用 `Haoran`（`default_d8a9b688b64e638d`），要区别语气时用 `controls`（语速/情绪）微调；
- 不再需要批量克隆；将来真要专属音色，再走"书面授权 + 可撤销"流程；
- 千万不做：未经同意克隆真人（尤其是学生）的声音。

### 3.5 合规与署名
- 权重 Apache-2.0 可商用，但要在 仓库根的 `LICENSE-ART.md` / `legal/` 里登记：模型名、版本、许可、来源 URL、音色来源。
- 默认音色是随模型发布的示例素材；如果把它们用于产品播报，建议在致谢页写明"语音由 ZONOS3-Mini 生成"。
- 若将来克隆真人音色：需要书面授权、保存授权凭据、提供下线方式；这一步不要顺手做。

## 4. 分阶段（每步都能独立验收）

| 阶段 | 内容 | 验收 | 明确不做 |
| --- | --- | --- | --- |
| B0 基准（半天） | 在 48 核机上用 ggml 服务端跑通 `/v1/audio/speech`，量 3 段中文的 **RTF、内存、首字延迟**，并试 `--zac-threads` 多解码通道 | 有实测数字：单实例吞吐（秒音频/秒）与峰值内存 | 不接进项目 |
| B1 作者期生成（1–2 天） | 后台"生成/重生成本页音频"、幂等缓存、私有存储、失败重试 | 后端测试：无凭据、幂等、分段、失败不写半成品 | 不做实时、不做学生端 |
| B2 学生播放（1 天） | 阅读工作区播放当前页音频（含倍速、进度记忆） | 浏览器回归：播放不产生模型调用；200% 字号可用 | 不做字幕对齐 |
| B3 课堂即时生成（可选） | 若 B0 证明吞吐够，再加"老师在课堂上现场生成一页" | 并发压测 + 配额 | 不做多人并发直播、不做流式播放 |

## 5. 需要你拍板

1. **生成端放哪**：先接便宜 API（SiliconFlow CosyVoice2，几分钟能跑）还是直接用 48 核机器自托管 ZONOS3（零边际成本、音色更可控，但要建镜像/守内存）。两者接口相同，随时可换。
2. **内存多少**：那台 48 核机器是 8 / 32 / 64 / 96 GB？（决定自托管稳不稳）
3. **音频范围**：只做讲解旁白，还是也给那 1–2 个讲课 NPC 配音？
4. **格式**：接受 mp3（需 ffmpeg）还是直接用 wav（体积 ×5，但零依赖）？

## 6. 我的建议（一句话）

内存实测可用 28 GB、48 核、且生成不是实时需求 → **自托管 ZONOS3 作为独立 compose 服务（`mem_limit: 4g`、`cpus: 8`、仅内部网络、带 token）是首选**：零边际成本、可调音色、不依赖第三方；仍按"老师生成 → 审核发布 → 学生只播放文件"的形态跑。想当天就看到第一段音频，可以先接 SiliconFlow CosyVoice2（同接口），再换回自托管。

## 7. 部署骨架（待你同意后再做）

```yaml
# deploy/compose.yml 里新增，profile 默认不开
  tts:
    profiles: [tts]
    image: pythontopia-reborn-tts:local   # 多阶段构建，或官方 release 二进制 + 模型
    command: >
      zonos3-server gguf/backbone-ptq.gguf --port 1919 --host 0.0.0.0
      --tts-default-voices-dir gguf/voices --zac gguf/zac-keep2.gguf
    environment:
      ZONOS3_ACCESS_TOKEN: ${REBORN_TTS_TOKEN:?set in deploy/.env}
    mem_limit: 4g
    cpus: 8
    read_only: true
    tmpfs: [/tmp:rw,nosuid,nodev,size=256m]
    volumes: [reborn-tts-models:/models:ro]
    networks: [default]          # 不发布端口，只有 API 能访问
    healthcheck: ... # GET /v2/capabilities
    restart: unless-stopped
    logging: {driver: json-file, options: {max-size: 10m, max-file: "3"}}
```

上线前需要实测的四个数字（B0）：**峰值内存 / 单实例 RTF / 首字延迟 / 长文本分段表现**。
