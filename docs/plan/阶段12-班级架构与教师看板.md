# 阶段 12 — 班级架构与教师看板

## 1. 时间窗口与定位

- 建议日期：2026-06-11 ~ 2026-06-14（第 4 周第 1-4 天，约 3 ~ 4 天）。
- 角色：1 名后端 + 1 名前端 + 1 名教学顾问（提供教师诉求）。
- 定位：在阶段 02 已建好的最小班级 schema 基础上，把"轻量班级"做到可演示、可教学：教师能发布班级任务、查看 KC 热力图、任务完成率、高频误区与资源使用情况。**不做**全功能 LMS。

## 2. 本阶段目标

- 教师视角：
  - 创建班级、复制 joinCode、分享给学生。
  - 发布班级任务（绑定 KC 与题目）。
  - 班级看板：KC 热力图、任务完成率、高频误区、资源使用情况、最近活跃学生。
- 学生视角：
  - 公告板"班级任务" tab 真实展示 + 一键接受。
  - 班级任务完成会同时反映到 `learning_path_node`（由阶段 08 已接管）。
- 教师任务必须有"题目"或"KC 资源类型"作为锚点；禁止纯文字、无验收点的任务。
- 班级看板不做实时大屏，按需刷新即可（学生 ≤ 50、KC ≤ 65 的规模一次性算清）。

## 5. 任务清单

### 5.1 schema 扩展

- T12-01 Flyway 迁移 `V080__classroom_kc_snapshot.sql`：
  - `classroom_kc_snapshot`：`id`, `classroom_id`, `kc_code`, `avg_mastery NUMERIC(4,3)`, `student_count INT`, `passed_count INT`, `failed_count INT`, `top_error_categories` JSONB, `computed_at`。
  - 用于看板查询缓存（每次教师打开看板触发重新计算 + upsert）。
- T12-02 复用阶段 08 `classroom_quest` 表，**本阶段补**：
  - 写入 API、与 `quest` 表的同步逻辑：教师发布班级任务后，对该班级所有 `ACTIVE` 成员生成 `quest`（`source=CLASSROOM`, `source_ref_id=classroom_quest.id`）。
  - 已存在 `quest`（重复发布相同 KC + due_date）的同一学生不重复生成；用唯一约束保护。
- T12-03 Flyway 迁移 `V081__classroom_quest_extend.sql`：
  - 增 `classroom_quest.target_problem_id BIGINT`（可空，若指定则 quest 类型为 `SOLVE_PROBLEM`）。
  - 增 `classroom_quest.target_resource_type VARCHAR(16)`（若指定则 quest 类型为 `READ_RESOURCE`）。
  - 约束二者至少 1 个非空。

### 5.2 后端教师 API

- T12-10 `com.pythontopia.classroom`（扩展阶段 02 包）：
  - `controller/TeacherClassroomController`：
    - `PUT /api/teacher/classrooms/{id}`：更新班级基本信息（仅班主任）。
    - `POST /api/teacher/classrooms/{id}/regenerate-code`：重置 joinCode。
    - `GET /api/teacher/classrooms/{id}/members?status=`：返回成员列表 + 概况。
  - `controller/TeacherClassroomQuestController`：
    - `POST /api/teacher/classrooms/{id}/quests`：DTO `ClassroomQuestCreateRequest{title, description, kcCodes, targetProblemId?, targetResourceType?, dueDate}`，触发同步生成学生 `quest`。
    - `GET /api/teacher/classrooms/{id}/quests`：列出班级所有任务。
    - `POST /api/teacher/classrooms/{id}/quests/{questId}/archive`：归档（不删除学生已生成 quest）。
  - `controller/TeacherDashboardController`：
    - `GET /api/teacher/classrooms/{id}/dashboard/kc-heatmap`：返回 KC 热力图数据（每 KC 平均 mastery、学生数、状态分布）。
    - `GET /api/teacher/classrooms/{id}/dashboard/quest-summary`：返回任务完成率（按任务粒度）。
    - `GET /api/teacher/classrooms/{id}/dashboard/error-hotspots`：返回最近 7 天高频错误 KC + 错误类别。
    - `GET /api/teacher/classrooms/{id}/dashboard/resource-usage`：返回资源使用次数（按类型 + KC）。
    - `GET /api/teacher/classrooms/{id}/dashboard/recent-activity?limit=20`：返回最近活跃事件。
- T12-11 `service/ClassroomQuestService`：
  - 发布任务时事务化：写 `classroom_quest` + 批量插入 `quest`；幂等键 `(classroom_quest_id, user_id)`。
  - 归档时只更新 `classroom_quest.status`，已发出的学生 quest 不动（避免破坏学生进度）。
- T12-12 `service/ClassroomDashboardService`：
  - 计算逻辑全部基于已有事件表（`kc_mastery_event`、`quest_progress`、`practice_submission`、`learning_resource`）；写 `classroom_kc_snapshot` 缓存。
  - 班级规模 ≤ 50 时不引入异步；单次计算 ≤ 1 秒。

## 7. 验收标准

### 7.1 功能验收

- 教师 T 创建班级，分发 joinCode，3 名学生加入；`GET /api/teacher/classrooms/{id}/members` 返回 3 人。
- 教师发布班级任务（KC=`for-loop`, targetProblemId=12, due 后天）：
  - `classroom_quest` 增加 1 行。
  - 3 名学生的 `quest` 表均增加 1 行 `source=CLASSROOM`。
- 3 名学生中 2 人完成任务：
  - `GET /api/teacher/classrooms/{id}/dashboard/quest-summary` 返回该任务 `completionRate ≈ 0.67`。
  - KC 热力图中 `for-loop` 平均 mastery 上升。
- 教师重置 joinCode 后，旧 joinCode 不可加入。

### 7.2 教育验收

- 班级任务必须含 KC + (problemId 或 resourceType)；缺失返回 400。
- 任务文字中不含敏感个人信息（safety 校验 PII）。
- 看板上每个 KC 必须可点击查看具体学生分布；学生信息只在教师视角显示。

### 7.3 工程验收

- `mvn test`、`npm run test` 通过。
- 学生访问任何 `/api/teacher/**` 返回 403。
- 班级 30 人 + 任务 5 个时，看板 5 个接口总响应 ≤ 2 秒。
- DTO 中无学生敏感字段（密码、邮箱）。

## 9. 风险与回滚

- 风险：批量生成 quest 失败导致部分学生没有任务；缓解：事务内批量插入；失败抛 5xx 触发前端重试。
- 风险：教师误归档任务影响学生进度；缓解：归档只动 `classroom_quest`，学生 `quest` 不动；UI 二次确认弹窗。
- 风险：热力图聚合慢；缓解：班级 ≤ 50 同步算；> 50 在阶段 14 评估异步。
- 回滚：删除 `classroom_quest` 行 + 关联 `quest` 行可还原；保留 `quest_progress` 审计。
