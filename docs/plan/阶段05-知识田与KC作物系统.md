## 1. 时间窗口与定位

## 5. 任务清单

### 5.1 KC 掌握度计算

- T05-01 Flyway 迁移 `V030__kc_mastery.sql`：
  - 表 `kc_mastery`：`id`、`user_id`、`kc_code`、`mastery_score NUMERIC(4,3)`（0.000~1.000）、`confidence NUMERIC(4,3)`、`last_event_at`、`updated_at`，唯一约束 `(user_id, kc_code)`。
  - 表 `kc_mastery_event`：`id`、`user_id`、`kc_code`、`source`（`RESOURCE_READ`/`PRACTICE_PASS`/`PRACTICE_FAIL`/`DEBUG_FIX`/`MANUAL_OVERRIDE`/`DECAY`）、`delta NUMERIC(4,3)`、`reason`、`created_at`。
- T05-02 `com.pythontopia.learner.mastery`：
  - `MasteryEvaluator`：
    - `applyEvent(userId, kcCode, source, delta, reason)`：写入事件，更新 `kc_mastery`；上限 1.0，下限 0.0。
    - `decay(userId, kcCode, days)`：基于 `last_event_at` 做半衰期衰减（参数从 `application.yml` 读取，默认 `halfLifeDays=14`）。
    - 计算公式写在 `/home/cypress/Pythontopia/docs/mastery_formula.md`。
  - `MasteryService.getSnapshot(userId)`：返回所有 KC 的 mastery / confidence / 最近 source。
  - 本阶段 `applyEvent` 只暴露给同模块或同 package 服务（package-private 或 `@PreAuthorize` 限定），不开放为公共 API。

### 5.2 KC 列表与作物 schema

- T05-10 复用阶段 02 的 `crop_tile_state` 表；本阶段补充字段（Flyway 迁移 `V031__crop_tile_state_extend.sql`）：
  - 新增 `status VARCHAR(16)`（`SEED`/`SPROUT`/`MATURE`/`WITHERED`），`unlocked BOOLEAN`，`unlocked_at`，`pack_id INT NOT NULL DEFAULT 43`。
  - 索引 `(user_id, pack_id, kc_code)` 唯一。
- T05-11 `com.pythontopia.world.crop`：
  - `CropStateService`：
    - `getMap(userId)`：返回该学生的所有 `crop_tile_state`（按 `tile_x, tile_y` 排序）。
    - `applyMasteryUpdate(userId, kcCode)`：从 `MasteryEvaluator` 读 mastery，映射成 `status`：
      - `mastery < 0.2` → `SEED`
      - `0.2 ≤ mastery < 0.5` → `SPROUT`
      - `0.5 ≤ mastery < 0.8` → `MATURE`
      - 已收获后 `last_event_at` 超过 30 天 → `WITHERED`
    - `unlockCrop(userId, kcCode, tileX, tileY)`：由 `CurriculumMapperAgent` 调用。
  - `dto`：`CropTileDto`、`KcMasterySnapshotDto`。
  - `controller/CropController`：
    - `GET /api/world/crops`：返回所有作物状态（仅本人）。
    - `GET /api/learner/mastery`：返回 KC mastery snapshot。

### 5.3 CurriculumMapperAgent（结构化映射，不调用 LLM）

- T05-20 在 `services/pythontopia-graph/pythontopia_graph/agents/curriculum_mapper_agent.py` 实现：
  - 输入：`MapperInput(user_id, profile_summary, course_chapters, course_kcs)`。
  - 输出：`MapperOutput(plan_steps, tile_assignments, unlocked_kcs)`。
  - 算法（**全确定式，不调用 LLM**）：
    1. 按章节 + KC `difficulty` 排序。
    2. 根据画像 `base_level.python_self_rated_level` 决定起点：低水平从 `kc_code` 前 5 个开始；高水平允许跳过基础前 3 个。
    3. 把 KC 分组为"田垄"（每行 5 个），生成 `(tile_x, tile_y)` 坐标。
    4. 输出 `unlocked_kcs`：默认解锁前 8 个；其他 KC 需在路径推进时解锁（由阶段 08 触发）。
  - 因为是确定式映射，可在测试中精确断言输出。
- T05-21 该 Agent 暴露 HTTP：`POST /agents/curriculum/map`，输入 `MapperRequest{user_id}`（由后端按需调用）。
- T05-22 graph 服务内部要求：
  - 即便确定式，也走 LangGraph 单节点封装，方便后续接入 LLM 优化（保留扩展点，不引入 LLM）。

## 7. 验收标准

### 7.1 功能验收

- 完成画像的学生触发 `POST /api/learner/curriculum/bootstrap` 后：
  - `crop_tile_state` 至少存在 65 条（已解锁 + 未解锁，未解锁 `unlocked=false`）。
  - 已解锁 KC 数=8。
  - `kc_mastery` 至少含解锁 KC 的初始记录（`mastery_score=0`, `confidence=0`）。
- 知识田场景能渲染 65 个 KC 占位：未解锁显示为"未开垦"地块；已解锁显示为种子。
- 手动调用 `MasteryEvaluator.applyEvent(userId, kcCode, RESOURCE_READ, 0.3, ...)`：
  - `kc_mastery_event` 增加 1 行；`kc_mastery.mastery_score=0.3`；`crop_tile_state.status` 变为 `SPROUT`。
- 调用衰减后超过半衰期 KC 状态可变为 `SEED` 或 `WITHERED`。

## 9. 风险与回滚

- 风险：65 个 KC 全部渲染对低端机性能压力；缓解：未解锁 KC 用统一 placeholder sprite；已解锁 KC 才走帧动画。
- 风险：mastery 公式参数误配置导致衰减过快；缓解：参数集中在 `application.yml` 并写入 `mastery_formula.md`；提供脚本一键还原默认。
- 风险：CurriculumMapperAgent 引入 LLM 后失去可重复性；缓解：本阶段禁止引入 LLM，并在测试中断言确定式。
- 回滚：`kc_mastery`、`kc_mastery_event`、`crop_tile_state` 单 user 清空可还原。

## 10. 不做事项

- 不让 `CurriculumMapperAgent` 调用 LLM。
- 不在前端做 mastery 计算（必须由后端权威）。
- 不为知识田添加纯装饰系统（如农场动物）。
- 不开放 `MasteryEvaluator.applyEvent` 为公共 API（仅内部模块调用）。
- 不让 KC 在没有画像的情况下解锁（必须先做画像）。
