# 阶段 08 — 学习路径、每日任务与公告板

## 1. 时间窗口与定位

- 建议日期：2026-06-07 ~ 2026-06-09（第 3 周中段，约 3 天，可与阶段 09 并行）。
- 角色：1 名 Python Agent 负责人 + 1 名后端 + 1 名前端。
- 定位：把画像、KC 状态、资源生成、班级任务（占位）汇总到"今天该做什么"。是学生进入小镇后**最高频触达**的功能；也是教师班级任务展示的入口。

## 2. 本阶段目标

- 实现 `PathPlannerAgent`：以学生画像 + KC mastery + 资源历史 + 班级任务为输入，规划 7 日学习路径与每日任务清单。
- 后端实现 `learning_path`、`learning_path_node`、`quest`、`quest_progress` 等表与 API。
- 前端实现"公告板"场景与"我的路径"面板：学生可看个人路径、每日任务、班级任务（班级任务实际写入由阶段 12 完成，本阶段先消费 schema）。
- 任务系统支持：
  - 任务类型：`READ_RESOURCE`（读资源）、`SOLVE_PROBLEM`（做练习）、`FIX_BUG`（修矿洞）、`PLANT_KC`（种 KC）、`PROFILE_UPDATE`（补画像）。
  - 任务状态：`OPEN`、`IN_PROGRESS`、`COMPLETED`、`SKIPPED`、`EXPIRED`。
  - 任务来源：`PATH_PLANNER`、`CLASSROOM`、`SYSTEM_DEFAULT`。
- **不做**：完整通知系统、消息推送、跨日实时刷新（用按需刷新即可）。

### 5.2 PathPlannerAgent（pythontopia-graph）

- T08-10 `pythontopia_graph/agents/path_planner_agent.py`：
  - 输入：`PathPlannerInput{user_id, profile, kc_mastery_snapshot, recent_resources, recent_submissions, classroom_quests}`。
  - 输出：`PathPlannerOutput{path_nodes: list[PathNodeDraft{day_index, order_in_day, kc_code, node_type, reason_summary, evidence_summary, suggested_resource_type?, suggested_problem_id?}]}`。
  - 算法（**结构化 + 可解释**，可选 LLM 调用来生成"reason_summary"，但选 KC/类型必须由确定式规则决定）：
    - 优先解锁 mastery 最低且 prerequisite 已满足的 5 个 KC。
    - 每个 KC 按"先读资源 → 再做题 → 再修 bug"顺序排入 7 天。
    - 必须包含至少 1 个 `PROFILE_UPDATE` 节点（每 7 天回顾画像）。
    - 班级任务的 KC 必须出现在路径头部。
  - 节点输出经 `grounding_critic`：所有 KC code 必须存在；所有 problem id 必须存在；reason 中提到的页码必须能在 RAG 命中。
- T08-11 LangGraph 图：`load_inputs → planner_core → grounding_critic → safety → persistor_dry_run`。`persistor_dry_run` 仅产出 artifact，不写库（由后端写）。
- T08-12 路由 `POST /agents/path/plan`：返回 `PathPlannerResponse`。
- T08-13 当上游缺画像时，Agent 返回 400 + `code=PROFILE_REQUIRED`，并提示客户端"请先完成画像"。

### 5.3 后端路径与任务服务

- T08-20 `com.pythontopia.learner.path`：
  - `controller/LearningPathController`：
    - `POST /api/learner/path/plan`：触发新规划，调用 graph 服务，落 `learning_path`(`status=ACTIVE`，旧的归档为 `ARCHIVED`) + `learning_path_node` + 生成对应 `quest`（仅 `PATH_PLANNER` 来源）。
    - `GET /api/learner/path/active`：返回当前激活路径 + 节点。

  - `service/LearningPathService`：写库；保证一个学生同时只有 1 个 ACTIVE 路径。
- T08-21 `com.pythontopia.learner.quest`：
  - `controller/QuestController`：
    - `GET /api/quests/today`：返回今日 `OPEN`/`IN_PROGRESS` 任务（按 priority + due_date）。
    - `GET /api/quests?status=&source=`：分页查询。
    - `POST /api/quests/{id}/start`：标记 `IN_PROGRESS`，写 `quest_progress`。

## 7. 验收标准

### 7.1 功能验收

- 学生完成画像 + 知识田后触发 `POST /api/learner/path/plan`：
  - `learning_path` 出现 1 行 ACTIVE，旧路径归档。
  - `learning_path_node` 出现 7 天节点；每天 1~4 个节点。
  - 自动生成对应 `quest`，每个 quest 关联到资源 ID 或 problem ID。
- `GET /api/quests/today` 在 day=1 返回所有 day_index=1 的 quest。
- 学生点击"完成"任务：
  - `quest.status=COMPLETED`；`quest_progress` 增加 1 行。
  - 相关 KC mastery +0.05（受阶段 07 节流限制）。
- 系统默认任务在路径生成后自动归档。

### 7.2 教育验收

- 路径节点中至少 1 个 `PROFILE_UPDATE`、至少 1 个 `PLANT_KC`、至少 1 个 `SOLVE_PROBLEM`。
- 任务 `reason_summary` 字段必须解释"为什么是这个 KC、为什么是这种类型"（基于画像 + mastery）。
- 班级任务存在时一定出现在路径头部（day=1）。

### 7.3 工程验收

- 跨用户访问 quest 返回 403。
- 状态机非法跳转返回 400（如已 `COMPLETED` 的任务再次 `start`）。
- 前端 `npm run typecheck`、`npm run test` 通过；`BoardPanel` 不显示假任务。
- `mvn test`、`pytest -q` 通过。
- `learning_path.version` 单调递增。

## 9. 风险与回滚

- 风险：每次重新规划清空旧任务导致学生未完成进度被丢失；缓解：旧任务保留为 `EXPIRED` 或 `SKIPPED`，不删除；前端可在历史路径中查看。
- 风险：PathPlanner LLM 输出 reason 含未授权 KC；缓解：grounding critic 拒绝并 retry。
- 风险：定时器 `EXPIRED` 错杀今日任务；缓解：以学生本地时区为依据（Beta 演示固定 `Asia/Shanghai`）。
- 回滚：归档 `learning_path` + 删除关联 quest 可回滚；保留 `quest_progress` 作审计。

## 10. 不做事项

- 不做消息推送、邮件通知。
- 不做跨学生协作任务。
- 不做"AI 自动完成任务"功能（学生必须真实操作）。
- 不暴露 PathPlanner 内部规则给前端（前端只看 reason）。
- 不允许直接由前端修改 `quest.status` 跳过状态机。
