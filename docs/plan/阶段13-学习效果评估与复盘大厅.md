# 阶段 13 — 学习效果评估、路径重排与复盘大厅

## 1. 时间窗口与定位

- 建议日期：2026-06-13 ~ 2026-06-16（第 4 周第 3-6 天，约 3 ~ 4 天）。
- 角色：1 名后端 + 1 名 Python Agent 负责人 + 1 名前端。
- 定位：把累积的学习数据（画像、KC mastery、资源、提交、Bug 矿洞、quest）转化为**可解释的学习效果评估**，并触发"学习路径重排"。这是 Pythontopia 教育闭环的"再播种"环节。

## 2. 本阶段目标

- 后端实现"学习效果评估"服务：
  - 输入窗口（默认 7 天）。
  - 输出多维指标：KC 掌握增量、资源消化量、提交通过率、Bug 矿洞修复率、画像置信度变化、班级排名（仅班级内）。
  - 评估结果落 `learner_evaluation`、`learner_evaluation_metric` 表。
- 触发"路径重排"：
  - 评估完成后调用阶段 08 的 `PathPlannerAgent`，传入最新画像 + mastery + 评估摘要，生成新版本路径，旧路径归档。
  - 重排原因落 `learning_path.goal_summary` 与 `learner_evaluation.path_diff_summary`。
- 前端实现"复盘大厅"场景与 `ReviewHallPanel.vue`：
  - 列出最近 N 次评估（默认 4 次）。
  - 单次评估展示：核心指标、增长曲线、推荐学习重点、新路径与旧路径 diff。
  - 提供"接受新路径" / "保留当前路径"选择。
- 接入"画像被动更新"：把提交、Bug 矿洞、资源反馈、quest 完成等事件转化为 `profile_revision`（阶段 04 已留接口）。

### 5.2 评估服务

- T13-10 `com.pythontopia.learner.evaluation`：
  - `controller/LearnerEvaluationController`：
    - `POST /api/learner/evaluations`：触发立即评估，DTO `EvaluationRequest{periodDays?}`（默认 7）。
    - `GET /api/learner/evaluations?limit=`：历史列表。
    - `GET /api/learner/evaluations/{id}`：详情（含 metric + diff + 新路径预览）。
    - `POST /api/learner/evaluations/{id}/accept-new-path`：把新路径设为 ACTIVE，旧路径归档；`acted_status=ACCEPTED`。
    - `POST /api/learner/evaluations/{id}/keep-old`：放弃新路径；`acted_status=KEPT_OLD`。
  - `service/LearnerEvaluationService`：
    - 计算指标：
      - `kc_mastery_delta_total` = 当前 KC mastery 总和 - 上次评估时 mastery 总和。
      - `practice_pass_rate` = 期间 AC 提交数 / 期间总提交数。
      - `bug_mine_resolve_rate` = 期间 `RESOLVED` session 数 / 期间 OPEN 数。
      - `profile_confidence_delta` = 期间画像 8 维平均 confidence 提升（来自 `profile_revision.diff`）。
      - `resource_consumption_count` = 期间 `learning_resource.feedback_status != NONE` 数量 +（无反馈但 mastery 提升的资源数）。
    - 生成 `narrative_summary`：可调用 graph `EvaluationNarrativeAgent`（仅写文字 narrative，KC 与数据由后端确定）。
    - 调用 `PathPlannerAgent` 生成"候选新路径"，落 `learning_path`（`status=DRAFT`，不立即激活，等学生 accept）。
  - `repository/`：对应 JPA 仓库。
- T13-11 引入 `learning_path.status=DRAFT`（迁移 `V092__learning_path_status_draft.sql`）：
  - `ACTIVE`（当前）、`ARCHIVED`、`DRAFT`（评估生成、等待学生 accept）。
- T13-12 `acceptNewPath(evaluationId)`：把 DRAFT 转 ACTIVE；同时把旧 ACTIVE 转 ARCHIVED；自动生成 quest 同阶段 08。
- T13-13 `keepOldPath(evaluationId)`：DRAFT 标 ARCHIVED，但保留 evidence。

## 7. 验收标准

### 7.1 功能验收

- 学生在过去 7 天内有 1 次画像更新、若干次资源生成、若干次提交、1 次 Bug 矿洞修复：
  - 触发评估后 `learner_evaluation` 增 1 行，`learner_evaluation_metric` 增 5+ 行。
  - 自动生成 `learning_path` DRAFT；narrative_summary 引用真实数字。
- 学生点击"接受新路径"：旧 ACTIVE 路径归档，新 DRAFT 转 ACTIVE，quest 自动同步（阶段 08）。
- 学生点击"保留当前"：DRAFT 标 ARCHIVED，原 ACTIVE 不变。
- 学生反馈一份资源 `DISLIKED`：`profile_revision` 增 1 行 `source=RESOURCE_FEEDBACK`；下一次评估的 `learning_preference.media_priority` 反映该偏好变化。

### 7.2 教育验收

- narrative_summary 不出现未在 metrics 中的数字、未在课程中的 KC code。

## 9. 风险与回滚

- 风险：DRAFT 路径与已发出的 quest 冲突；缓解：accept 时统一事务处理；keep-old 时只动 DRAFT，不动 quest。
- 风险：评估周期内事件为 0 导致 narrative 无内容；缓解：narrative agent 在 metrics 全 0 时直接返回固定模板，标注"近期无活动"。
- 风险：班级排名暴露同学姓名；缓解：仅显示班级内匿名编号或自愿展示开关。
- 回滚：删除 `learner_evaluation`、`learner_evaluation_metric` 行可还原；旧 ACTIVE 路径可从 `ARCHIVED` 重新激活。

## 10. 不做事项

- 不做跨班级评估对比。
- 不在评估中触发自动操作（必须学生 accept 才会改变 ACTIVE 路径）。
- 不允许 narrative_agent 凭空编造数字。
- 不把评估结果展示给其他学生（仅自己和教师视角看）。
- 不引入复杂可视化库（保持轻量）。
