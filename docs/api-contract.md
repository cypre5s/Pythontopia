# Reborn HTTP contract

All routes use /api. JSON fields use snake_case. Bearer session authentication is required except auth/register, auth/login and health. Student requests carry explicit classroom_id. Public registration never accepts a teacher/admin role. Errors return detail; malformed inputs return422. All public timestamps include an explicit UTC offset; release inputs must carry a timezone and are normalized to UTC before storage.

## Session and classes

- Public user fields additionally include `must_change_password`. POST /auth/password {current_password,new_password} validates the old password and a 6–200 character new password different from the student ID and current password; atomically revokes all sessions and returns a new {access_token,user} session for this client. Login accepts 1–200 characters for temporary student-ID passwords; self-registration still requires 6–200. Temporary-password accounts may only call /auth/me, /auth/password and /auth/logout until changed; other authenticated endpoints return403.
- GET /teacher/classrooms/{id}/students returns student roster {id,student_id,name,must_change_password}. POST same path {students:[{student_id,name}]} atomically creates 1–500 students and memberships, returning {created,existing}; initial password equals the student ID and must be changed. Existing classroom students are skipped without modifying credentials; existing accounts outside the class or staff IDs reject the entire request. Concurrent duplicate writes return409 without partial creation.
- POST /teacher/classrooms/{id}/students/import-preview accepts multipart `file`: UTF-8 CSV or XLSX, 2MB, at most500 students, exact columns 学号/姓名. One worksheet, text student IDs, no formulas; bounded archive expansion. Returns {students:[{student_id,name,action:create|existing}]}; preview is read-only, confirmation uses the create endpoint and revalidates authorization and conflicts.
- POST /teacher/classrooms/{id}/students/batch {student_ids:[string],action:reset-password|remove} accepts1–500 student IDs and returns {affected}. Only students already in the owned classroom may be targeted; any invalid target rejects all changes. Reset sets each password to their own student ID, revokes sessions and requires password change. Remove only deletes this membership, preserving accounts, other classrooms and learning evidence. Teachers cannot reset staff passwords; all staff change their own password with the old password.
- POST /teacher/classrooms/{id}/town-session creates or reuses a dedicated student identity for the authenticated teacher and selected classroom, then returns `{access_token,token_type,user}` with `user.town_preview: true`. Access requires classroom management and an installed course. The token can play only in the bound classroom and depends on the issuing teacher session remaining valid. Teacher logout, password changes and loss of classroom access revoke preview access. The preview identity is omitted from class membership and teacher learning statistics. It cannot log in with a password or join additional classes.

- POST /auth/register {student_id,password,name}; POST /auth/login {student_id,password} -> {access_token,user:{id,student_id,name,role,dev_tools_enabled}}. GET /auth/me returns the same public user fields; POST /auth/logout. `student_id` is a string of 1–32 ASCII digits, trimmed at the boundary, preserving leading zeroes. All roles use this field; email payloads are rejected (422), duplicate registration is 409, incorrect credentials are 401. Registration cannot select a role. Migrated unassigned accounts cannot log in or use old sessions until an operator assigns a real student ID.
- GET /classrooms returns authorized classroom summaries {id,name,teacher_id,teacher_name}; non-admins receive only classrooms they teach or belong to. Teacher names are returned without teacher student IDs. join_code is included only for the owning teacher/admin, never for student members. POST /classrooms {name} (teacher); POST /classrooms/join {join_code}; DELETE /teacher/classrooms/{id}/members/{user_id} (owner/admin). Authorized teacher progress/member details use `student_id` instead of email (nullable only for unassigned legacy users).
- GET /world?classroom_id -> player position, configured NPCs/scripts, current quests and node statuses, available chapters and world flags. PUT /world/position {classroom_id,map_key,tile_x,tile_y,direction}.
- Fixed world geometry and portal destinations come from shared/world/world.json. PUT /world/position validates logical dimensions/walk_bounds and only permits same-map updates (cross-map409). POST /world/transition {classroom_id,portal_id} validates membership, source map, radius and current classroom building_access. Unknown portal404, wrong source/distance422, denied entry403; an active course interaction bound to the entrance must finish first (409). Exits remain usable without an entry building gate. Returns {player,world} using the fixed destination; render_bounds never grant additional movement.
- POST /events {classroom_id,event_id,quest_id,node_id,evidence}. Evidence fields are npc_key/dialogue_id/choice/object_id/map_key/tile_x/tile_y/record_id/submission_id as appropriate. The server validates current node, context and learning evidence. Repeated identical IDs are idempotent; different bodies with the same ID return409.
- TALK_TO_NPC/PLAY_DIALOGUE/REPORT_BACK events require the matching server story checkpoint and persisted completion marker. Proximity or a client dialogue claim alone is insufficient. There is no legacy `/dialogues` execution endpoint.

## Development and preview progress reset

- `User.dev_tools_enabled` is true for a regular student only when the API process explicitly has both `REBORN_ENV=development` and `REBORN_DEV_TOOLS=1`. It is also true for a dedicated teacher preview student, whose session has `town_preview: true`. The capability comes from the server.
- `POST /dev/progress/reset {classroom_id,confirmed:true}` requires the authenticated student to belong to that classroom and affects only that student's records in that classroom. The body cannot select another user. Explicit confirmation is required; invalid input returns 422, unauthorized role or membership is rejected, and unfinished judge/assistant work returns 409 without clearing progress.
- Success returns `{ok:true,user_id,classroom_id,deleted:{table_name:count}}`. It clears that scope's quest/node/event/story state, reading participation and resume progress, submissions/grades and related private execution payloads, saved position and world flags. Counts describe the reset transaction; subsequent world reads can recreate the initial quest projection. Server assistant sessions/calls and their audit/budget history are retained; only client restore pointers are disconnected. It does not delete accounts, authentication sessions, memberships, classrooms, releases or course content, nor other users'/classrooms' records.
- The client clears matching user/class browser reading positions, practice drafts, assistant restore IDs and library filters only after success. Authentication, selected membership and device interface/music preferences remain. The student re-enters the welcome flow at `town_hub (22,36)` with the arrival main quest at zero completed steps; this is not a content snapshot or undo mechanism and invokes no model.
- The ordinary `/dev/progress/reset` route is registered only when both explicit development switches are enabled. `POST /teacher-town/progress/reset` accepts the same confirmation and response shape, and authorizes only the teacher preview identity in its bound classroom. This route is available to that identity in production as well.

## Learning and formal submissions

- POST /story/interactions {classroom_id,npc_key? ,interaction_id?} requires exactly one target and selects the authorized current flow. Returns404 when no applicable flow exists; the client shows feedback without a fallback dialogue engine. Same actor/classroom starts serialize under one transaction, so concurrent first requests return the same session. A character speaker uses `speaker_npc_id`; the server resolves current name/portrait, while `speaker` remains available for narration.
- Story responses include mode:task|public|ambient. Public/ambient may have null chapter_id; a non-null chapter still requires release authorization. Only ambient forbids activities and learning/unlock effects. Public can wait for real activities and perform evidence-guarded unlock_building. world.story_available reports authorized flow availability without exposing definitions; entry selection follows the five-layer priority in the content specification. Active/waiting sessions are resumed first and never silently replaced by another entry.
- Story conditions are data-only all/any/not compositions of allowlisted goal, quest, chapter and fully graded assessment score predicates. Dialogue choices are filtered to public id/label fields and revalidated on advance; a now-hidden or forged choice returns422. Random nodes settle once into a persisted dialogue cursor; current/resume and repeated matching event_id do not redraw. Ambient forbids bindings/activity/checkpoint/effects, never initializes PlayerQuest or writes learning/grades/world-unlock markers, and makes no model calls. Only the dialogue session and its bounded request receipts are persisted. If no conditional choice remains, the dialogue may safely end without a choice.
- An interface action can omit `text`. The client advances a textless action with the normal server-authorized session request and opens the workspace or enters the building after acknowledgement. Existing scripts with nonempty action text retain the confirmation step. New explanations belong in a preceding dialogue node.
- GET /story/current?classroom_id restores the active/waiting story or returns null. POST /story/sessions/{id}/advance {classroom_id,event_id,revision,choice?}; POST /story/sessions/{id}/return {classroom_id,event_id,revision}. Return results are decided from server evidence, never a client completion claim. Responses contain {id,revision,status:active|waiting|ended,npc_key,node,activity,world}. Activity includes {id,kind,page_no}; only the current visible dialogue and choices are sent. Duplicate request IDs are idempotent, mismatched bodies or stale revisions return409. Teacher preview cannot write a student story. Current/resume still checks classroom/course/chapter access. A session retains its verified physical anchor even if later completion makes the entry/NPC appearance condition false; advance/return require proximity to that anchor, updated to the destination after entering a building. Explicit end may close the actor’s own classroom session after leaving the anchor or chapter suspension, without reading unauthorized flow content.
- GET /activities/{id}/progress?classroom_id; POST /activities/{id}/progress {classroom_id,page_no}. Stores authorized real page IDs and resume position by user/class/activity; returns {page_no,visited_pages,completed,participation_only,required_page_ids,read_count,read_total,watched_seconds,required_seconds} for lesson/reading. participation_only is true for reading and false for practice/assessment. Practice progress is computed from accepted formal submissions by stable question ID and includes accepted_question_ids. Assessment completion comes from an immutable, fully graded answer sheet; passed and correct_count/total are separate, so incorrect answers do not deadlock story return. Activity responses include completion/learning/progress. Reading completion covers the declared participation targets, not mastery. Story lesson goals additionally require completed server progress under the current legacy or learning rule.
- POST /activities/{id}/video-progress {classroom_id,material_id,playback_session_id:UUID,sequence:positive_integer,position_seconds:finite_number,playing:boolean,playback_rate?:number} -> the same lesson progress payload. Only an authorized student can write a ready video with reliable duration; material_id must match the activity's current bound material. Each playback session starts at sequence1. A recent identical session/sequence/body retry is idempotent; mismatched reuse, nonsequential packets or another active playback session return409. The server serializes the student's progress writes and counts only continuous media advance normalized by the previous playback rate and bounded by server elapsed time, with a maximum20-second heartbeat gap. playback_rate defaults to1 and accepts0.25..4; faster playback never earns more effective seconds than elapsed wall time. A rate change closes the old heartbeat boundary and begins a new playback session. Paused time, direct seeks, excessive media advance and long offline gaps do not count. Another session may start after the old one pauses or is inactive15seconds. Effective seconds are cumulative actual playback (rewatching may count), not unique coverage or mastery. Material changes retain bounded per-material seconds summaries without reusing playback sessions; stale packets naming the old material return409. No client-reported total elapsed time or completion field is accepted.

- GET /activities/{id}?classroom_id -> current activity, authorized material, public questions, knowledge_point_ids and public knowledge_points with source IDs. The optional learning object is {reading?:{scope:all|range,start_page?,end_page?},video?:{minimum_seconds},highlights?:{pages?:[{start_page,end_page,label}],video?:[{start_seconds,end_seconds,label}]}}. Rules always refer to the activity's one bound material; reading/video completion rules are mutually exclusive and cannot coexist with legacy completion.required_page_ids. Highlights may coexist with the legacy rule and never create completion evidence. All/range use actual original page IDs; ranges include existing pages between valid original endpoints. Video targets require reliable duration and minimum_seconds1..86400. POST /activities/{id}/participation {classroom_id,page_no?,video_time?} -> record_id remains a participation record, not mastery or elapsed-video evidence; a configured video target must already be verified complete before recording its completion participation. Neither this record nor a last-page position bypasses task evidence validation.
- GET /library?classroom_id lists authorized current activity-bound materials and explicitly published trusted course media. GET /materials/{id}?classroom_id returns the current readable material; GET the same path/file streams authorized bytes with Range206 support. Files never live in public uploads. Material summaries/details include authorized chapter_ids and duration_seconds:number|null; there is no required/supplementary classification. Any usable chapter association must also satisfy classroom, owner and publication checks; unpublished sibling chapter IDs are not exposed. Browsing material alone does not create activity/quest progress.
- The town library's chapter directory, title/chapter search and material-type filters operate on this authorized response in the client. They do not add a publication API or bypass chapter authorization. The classroom workspace reads progress from current /world data; changing UI categories and preferences does not create participation, grades or model calls. Classroom switching uses the existing authenticated GET /world?classroom_id and changes the selected client classroom only after a successful response.
- POST /submissions {classroom_id,activity_id,question_id,idempotency_key,mode:submit,answer?,code?}; GET /submissions/{id}?classroom_id. Return id, activity/question/mode/status/feedback/created_at. Practice remains repeatable per question. The retired server run mode returns 422; public samples execute only in the browser and create no Submission. Assessment rejects single-question submissions. Existing historical receipts remain readable.
- GET /activities/{id}/assessment?classroom_id returns {id,status:draft|grading|graded|attention,revision,locked,legacy,question_ids,answers:[{question_id,answer,code}],results:[public_submission],correct_count,total,score:int|null,max_score:100,completed,passed}. All state is authenticated-student/classroom/activity scoped. A new empty sheet has id:null/revision:0 and GET creates no rows. On a student first read, an already fully graded legacy sheet is bound once to an immutable legacy attempt using only its actual existing question/answer/submission identities; this endpoint alone commits that binding under the authenticated user lock, without creating or regrading submissions. Other world/progress/evidence reads remain pure. Before hand-in results is empty. Submitted answers are immutable; grading uses existing per-question Submission rows and the durable Judge0 worker. No expected answers, hidden cases or internal execution payloads are returned.
- PUT /activities/{id}/assessment {classroom_id,revision,answers:[{question_id,answer?,code?}]} persists the whole draft and increments revision. Unknown/duplicate question IDs and extra fields are rejected; a stale revision or locked sheet returns 409. Teacher preview cannot write. Drafts may be incomplete and are never graded.
- POST /activities/{id}/assessment/submit {classroom_id,idempotency_key,answers:[{question_id,answer?,code?}]} requires every currently configured question answered, atomically locks the sheet and stages all question submissions/execution payloads. Repeating the same key and answers returns the same receipt, including after the current question set changes; another key or changed answers returns 409. Concurrent hand-ins are serialized by authenticated user lock and a unique actor/class/activity sheet. A failure staging any question rolls back the whole hand-in. There is no student unlock or blind Judge0 resubmission endpoint.
- Assessment status graded means all academic judgments are terminal, completed=true, with score=correct_count*100//total (integer floor), max_score=100, and score=null until graded; passed=true only when all are correct. grading covers prepared/dispatching/queued/running; attention covers infrastructure failures or unknown external dispatch and remains locked/completed=false until legitimately reconciled. PASS_ASSESSMENT uses fully graded sheet evidence (including wrong answers), not an all-correct retry loop. Existing question submissions are never regraded: if all current questions already have terminal formal history, a read-only legacy sheet is derived from each question's latest actual receipt without inserting new Submission rows. The first authenticated student read binds those real identities in an AssessmentAttempt; other world/progress queries remain read-only. A bound legacy sheet retains its original answered IDs even if current authoring later appends questions; a new examination uses a new activity ID. Unbound partial history pre-fills a new draft; old pending/unknown history locks grading/attention to prevent blind duplication. New assessment_attempts rows only hold students' answer/evidence identities, not old question-text/content snapshots.
- Feedback contains detail/status and optional public samples[{status,stdout,stderr,compile_output}]. Hidden tests, expected outputs and hidden indices are absent. States include prepared/dispatching/queued/running/accepted/wrong_answer/compile_error/runtime_error/time_limit/memory_limit/infrastructure_error/submission_unknown. Uncertain dispatches require reconciliation; no blind resubmit.

## Teachers and authoring

- GET /teacher/courses?classroom_id -> {chapters,knowledge_points,activities,npcs}, restricted to the selected authorized classroom CourseInstance.
- POST/PUT/DELETE /teacher/chapters[/id]. Create {title,order_index?}; update {title?,order_index?}. POST/PUT/DELETE /teacher/knowledge-points[/id]. Create {chapter_id,title,content?}; update {title?,content?}. Unreferenced entries in the authorized instance may be deleted, otherwise409. Cross-instance reads/edits/bindings are rejected even for the same teacher.
- POST /teacher/activities {id,chapter_id,title,kind,npc_key?,material_id?,assistant_allowed?,knowledge_point_ids?,learning?}; PUT /teacher/activities/{id} updates owned content in place. learning is stored as content.learning under the same bounded schema as YAML; PUT learning:null explicitly removes it. Unknown rule fields, wrong material kinds, invalid/reversed original page ranges, unknown video duration and out-of-duration highlights are rejected422. Material replacements revalidate retained learning rules; failures preserve the old activity. KC IDs must be unique positive integers from authorized chapters in the same classroom course instance. Activities outside the selected instance cannot be overwritten. GET /teacher/courses activity summaries include learning for authorized instance activities.
- GET/POST /teacher/questions and PUT/DELETE /teacher/questions/{id} manage an independent question bank. POST {id,title,kind,prompt,chapter_ids?,knowledge_point_ids?,source_type?:ai_generated|imported,status?:draft|ready|disabled,options?,samples?,answer?,hidden_cases?,source?}; PUT accepts partial edits. Questions do not require activity_id. Ready questions need at least one authorized chapter and valid grading configuration; knowledge points are optional and must belong to selected chapters. source is optional reference evidence, not a third origin type. Teacher responses include owner_id, chapter_ids, knowledge_point_ids, source_type, status, source, activities:[{id,title,chapter_id}] and private grading fields; student responses never include private answers/cases. Cross-owner changes are rejected. Removing required chapter associations or making a referenced question unavailable returns409; delete is rejected while referenced. Python samples+hidden cases total<=20 with validated field shapes and bounded text.
- PUT /teacher/activities/{id}/questions {question_ids:[string]} replaces the ordered selection atomically. Only owned/admin editable practice/assessment activities, available questions in the same instance and matching chapter associations are accepted. Duplicate/unknown IDs are rejected; an assessment may select at most100 questions, matching draft/hand-in limits. Existing assessment attempts block changing the ordered assessment question set (409); changing a question kind with submitted/locked evidence also returns409 and requires a new ID. ActivityQuestion is the only stored selection source; GET /teacher/courses activity summaries expose computed question_ids for management. Reusing a question does not reuse another activity's submissions, grades or sheet locks.
- GET /teacher/quests; POST /teacher/quests/validate {definition}; POST /teacher/quests {definition}. One current definition per ID; strict schema, graph, content and ownership validation. kind=main|side; optional nodes are booleans; activity_id must identify a real current activity of the required type. ALL merges ignore unselected branches but still require the selected branch and subsequent learning. Side quests do not implicitly block main chapter prerequisites.
- PUT /teacher/classrooms/{id}/releases/{chapter_id} {status:published|paused,opens_at:ISO8601|null,prerequisite_chapter_id?}. GET /teacher/classrooms/{id}/releases. Server-time evaluation is immediate. Releases control visibility, schedule and prerequisites; all students use current definitions.
- GET /teacher/classrooms/{id}/progress; GET /teacher/classrooms/{id}/students/{student_id}: real members (including completed_chapters: integer >= 0), node events, participation records, submissions and error distribution. completed_chapters counts released chapters whose required main quest IDs all have completed server-verified PlayerQuest instances for this student/class; it uses the same current main-quest rule as chapter prerequisites, excludes side-only chapters, and retains completed history while paused. Teachers own the class; preview cannot write student grades.
- POST /teacher/materials/upload multipart {chapter_ids?:JSON-encoded integer array,title,material_id?,file} -> {id,status,title}; omitted chapter_ids creates an unclassified upload, or preserves existing links on replacement. PUT /teacher/materials/{id} {title?,chapter_ids?} edits metadata and multiple chapter links. GET /teacher/materials lists authorized metadata; GET /teacher/materials/{id} and /file provide owner/admin preview, including unclassified material, without classroom publication. DELETE /teacher/materials/{id} returns409 for referenced content. queued/processing/ready/failed processing states persist. Upload alone does not publish; student access still requires an authorized published association/activity. Same material_id replaces the current file while preserving type; removing chapter links required by existing activities is rejected.
- Character CRUD is part of the complete classroom authoring draft below. Independent `/teacher/npcs` writes are removed. Activities use nullable npc_key: null selects the course default, a non-null value selects an authorized classroom character. PUT npc_key:null clears an override. Activity responses include the server-resolved `role:{key,name,portrait,sprite}|null`; world responses expose the same `default_role` identity for library reading. `sprite` contains id/url/frame_width/frame_height from the same character assets as the world, including unplaced assistants; private URLs keep classroom authorization and version checks.

## Active teaching assistant

- GET /assistant/status -> available, reason, model_calls. Missing credentials are explicit.
- POST /assistant/sessions {classroom_id,activity_id? ,material_id?} -> id; exactly one target is required (both/neither:422). Direct library reading uses material_id and the librarian role; ready status and current classroom/material authorization are mandatory. Activity sessions retain assistant_allowed policy; GET /assistant/sessions/{id}; POST /assistant/sessions/{id}/messages {message,page_no?,video_time?,code?} streams SSE meta(request_id/session_id), token(text), references(items), done(status/tokens), error(detail).
- POST /assistant/requests/{id}/cancel; owner validation and thread-safe cancellation. Sessions isolate user/class/activity or user/class/material and reauthorize on history access and every message. Material sessions have nullable activity_id, reference only the current material, and expose no question answers, submissions or synthetic teaching activity. References contain material_id/page_id/page_no with no content version. Tests prohibit AI on assessments when the server policy forbids it.
- One create_agent factory, five read-only tools, no grading/unlock/publish/SQL/shell tools. Default3 model and5 tool calls,45s timeout,512 output tokens/model, conservative request/user/class budgets. Production has no fake provider.

Paused policy denies new content/progress/assistant requests immediately and preserves history; reopening continues stored state. The only built-in main quest is arrival (stable ID arrival, 初来小镇：第一堂 Python 课; database IDs are instance-specific). Retired shared quest definitions are removed only during explicit course import, so stored player history does not restore them to the current world. Teacher-owned definitions and learner grades remain intact. Normal course import includes only currently selected teaching questions, not an automatic legacy archive. Explicit development cleanup skips real learner and authoring references; ordinary migration does not delete grades. Validation results and external-service skips are documented in acceptance.md.

## 资料逐页讲解与音频

教师接口必须带 `classroom_id` 并限定在选定班级当前课程实例；学生接口按资料授权与班级开放范围鉴权，未授权一律404/403，不泄露资料存在性。以下路径均在 `/api` 下。

- GET /teacher/materials/{id}/narrations?classroom_id -> {pages:[{page_no,title,has_text,status,narration,bridge_in,anchors,target_seconds,source_text,audio,audio_seconds,reviewed_at,reviewed_by}],coverage:{pages,covered,missing,draft,accepted,rejected,unavailable,stale},quota:{...}}。`status` 为 draft|accepted|rejected|unavailable|stale；`source_text` 为该页当前原文前2000字，只用于并排比对，不返回学生。
- PUT /teacher/materials/{id}/narrations/{page_no} {text,bridge_in?,anchors?,target_seconds?} 写入或改写讲解正文，结果为 draft；页文本已变时旧 accepted 记录在读取时被判 stale。DELETE 删除该页讲解。
- POST /teacher/materials/{id}/narrations/{page_no}/accept；POST .../reject。只有 accepted 能进入学生端、音频与课程包。未保存修改不得接受（后台层面阻断，服务端以提交正文为准）。
- POST /teacher/materials/{id}/narrations/{page_no}/generate 按单页生成，POST .../narrations/generate {first_page,last_page,mode?} 批量逐页生成；`mode=serial`（默认独立）会把已生成页的讲解作为上下文，过渡句才有依据，且上下文参与幂等键。
- GET .../narrations/job -> {running,kind,status,done,total,message,started_at}：前端轮询用。
- 生成／校准／音频端点共用一份资料锁：已有任务在跑时返回 409「这份资料正在处理中」；心跳超过 5 分钟的旧任务视为过期，允许接管。
- POST .../narrations/accept-batch {first_page?,last_page?} 一次接受范围内全部可审草稿，返回 {accepted:[页码],count,skipped:[{page_no,reason}]}；空文本、非 draft 页跳过。
- POST .../narrations/audio-batch {first_page?,last_page?} 为范围内已接受的页批量合成音频，返回 {made,reused,failed:[{page_no,error}],skipped,count}；单页失败不中断。；两者幂等，输入未变不重复请求模型。余额/额度不足、无凭据、供应商失败分别返回429/409/502，单页失败不阻断其余页。
- GET /teacher/materials/{id}/narrations/quota 返回当日额度使用；POST .../narrations/calibrate 产出全篇校准报告，GET .../calibrate 取最近一份，POST .../calibrate/apply 只重生成 draft 页并列出待教师确认的 accepted 页。
- GET /teacher/materials/{id}/narrations/{page_no}/page-image -> image/jpeg，返回审校用页图（与生成时送模型的页图同一份、同一尺寸）；文本资料或没有可读来源时404。页面图像不返回给学生，学生端仍只看课件本身。
- POST /teacher/materials/{id}/narrations/{page_no}/audio 合成单页语音：仅 accepted 可合成（draft/未就绪409），无TTS引擎409且不伪造音频，引擎失败502。GET .../narrations/audio 返回逐页就绪状态与音色/模型；GET .../{page_no}/audio/file 为教师试听流（audio/mpeg）。
- GET /materials/{id}/narrations?classroom_id 学生只读到 accepted 且未 stale 的页，字段仅 page_no/text/bridge_in/target_seconds/audio/audio_seconds。GET /materials/{id}/narrations/{page_no}/audio?classroom_id 为 audio/mpeg 流，未接受或无录音404。
- POST /materials/{id}/narrations/{page_no}/ask {question} -> {page_no,answer,cites,remaining,checks}。只有学生主动提问才调模型；上下文限本页原文、该页已接受讲解与邻近页标题，草稿不进入；`cites` 只保留邻近页码，越界丢弃。空问题或超500字422，越界页或无内容页404，无凭据409，日额度用尽429，供应商失败502。

讲解、审校、音频与提问均不改变成绩、解锁、任务进度或阅读完成；翻页、播放与浏览不产生模型调用。课程包导出目前不包含讲解，见内容规范的未覆盖说明。

## 班级课程与包交换

以下路径均位于/api。教师内容接口必须带classroom_id查询参数，路径包含班级时以路径为准；省略或班级未初始化不能访问全局来源。管理员也必须指定实例，跨班对象、关联、文件和学生预览均再次鉴权。包内stable_id与运行id分开，新增内容后使用服务端返回的id。

- GET /teacher/classrooms/{id}/course：返回id/classroom_id/package_id/name/package_version/revision；无实例为null。
- POST /teacher/classrooms/{id}/course/empty {confirmed:true,name}：创建空课程，已有实例幂等返回。不会自动生成章节、题目、NPC或交互。
- GET /teacher/classrooms/{id}/course/ids：教师可查看九类实体的stable_id→当前运行ID映射，用于迁移/受控集成，不能用于越班查询。
- POST /teacher/classrooms/{id}/course/imports/preview：**已关闭，固定返回 410**（ZIP 上传入口不再开放）。要导入请把解压后的目录包放入私有 `data/course/`，改用下面的 `imports/available/preview`；返回结构（id、expected_revision、expires_at 24 小时、can_apply、diff、blockers、warnings、learning_impact）不变。校验或预览不等于激活。
- GET /teacher/classrooms/{id}/course/packages 返回 `{items:[{key,name,package_id,package_version,source}],unavailable}`。当前只列私有交换目录里的**解压目录包**（`source=mounted`）及本班自己的导出目录；其他班级的导出目录不可选。POST /teacher/classrooms/{id}/course/imports/available/preview 接受 `{package_key}`，对目录创建私有副本并计算内容指纹，执行与预览一致的校验并返回相同预览结构。响应不暴露文件系统路径。
- POST /teacher/classrooms/{id}/course/imports/{preview_id}/apply {request_id:UUID,expected_revision:int>=0}：返回instance_id/revision/package_id/package_version/duplicate。重复请求保持原回执；包被篡改、预览过期、修订冲突、影响学习记录或进行中会话时拒绝，旧课程保留。
- GET /teacher/classrooms/{id}/course/export：把完整课程原子发布为私有交换目录 `data/course/export-<班级ID>-<随机ID>/` 并返回 `{directory,path}`（不再是ZIP附件）；覆盖未归类、草稿、停用、未选用内容和私有答案/媒体，不包含账号、成员、学习记录或部署密钥。缺失/转换中的媒体不能导出为完整包。

原始包、预览和答案只供授权教师。学生只获得过滤后的运行DTO；secrets目录名本身不构成权限边界。课程文件保存在REBORN_COURSE_EXCHANGE_ROOT，运行媒体保存在原私有存储，两者不是公开静态路径。

## 教学流程与世界编辑

- GET /teacher/classrooms/{id}/authoring 返回 revision、catalog、npcs、flows、quests、configuration 和 students。npcs 为完整角色资料列表，字段为 id/name/portrait/sprite/persona/placement/appearance_condition，placement 可以为空。catalog 按当前放置地图分组角色。
- POST /authoring/validate 在上述班级前缀下提交 `{expected_revision,npcs,flows,quests?,configuration}`。返回 `valid` 与 `diagnostics`。诊断包含 `code`、`message`、JSON Pointer `path`，可带 `suggestion` 与稳定 ID 的 `target`。可发布但涉及清理进度时另返回 `reset_impact`，含确认令牌及受影响统计。该接口只读。configuration 允许 world/buildings/assistant/editor。角色引用、未放置地图目标、素材和布局与流程统一校验。
- PUT /authoring 在独占班级事务中复查并保存，接受可选的 `confirmation_token`，成功返回新 revision。定义无效返回 422 与结构化诊断。影响范围需要确认且令牌缺失或过期时返回 409 与 `detail.reset_impact`，需要教师查看并重新确认。硬阻断返回 409 与 `detail.diagnostics`。过期课程修订返回 409。重置与发布同事务提交，保存与章节开放分别控制。
- POST /authoring/preview：同一输入加student_id、entry（NPC稳定ID或interaction:<id>），用真实本班学生状态返回selected_flow_id/node_id/trace/stopped_at，不创建进度或执行效果。
- world.interactions 定义 id/label/prompt/trigger(click|enter)/map_key/target(object_id或整数矩形region)/when?。不再接受 world.npcs；角色条件由 appearance_condition 保存。进入区域不可重叠，区域/位置必须可达。
- buildings 按固定建筑 ID 定义 enabled/default_unlocked/blocked_message/when?；assistant 仅含 enabled、limits、default_npc_id?，不再保存独立角色名单或映射，不接受凭据、模型连接或特权工具。人设不进入当前模型请求。

角色与流程、任务、配置在同一事务保存；改名、换素材、人设编辑不触发进度重置。删除角色须通过活动、流程、任务、图书馆及历史引用检查；正在互动的角色移动、撤回或改变出现条件返回带定位诊断的 409。

- GET /teacher/classrooms/{id}/character-assets 返回本班可选系统和私有素材描述。
- POST 同一路径接收 multipart 的 file/kind(portrait|sprite)/owner_npc_id/expected_revision/frame_width?/frame_height?。上传与完整包导入共用图片解码、大小及布局检查，成功 201 返回 id/kind/name/url/sha256/owner_npc_id，精灵另含帧宽高；不改变角色引用或课程修订；修订过期返回409。自定义素材禁止跨角色引用。保存角色时事务内移除不再引用的图片清单并持久化文件清理队列，提交后删除文件，失败定期重试。未提交上传保留24小时后回收。
- GET /classrooms/{id}/character-assets/{asset_id} 按当前班级授权返回图片，private/no-store/nosniff。学生仅可读已被角色引用的素材，未发布 404，跨班 403。地址带哈希缓存标识；客户端切班/退出释放资源。格式限制见[角色素材规范](content-authoring.md#统一教学角色与素材)。

`/world` 中只有已放置且满足出现条件的 NPC，返回 direction、sprite 描述以及当前 name/portrait；default_role 为课程默认答疑角色或 null。persona 不在学生世界、活动和对白 DTO 中输出。

GET /world?classroom_id增加当前可用interactions、building_access及building_unlock解锁建筑ID列表；NPC可见性按同一条件解释器过滤。POST /story/interactions {classroom_id,npc_key? ,interaction_id?}只允许一个目标，距离和当前条件均由服务端验证。故事action支持open_workspace(library/journal/classroom)及enter_building；响应只描述允许的动作，客户端等待服务端advance确认才打开界面或切图。POST /story/sessions/{id}/end {classroom_id,event_id,revision}显式结束当前演出，退出工作区/暂时离开不冒充活动完成。故事幂等键、revision、等待/恢复和服务端证据要求保持。

## 目录课程包接口更新2026-11-12

`GET /teacher/classrooms/{id}/course/packages` 只列出共享包目录及本班导出目录。`POST .../imports/available/preview` 对目录创建私有副本，生成内容指纹并执行完整校验与影响分析；确认应用时再次核对指纹、课程修订和授权。其他班级导出目录不可选择。

`POST .../imports/preview` 返回410，表示ZIP上传关闭。`GET .../export` 返回JSON，包含 `directory` 和 `path`，完整课程已写入服务器 `data/course/` 下的目录。原ZIP下载响应已退出当前接口。历史ZIP预览仍按原私有暂存与指纹校验应用。

对白文本用空行分轮。运行DTO每次只返回当前轮文本，末轮才附带选项；提前传选择返回422。继续请求遵循原事件ID和revision幂等规则，末轮后才完成检查点。

课程包列表增加 directory、created_at、chapter_count 和 question_count。created_at 表示该包的 exported_at 或原始 created_at。列表仅读取章节定义和题目索引生成摘要，正式预览及应用仍执行完整校验。新导出目录为 export-<班级ID>-<安全课程名>-<北京时间YYYYMMDD-HHMMSS>-<8位随机串>，旧目录继续可选。

导入预览的暂存副本在已应用或24小时过期后由后台周期清理。预览与应用接口继续使用既有有效期和幂等规则，成功回执独立于文件保留；同请求重试仍返回duplicate结果。清理忙碌跳过，处理中的预览、应用和导出持有交换目录锁。

课程设置：GET /teacher/classrooms/{classroom_id}/course/settings 返回 revision、assistant 和本班角色选项 roles。PUT 同路径接受 {expected_revision,assistant}，课程排他锁内校验默认角色和预算，保留其他课程配置；冲突 409、非法字段/旧 library_npc_id/越界预算/外班角色 422，成功递增修订。不允许学生调用，教师仅管理自己班级。旧角色编辑路径不再提供预算控件，包和角色删除校验继续保护课程默认引用。
