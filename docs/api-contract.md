# Reborn HTTP contract

All routes use /api. JSON fields use snake_case. Bearer session authentication is required except auth/register, auth/login and health. Student requests carry explicit classroom_id. Public registration never accepts a teacher/admin role. Errors return detail; malformed inputs return422. All public timestamps include an explicit UTC offset; release inputs must carry a timezone and are normalized to UTC before storage.

## Session and classes

- POST /auth/register {email,password,name}; POST /auth/login {email,password} -> {access_token,user:{id,email,name,role}}. GET /auth/me; POST /auth/logout.
- GET /classrooms returns authorized classroom summaries {id,name,teacher_id,teacher_name}; non-admins receive only classrooms they teach or belong to. Teacher names are returned without teacher email. join_code is included only for the owning teacher/admin, never for student members. POST /classrooms {name} (teacher); POST /classrooms/join {join_code}; DELETE /teacher/classrooms/{id}/members/{user_id} (owner/admin).
- GET /world?classroom_id -> player position, configured NPCs/scripts, current quests and node statuses, available chapters and world flags. PUT /world/position {classroom_id,map_key,tile_x,tile_y,direction}.
- World geometry and portal rules come from data/world/world.json. PUT /world/position validates logical dimensions and walk_bounds and only permits updates within the current map; cross-map requests return409. render_bounds may extend visible scenery without granting movement outside walk_bounds. POST /world/transition {classroom_id,portal_id} validates membership, source map, configured radius and required flags, then returns {player,world} with the configured destination. Unknown portal404, wrong source/distance422, missing flag403. Historic indoor saves are preserved and may leave through their configured exit.
- POST /events {classroom_id,event_id,quest_id,node_id,evidence}. Evidence fields are npc_key/dialogue_id/choice/object_id/map_key/tile_x/tile_y/record_id/submission_id as appropriate. The server validates current node, context and learning evidence. Repeated identical IDs are idempotent; different bodies with the same ID return409.
- POST /dialogues/{npc_key}/steps {classroom_id,node_id,choice?} -> {node,next_id,completed_root,effects}. The node returned is the one just completed. PLAY_DIALOGUE events require a real terminal script marker. Whitelisted remember/open_activity effects never grade or unlock a task directly. Normal scripts use0 model calls.

## Learning and formal submissions

- POST /story/interactions {classroom_id,npc_key} selects the authorized current story. Returns404 when this NPC has no applicable story (NPCs without a chapter story use ordinary scripted dialogues).
- GET /story/current?classroom_id restores the active/waiting story or returns null. POST /story/sessions/{id}/advance {classroom_id,event_id,revision,choice?}; POST /story/sessions/{id}/return {classroom_id,event_id,revision}. Return results are decided from server evidence, never a client completion claim. Responses contain {id,revision,status:active|waiting|ended,npc_key,node,activity,world}. Activity includes {id,kind,page_no}; only the current visible dialogue and choices are sent. Duplicate request IDs are idempotent, mismatched bodies or stale revisions return409. Teacher preview cannot write a student story.
- GET /activities/{id}/progress?classroom_id; POST /activities/{id}/progress {classroom_id,page_no}. Stores authorized real page IDs and resume position by user/class/activity; returns {page_no,visited_pages,completed,participation_only}. participation_only is true for reading and false for practice/assessment. Practice/assessment progress is computed from accepted formal submissions by stable question ID and includes accepted_question_ids. Activity responses include completion/progress. Reading completion covers the declared participation targets, not mastery. New story lesson goals additionally require completed server progress.

- GET /activities/{id}?classroom_id -> current activity, authorized material, public questions, knowledge_point_ids and public knowledge_points with source IDs. POST /activities/{id}/participation {classroom_id,page_no?,video_time?} -> record_id. Video sends video_time only; reading records participation, not mastery.
- GET /library?classroom_id lists authorized current activity-bound materials and explicitly published trusted course media. GET /materials/{id}?classroom_id returns the current readable material; GET the same path/file streams authorized bytes with Range206 support. Files never live in public uploads. Material summaries/details include supplementary:boolean and duration_seconds:number|null; supplemental media still require classroom membership, chapter release and ownership authorization and do not create activity/quest progress.
- The town library's chapter directory, title/chapter search and material-type filters operate on this authorized response in the client. They do not add a publication API or bypass chapter authorization. The classroom workspace reads progress from current /world data; changing UI categories and preferences does not create participation, grades or model calls. Classroom switching uses the existing authenticated GET /world?classroom_id and changes the selected client classroom only after a successful response.
- POST /submissions {classroom_id,activity_id,question_id,idempotency_key,mode:run|submit,answer?,code?}; GET /submissions/{id}?classroom_id. Return id, activity/question/mode/status/feedback/created_at. Run never forms a formal grade.
- Feedback contains detail/status and optional public samples[{status,stdout,stderr,compile_output}]. Hidden tests, expected outputs and hidden indices are absent. States include prepared/dispatching/queued/running/accepted/wrong_answer/compile_error/runtime_error/time_limit/memory_limit/infrastructure_error/submission_unknown. Uncertain dispatches require reconciliation; no blind resubmit.

## Teachers and authoring

- GET /teacher/courses -> {chapters,knowledge_points,activities,npcs}, filtered to shared+owned content (admin may see all).
- POST/PUT/DELETE /teacher/chapters[/id]. Create {title,order_index?}; update {title?,order_index?}. POST/PUT/DELETE /teacher/knowledge-points[/id]. Create {chapter_id,title,content?}; update {title?,content?}. Shared source content is read-only for teachers; owned unreferenced entries may be deleted, otherwise409. Cross-owner reads/edits/bindings are rejected.
- POST /teacher/activities {id,chapter_id,title,kind,npc_key,material_id?,assistant_allowed?,knowledge_point_ids?}; PUT /teacher/activities/{id} updates owned content in place. KC IDs must be unique positive integers in the same authorized chapter. Shared activities cannot be overwritten.
- GET /teacher/questions; POST /teacher/questions {id,activity_id,title,kind,prompt,options,samples,answer,hidden_cases,source?}. New questions update the current activity question_ids; tasks reference only activity_id. Python samples+hidden cases total<=20 with validated field shapes and bounded text.
- GET /teacher/quests; POST /teacher/quests/validate {definition}; POST /teacher/quests {definition}. One current definition per ID; strict schema, graph, content and ownership validation. kind=main|side; optional nodes are booleans; activity_id must identify a real current activity of the required type. ALL merges ignore unselected branches but still require the selected branch and subsequent learning. Side quests do not implicitly block main chapter prerequisites.
- PUT /teacher/classrooms/{id}/releases/{chapter_id} {status:published|paused,opens_at:ISO8601|null,prerequisite_chapter_id?}. GET /teacher/classrooms/{id}/releases. Server-time evaluation is immediate. Releases control visibility, schedule and prerequisites; all students use current definitions.
- GET /teacher/classrooms/{id}/progress; GET /teacher/classrooms/{id}/students/{student_id}: real members (including completed_chapters: integer >= 0), node events, participation records, submissions and error distribution. completed_chapters counts released chapters whose required main quest IDs all have completed server-verified PlayerQuest instances for this student/class; it uses the same current main-quest rule as chapter prerequisites, excludes side-only chapters, and retains completed history while paused. Teachers own the class; preview cannot write student grades.
- POST /teacher/materials/upload multipart {chapter_id,title,material_id?,file} -> {id,status,title}; GET /teacher/materials. Status queued/processing/ready/failed persists. Upload alone does not publish; bind the material ID through an owned activity. Upload with the same material_id replaces the current content.
- POST /teacher/npcs is admin-only because world characters are global. Teachers bind existing characters using activities. Script schema supports speaker/portrait/text, next, choices, flag conditions, once and restricted effects; no arbitrary expressions/SQL/code.

## Active teaching assistant

- GET /assistant/status -> available, reason, model_calls. Missing credentials are explicit.
- POST /assistant/sessions {classroom_id,activity_id} -> id; GET /assistant/sessions/{id}; POST /assistant/sessions/{id}/messages {message,page_no?,video_time?,code?} streams SSE meta(request_id/session_id), token(text), references(items), done(status/tokens), error(detail).
- POST /assistant/requests/{id}/cancel; owner validation and thread-safe cancellation. Sessions isolate user/class/activity and reauthorize current material on every message. References contain material_id/page_id/page_no with no content version. Tests prohibit AI on assessments when the server policy forbids it.
- One create_agent factory, five read-only tools, no grading/unlock/publish/SQL/shell tools. Default3 model and5 tool calls,45s timeout,512 output tokens/model, conservative request/user/class budgets. Production has no fake provider.

Paused policy denies new content/progress/assistant requests immediately and preserves history; reopening continues stored state. The only built-in main quest is arrival (chapter179, 初来小镇：第一堂 Python 课). Retired shared quest definitions are removed during seed, so stored player history does not restore them to the current world. Teacher-owned definitions and learner grades remain intact. Original raw questions stay archived/unpublished unless explicitly bound to an authorized current activity. Validation results and external-service skips are documented in acceptance.md.
