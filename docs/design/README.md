# 界面设计规范

修改界面前先复核[已确认要求](../requirements.md)中的UI约束；每轮按[文档维护流程](../README.md#每轮维护流程)同步相应规范与验证。这里维护当前规则，历史试版与部署经过见[归档](../archive/README.md)。

Pythontopia 的学生游戏界面与教师后台使用两套布局和组件规范。选择规范以页面用途为准，不以登录账号角色为准：教师进入小镇时仍使用游戏界面，进入管理页时使用后台界面。

| 范围 | 规范 | 实现入口 |
| --- | --- | --- |
| `/world` 内任务日志、图书馆、地图、班级、设置、资料阅读、课程与练习工作区 | [游戏界面规范](game-interface.md) | `OverlayHost.vue`、`gameDesign.css`、`townWorkspaces.css`、`learningUi.css` |
| `/teacher` 班级教学、课程资源及学习体验管理 | [后台界面规范](teacher-interface.md) | `TeacherPage.vue`、`teacherTheme.css`、本地后台组件 |

游戏工作区共享透明外壳、单一中文标题和统一控件，内容以独立纸面卡片呈现，小镇从卡片之间露出。教师后台采用独立管理布局、表格和表单，保持自己的主题。两套主题必须保持作用域边界。

资料阅读和练习另共用学习支持区域：主内容与右侧“学习目标 / 文档或题目目录 / 当前角色”标签页分栏，助教采用淡立绘背景、清晰消息和底部输入。PDF 完整适应左侧卡片，题名与原始页码放在底部分页条；不向学生展示转换提取文本。所有目录或支持侧卡可折叠，页头统一展开；分栏宽度可拖动调整，间距保持统一，具体结构、可读性和交互要求见游戏规范的“学习工作区：内容与支持”。

练习逐题提交且可改错，单元测验支持单题/整卷排版并统一交卷、锁定结果；按钮采用无厚边的平面样式，状态图标统一使用Lucide。新游戏页面先接入统一工作区入口，再复用共享布局、图标与语义控件；新后台页面先复用现有后台组件。只有正文结构或业务交互不同的部分才增加页面局部样式。

这些文档记录当前设计规则与验收要求，不代替实际验证记录。产品行为见 [产品说明](../product.md)，状态与样式职责见 [架构说明](../architecture.md)，启动和检查命令见 [开发说明](../development.md)，实际通过、失败、跳过及未覆盖项统一记录在 [验收记录](../acceptance.md)。继续工作时更新现有规范和记录，不另建平行设计计划。
