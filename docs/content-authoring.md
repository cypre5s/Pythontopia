# 内容配置与发布

## 当前课程交换方式

2026-11-12 起，运行入口使用 `data/course/<包目录>/` 的解压目录。ZIP上传关闭，目录选择直接复制到私有暂存目录并校验，不再压缩和解压。导出把完整内容原子发布为 `data/course/export-<班级ID>-<随机ID>/` 并返回路径。已有ZIP预览仅保留应用兼容，旧ZIP工具用于离线历史包处理。本文旧ZIP格式和阶段验收描述不代表当前上传入口开放。

对白在后台按轮次分框编辑，支持添加和删除；课程包文本仍按空行分轮，最后一轮才展示选项并触发交谈检查点，轮次随服务端会话恢复。流程允许多个结束节点，编排建议见[教学流程建议文档](教学流程建议文档.md)。

先复核[已确认要求](requirements.md)中的数据与教学约束；本页拥有当前配置格式，运行命令见[开发手册](development.md)。

## 当前配置与 YAML 导入

运行中的章节、NPC、活动、任务与流程保存在班级课程实例。旧格式转换来源位于私有 `data/course/legacy/content/chapters/`，不是应用内置资源。`shared.yaml` 保存公共NPC和第一章共用练习（quests为空），当前唯一内置主线为arrival，旧第二章任务不再导入，`chapter01.yaml` 保存当前第一章任务与剧情。旧来源的私有答案位于其 `questions/concepts.private.yaml`；新包的私有答案在 `content/secrets`，整个包只向授权教师开放，不能进入学生静态资源或公开响应。

每个稳定ID只对应一份当前配置，没有材料、活动、题目、任务或剧情的内容版本和快照。完整包同课程更新按稳定ID映射本班对象，同ID更新、新ID新增，历史和进行中引用须先通过影响检查；重复导入不增加重复记录。不再填写version、activity_version或material_version。schema_version只表示文件格式，story revision只处理并发推进，均不是内容版本。

校验、迁移和重复导入统一按[开发手册](development.md)执行，不在脚本格式说明中复制启动命令。

维护工具seed仅用于显式整理旧格式来源，不能写入已绑定班级实例的同ID内容；班级日常更新使用完整包导入或后台。seed会更新课程源章节、知识点、文本、例题、题目及YAML定义，但不会删除学生、班级、任务节点记录、阅读进度、提交或成绩；手动上传的当前文件不会被种子文本覆盖。内置共享任务按当前YAML集合收敛，移除的旧任务不会继续分配或展示；教师自有任务和历史学习记录保留。删除其他课程资源条目不会级联删除学生内容。保持ID稳定：旧节点被移除后历史记录仍保留，但不会自动映射到新节点；修改题面/答案不会重新评分历史提交，已有accepted仍按题目ID计入通过。若需要独立的新一次考核，应使用新的活动/题目ID。已完成任务不因配置更新自动撤销。修改必读页后，读取进度和检查任务证据都按当前必读页与保留的访问页重新判定。没有旧版教学内容可供恢复。

剧情会话持久化当前对白、等待活动及 revision。课程包更新预检保护正在使用的节点、活动依赖和已有任务证据。教学编辑器允许教师明确确认后，清理本班受影响的记录并发布。删除流程会清理该流程的会话，修改流程会清理受影响的进行中会话。删除任务或改变目标结构会清理该任务的进度及相关会话和完成标记，保留阅读、作答、成绩、已发放的建筑解锁和其他任务。学生可重新完成修改后的任务，仍有效的活动证据可按当前规则复用。依赖主线的后续章节会重新判断开放条件。草稿中悬空的引用仍须修正后才能发布。

教学配置由显式导入载入数据库，容器启动不执行seed；外部课程包通过受控来源路径提供。后台日常维护不依赖重建镜像，包内YAML修改后先校验再显式导入。新后台提供流程、地图交互与任务编辑；手工包文件仍必须经过同一服务端校验与显式导入。

旧来源格式的章节聚合文件包含`schema_version/id/chapter_id/quest/story/activities`，须经转换器转为下方完整ZIP；它不是新包中单个chapter.yaml的结构。`quest` 仍使用既有任务DAG；节点可配置 `navigation_target` 指向NPC。`story` 包含：

- `bindings`：命名活动绑定，任务流程每项明确`activity_id/goal_id`；公共流程只需`activity_id`，不伪造任务目标。
- `entries`：每个NPC有从上到下匹配的入口列表，最后一项必须为 `when: {always: true}`。原有 `goal_complete`、`goal_ready`、`activity_started` 简写继续有效；完整条件组合和成绩分支见下方[剧情条件](#剧情条件成绩回应与任务外日常)。反复访问通过重新选入口实现。
- `nodes`：支持`dialogue`、`activity`、`branch`、`random`、`action`、`unlock_building`、`end`。对白含稳定ID、说话者、文本、next或带ID的选项。`checkpoint` 只能引用交谈目标，并由服务端确认；日常禁止任务检查点和活动。单次演出无环，缺失跳转和不可达节点拒绝发布。
- `activity`：引用binding，必须定义 `returns.completed/suspended/unavailable`。打开活动保存等待点，玩家主动关闭后由服务端检查证据决定返回分支；刷新直接恢复等待活动。
- 旧来源`checkpoint_effects.library_unlocked`由显式迁移兼容到建筑ID。新流程使用`unlock_building`受限节点/效果，服务端验证完成条件并幂等记录BuildingUnlock。纯日常不允许效果。操作节点配置打开的工作区或具备室内的建筑，落点由系统控制。需要说明时将对白接到操作前，例如“对白 → 打开页面 → 结束”。旧包内的操作提示仍可读取，编辑器支持转换为独立对白。

新第一章依次为：镇长欢迎→馆员介绍→指定阅读→教练介绍→概念练习→镇长测试说明→独立章节测试→章节总结。镇长重复拜访只提醒；馆员记录中途离开与重返；练习和测试分别保存正式结果。章节测试不开放助教。

完整ZIP的活动条目用顶层question_ids声明有序题集，导入后只存ActivityQuestion，不在Activity.content保留副本；完整包拒绝content.question_ids。旧来源转换器才接受旧写法content.question_ids。后台先独立创建题目，再通过活动选题操作引用；同一道题可用于多个练习/测验，同ID题面/答案更新不重评旧提交。

原课程的稳定活动ID`ch1-lesson`绑定旧来源稳定资料ID186（本班运行ID由实例映射），馆员作为教学身份；完成规则为 `content.completion.required_page_ids: [10715,10723,10724]`，对应真实第34、42、43页。界面提供指定页导航并说明这只是阅读参与目标，掌握情况由练习和测试判定。服务器按用户、班级、活动保存页码和参与页集合；单条participation记录、访问末页或关闭窗口不能替代完成规则。导入课程包后，7份PDF原位替换纯文本课件展示并保留材料、页面ID及页码，34份视频作为资料库补充内容，不增加主线任务；原文件保存在私有存储，不随Git分发。学生通过私有阅读器查看PDF整页，不展示转换或提取文本；后台文本仍用于授权检索与引用。人工编写的文本资料仍按文本形式阅读。

## 学习目标与重点标记配置

活动仍一次绑定一份 `material_id`。多个资料的教学流程通过已有任务/剧情串联多个活动，不在一个活动中另建资料权限。新配置放在活动 `content.learning`；教师API使用顶层 `learning` 字段创建或更新，服务器写入同一内容字段。活动编辑器维护相同的学习规则，不另存一套完成状态。

阅读活动可以要求整份课件，或按原始页码指定闭区间。以下是活动 `content` 中的实际可用字段：

```yaml
content:
  question_ids: []
  learning:
    reading:
      scope: all
    highlights:
      pages:
        - start_page: 42
          end_page: 43
          label: 重点：计算思维
```

要求一段页码时，把上面的 `reading` 换成：

```yaml
reading:
  scope: range
  start_page: 34
  end_page: 43
```

`scope: all` 不能附带起止页；`range` 必须同时给出正整数起止页且顺序正确，首尾必须对应真实原始页码，目标集合包含该闭区间内实际存在的页面。进度分母为当前目标页集合大小，分子为其中服务端已记录的不同页面数；翻到末页不等于完成整份材料。原页面ID和既有访问集合继续保留，改变范围后按当前规则重新计算参与完成状态，不清空旧访问页或改动已完成任务与成绩。

视频活动绑定可靠时长、已就绪的实际视频资料；下面以资料193的中国计算机发展史视频为例（课程清单时长460秒）。

```yaml
content:
  question_ids: []
  learning:
    video:
      minimum_seconds: 180
    highlights:
      video:
        - start_seconds: 60
          end_seconds: 105
          label: 重点讲解
```

`minimum_seconds` 是1至86400的整数，表示累计有效播放秒数，允许实际重复观看，因此可大于视频单次长度；它不是唯一片段覆盖率，也不是知识掌握率。学生需要明确播放；服务端依据连续心跳、实际媒体位置增量和服务端墙钟计时，不把客户端直接上报的总观看时间或末尾位置当作完成证据。正常前端每5秒记录一次，并在暂停、跳转、结束和隐藏页面时发送边界状态。每次仅计入连续且不超过20秒的心跳间隔，计入值不超过墙钟时间和按前次播放速率折算的合理媒体推进时间；支持0.25–4倍速，倍速播放不会额外赚取有效秒数。改变播放速率时先记录边界，再开始新播放会话；跳播、暂停等待、长时间离线或不符合声明速率的过快推进不增加时长。

播放会话有UUID和递增序号，相同会话/序号/内容重试不会重复累计，序号复用不同内容或不连续会返回冲突；同时播放的另一会话在前一会话活跃15秒内不能抢占累计。每个请求核对当前活动绑定的材料ID，教师换资料后旧视频请求不能写入新视频进度。进度按学生、班级、活动隔离，视频累计另按稳定材料ID保存简洁秒数摘要（每活动最多64份），切回原资料可继续，旧会话不复用。同材料ID替换当前文件沿用稳定ID的参与记录约定，不保存旧文件或配置快照。

`highlights.pages` 与 `highlights.video` 只描述当前绑定资料的重点：每项必须有起止范围和1至200字 `label`，每种最多100项。页面范围首尾必须真实存在；视频片段必须有正长度且不超过可靠视频时长。它们用于目录标记与定位，点击重点不产生额外完成证据，不向学生展示后台提取文本。

一个活动的 `reading` 与 `video` 完成规则互斥。新完成规则也不能与旧 `content.completion.required_page_ids` 同时配置，避免两套条件相互矛盾；仅增加 `learning.highlights` 可以保留原必读页规则。当前内置主线继续使用原始34/42/43页ID，未因新增能力而要求阅读全部45页或增加视频任务。练习继续按当前已审核发布题集的服务端正式 `accepted` 提交判断完成，进度为不同已通过题数/当前题集数；运行公开样例和重复通过同题不增加计数。测验采用下述一次整卷提交语义。

YAML结构检查、seed真实资料解析、教师创建/更新与学生进度接口共用验证。更换活动资料时重新校验现有规则与重点范围；资料必须属于活动章节及当前授权范围。未知字段、布尔值冒充数字、起止倒置、无真实页码、未知视频时长、越界片段或错误资料类型均拒绝，不能静默降级为完成。缺失文件、暂停章节或未加入班级不允许记进度；教师预览不写学生记录。新视频状态保存在原 `activity_progress.media_progress` JSON，旧行只补空对象，已有页码/访问页/成绩不变，开发重玩仍按原活动进度表统一清理。
本轮已接入受限流程编辑与运行；任意循环、卡片节点或脚本化镜头节点不在当前支持范围；跨地图自动导航已衔接小镇与图书馆，地图渲染仍使用现有适配器。未来扩展应增加受限指令和验证，不允许在脚本中执行代码。YAML拒绝重复字段、锚点、别名、自定义对象及过深/过大的数据。

权威 HTTP 字段见 api-contract.md。真实旧课程源已保留到私有 data/course/legacy/course-pack-43/json；保留原始文档、页面、章节和知识点 ID。种子可以重复运行，不创建默认教师或班级。39道原编程题保留在外部旧来源，普通导入只取当前教学使用的题目；当前主线使用独立的第一章概念练习和章节测试。后续若要开放原题，应先审查题面、来源与私有用例，再绑定当前活动；归档导入本身不等于发布。

## 教师操作

地图配置位于 `shared/world/world.json`，与章节文本分工：地图定义建筑、门和地点，章节脚本引用稳定的NPC/地点ID。maps中的建筑必须配置中文label、purpose、status、object_name及可达anchor；open建筑绑定portal，未开放室内使用closed/landmark并给出真实用途，不能虚构可进入场景。portal声明from、to及系统保留字段required_flags/blocked_message，后两者不再承载本班教学开放条件；实际开放和提示由building_access课程策略决定；源/目标都必须落在可达位置，并提供返回路线。建筑anchor不再复制进interactions。调整后运行 `node scripts/validate-world.mjs` 与 `node scripts/audit-assets.mjs`，再重建前后端。新增地图仍需使用现有支持的renderer或增加相应渲染实现。

当前11栋建筑都有屋顶名称及地图工作区目标，屋顶不附加开放状态文字；入口/出口使用小型素材箭头。地图工作区固定当前图，右侧卡顶部筛选建筑/人物，前往才触发实际导航；预览只画逻辑地图，外围景观只保留在实际场景与登录背景。未开放建筑不显示E提示或未开放弹字。图书馆门禁在新版镇长欢迎后开放，室内家具布局位于library.json。

同一物件可用`points: [{map_key, tile_x, tile_y}, ...]`替代单点字段，1至64个唯一真实位置，不能混用两种形式。每个位置都须在可走区，并与美术对象的interaction_id及脚底锚点一致。图书馆10组书架统一绑定library_shelf，地图只显示一个语义项；点击柜体优先去该柜前，普通导航选择最近可达柜前。物件证据半径2，不能用一个大范围点覆盖整个房间。旧任务事件保持原值，显示名称别名由前端兼容。

地图可声明walk_bounds（可行走矩形）、render_bounds（景观及有界镜头矩形）与camera_mode（centered/bounded）。小型室内使用centered，角色保持居中；大型室外扩展render_bounds但不扩展walk_bounds。静态素材和碰撞须保持一致，出生、NPC、交互与传送位置均须在行走范围内，保留旧存档坐标。新增素材保留原始PNG和来源记录，用图集帧或图层配置排布。

管理员通过 CLI 显式创建教师账号。教师登录后台，创建班级并分发加入码；学生注册后加入。教师上传文件，等待 ready 或查看 failed 原因，再创建自己的教学活动，绑定章节、NPC 和材料。教师编辑本班独立定义，来源模板与其他班级保持不变；新活动和任务仍由服务端校验授权及证据。

任务使用可视化DAG编辑，底层保存受校验的JSON节点列表。先校验再保存，按稳定ID关联。节点支持 TALK_TO_NPC、PLAY_DIALOGUE、REACH_LOCATION、INTERACT_OBJECT、STUDY_LESSON、COMPLETE_PRACTICE、PASS_ASSESSMENT、REPORT_BACK。dependencies 是节点 ID 列表，aggregation 默认 ALL，可用 ANY；optional 是可选目标。学习/练习节点必须绑定实际 activity_id。

分支父节点给出 choices（id、label），子节点用 condition: {node, choice} 引用直接父节点。任务完成只要求实际选择的支路；不得用任意代码或 SQL 作为条件。任务effects允许set_world_flag和unlock_building；建筑开放优先使用后者的building_id，旧library_unlocked效果兼容映射为BuildingUnlock。Story检查点效果使用更窄白名单，不等同于任务effects。重复 ID、悬空依赖、环、错误内容、非法效果应在保存前被拒绝。

NPC 的教学身份由活动 npc_key 配置决定，不创建第二套页面或 Agent。对白是确定性脚本，不调用模型。新增 NPC/活动/任务通过配置 API 完成。世界坐标须经地图可达校验，图书馆室内边界为18×14。

教师按班级发布章节，指定 published/paused、带时区 opens_at与可选前置。界面默认 Asia/Shanghai，服务端按当前时间即时判定。暂停不删除成绩；当前策略为暂停后拒绝继续访问该章，重新开放后从已保存状态继续。教师预览不可写入学生成绩。

## 媒体与安全

文本使用 UTF-8；PDF 支持私有阅读；MP4/WebM 支持鉴权文件流与 Range；PPT/PPTX 必须经过配置的隔离 LibreOffice 转换。未安装转换环境时保留失败状态，不能伪报成功。不要将私有材料复制到 frontend/public，不要把隐藏答案写进题干、公开样例或助教可见上下文。同material_id上传替换当前文件，绑定该ID的活动读取新内容；旧文件不作为历史版本提供访问。

## 自有章节与知识点

教师后台章节与知识点页面可编辑当前班级实例的章节/KC，包括导入后的原课程条目；不会改写来源模板或其他班级。新增内容仍使用当前Python运行能力，并非另建多学科平台。无引用条目可删，有活动、任务、发布或历史引用时返回409。

活动可按所属章节多选本班课程的KC，跨章节选择仍绑定到同一个活动。绑定直接更新活动并保留真实来源编码与页码；不能引用另一个班级的KC，即使同属一位教师。学生打开已授权活动时可读该活动显式关联的知识点，章节页面仍单独鉴权。题目独立录入后由活动选题关系引用，任务只引用活动ID。

任务日志按主/支线和进行中/已完成筛选。侧线不隐式阻挡主线的章节前置。教学、练习与其他工作区共享同一实现，新增绑定不复制页面。

排课界面时区由admin的VITE_TIME_ZONE或容器构建参数REBORN_TIME_ZONE配置，默认Asia/Shanghai。所有API时间戳带明确偏移，数据库保存UTC；DST不存在或重复的本地时刻会被界面拒绝，避免静默错排。

后台的表单、列表、分页、草稿与焦点规则由[后台规范](design/teacher-interface.md)拥有。题库先维护独立题目，活动选题另行保存；发布只控制开放状态、时间与前置，不改写已有成绩。

## 练习与一次交卷测验

`kind: practice` 使用单题练习，学生可逐题提交、改错和再次提交；完成规则仍是当前题集每题至少一次正式通过。`kind: assessment` 使用同一个已审核题集，允许单题或整卷浏览，但只能填写完整后一次“提交试卷”。单题布局与整卷布局只是同一份答案的两种显示方式，切换布局不创建新考核或清空草稿。

测验草稿按学生、班级、活动持久化，revision仅防并发草稿覆盖，不是内容版本。正式交卷在一个事务中锁定答案并建立每题判定记录，随后不可改答案、重新交卷或再运行不同代码。成绩统一满分100分，使用整数公式 `答对题数 × 100 // 总题数`，始终向下取整：三题答对一题33分、两题66分、全对100分；未完全判定时score为null，不冒充0分。正确题数/总题数保留，旧Submission不改写或重判。隐藏答案和私有用例不进入学生响应。Python题仍只通过Judge0判定，状态未知时不盲目重发。

测验的“完成”和“全部答对”分开：整份已交试卷的题目都已获得学术判定即完成，可继续剧情，即使有错题；全部答对另以passed表示。既有节点名PASS_ASSESSMENT继续使用，但其服务端证据改为已锁定且判定完毕的整卷，不再要求错题可重交到全对。基础设施故障、尚待判定或外部分发状态未知不算测验完成；试卷保持只读，不能把服务异常当成答错。

升级不会批量生成试卷或重评旧提交。当前全部题目已有正式终态记录时，按每题最新真实记录只读恢复legacy测验；学生首次查看时仅收录真实题目ID、本人答案与判定记录ID，固定只读身份，不插入新成绩或重评。收录后追加当前题目不会解锁旧卷；新的独立考核应使用新的活动ID。其他world/progress/任务证据查询不暗中收录或提交事务，已有成绩与任务记录保留。若仅完成一部分旧题，将真实已有答案预填新草稿，允许补齐后首次整卷交卷；旧记录保留。仍在判定或状态未知的旧记录需先完成对账，不能盲目交第二份。已交试卷只保存题目ID、本人答案和判定记录ID等考试证据，不保存旧题面、旧资料或内容快照。

## 剧情条件、成绩回应与任务外日常

任务仍负责“要完成什么”，演出负责“人物怎么回应”，日常演出负责“没有委托也能聊什么”。三者复用受校验的对白节点，不把每次闲聊建成支线任务。教师通过流程编辑器维护，完整包的章节流程位于curriculum/chapters/*/flows，公共流程位于world/flows；旧来源content/chapters及content/ambient只供显式转换。它们不会复制一份教材或建立内容快照。

条件用于NPC入口、branch分支、日常可用性和dialogue选项的when；所有判断在服务端读取当前学生、当前班级的授权证据，不能写Python表达式。顺序路由从上到下选第一项匹配者，最后必须有always兜底。可组合的条件包括：

| 条件 | 用途 |
| --- | --- |
| `always: true` | 无条件兜底 |
| `goal_complete` / `goal_ready` / `activity_started` | 保留现有任务演出的简写 |
| `goal: {quest_id, id, status}` | 指定任务目标的ready、complete、locked或skipped状态 |
| `quest: {id, status}` | 指定任务active或complete |
| `chapter: {id, status}` | 章节available（当前已开放）或complete（权威主线完成证据） |
| `assessment_score: {activity_id, min?, max?}` | 已判完测验的百分制闭区间，min/max至少填一项；未判完不命中 |
| `building_unlocked: 建筑ID` / `activity_completed: 活动ID` | 已解锁建筑或真实活动完成证据 |
| `all_quests_complete: true` | 至少有一个当前可见任务，且全部完成；没有任务时使用always |
| `all: [条件, ...]` / `any: [条件, ...]` / `not: 条件` | 有界条件组合，无任意代码执行 |

例如在测验完成后放一个自动分支，正文节点由该分支选择。分支本身不增加任务或修改分数：

```yaml
- id: exam-ending
  type: branch
  routes:
  - when: {assessment_score: {activity_id: ch1-assessment, min: 100}}
    node: mayor-score-excellent
  - when: {assessment_score: {activity_id: ch1-assessment, min: 60, max: 99}}
    node: mayor-score-good
  - when: {always: true}
    node: mayor-score-encourage
```

本例是节点片段，引用的三个对白节点也必须在同一演出的nodes中定义，并能走到end。第一章内置剧情保留原总结和任务检查点，再按满分、60–99分、0–59分给出不同回应；成绩不足不会让一次交卷测验无法继续。

日常演出使用 `mode: ambient`，不绑定quest；chapter_id可空表示公共日常；绑定真实章节时继续受发布授权，始终遵守班级成员与NPC距离权限。`bindings`必须为空，不能包含学习activity节点、任务checkpoint或解锁effects。`when`决定整段日常何时可用；例如 `quest: {id: arrival, status: complete}` 可让第一堂课结束后继续闲聊。任务当前有可执行目标或等待中的活动时优先，日常不能抢走教学进度。

选项可以附加条件，符合章节状态时才出现；隐藏选项不能靠手工发送choice绕过，提交选项时服务端再次检查：

```yaml
choices:
- id: next-chapter
  label: 下一章会学些什么？
  when: {chapter: {id: 180, status: available}}
  next: next-chapter-chat
- id: goodbye
  label: 下次再聊
  next: end
```

保留无条件离开选项，避免所有条件都不满足时无法退出。`random`节点用 `next: [对白节点ID, ...]` 配置候选，对每次新互动由服务端选取；所选对白位置保存在原StorySession，刷新、恢复或幂等重试不重新抽取。开始新的闲聊才会重新选择。随机节点依然遵守有界无环图，不能执行活动、写成绩或冒充AI对话。日常只保存对白会话，不写学习事件、任务目标、世界解锁标记或助教调用。

## 独立资料与题库

资料和题目通过关联表连接多个章节，后台可先创建未归类草稿；学习活动引用时校验章节、所属教师、就绪/审核状态及班级开放权限。资料不设必读/补充分类，具体学习完成条件仍在活动。题目source_type仅ai_generated/imported；后台录入归入imported，source可选记录材料与页码，不凭空生成引用。题目状态draft/ready/disabled分别表示待审核/可用/停用；新AI题应先审核，本轮仅准备数据和管理能力。

题目与活动的关联、顺序只保存在ActivityQuestion，学生提交与成绩仍按用户/班级/活动/题目隔离。删除被活动、学习记录或正式提交引用的内容应返回冲突，不靠后台删除级联清空学习证据。历史废弃内容清理使用显式开发命令，范围与结果见开发手册和验收记录。

## 班级课程完整包设计

本节拥有完整包格式、班级课程边界及唯一阶段计划。教师在React后台维护资料、题目、活动、任务、剧情与地图交互；完整ZIP用于跨班复制、备份与交换，运行权威来源是数据库及私有文件存储。仍使用现有Python教学能力，不承诺任意学科、任意语言执行或多课程同时学习。已实现范围及实际验证见[验收记录](acceptance.md)；旧来源必须显式转换，不能直接当新ZIP导入。

### 程序、课程与学生数据的边界

| 随程序发布 | 随课程包维护 | 仅保存在运行环境 |
| --- | --- | --- |
| 地图尺寸、地形、碰撞、镜头、基础出生点 | 对现有对象的交互绑定、合法区域、提示、触发方式 | 学生位置、任务与活动进度 |
| 建筑稳定ID、基础名称/用途、室内能力、入口/出口/落点 | 建筑默认开放、条件开放、锁定提示 | 按用户与班级隔离的已解锁建筑 |
| 地图、美术资源及其许可、入口箭头样式与自动定位 | NPC出现条件、教学角色、对白与流程 | 账号、班级成员、成绩、提交、聊天及流程会话 |
| 条件解释器、活动执行器、鉴权和判题能力 | 章节、知识点、资料、题库、活动、任务、助教教学策略 | 数据库连接、模型/判题凭据及运行配置 |

固定世界资源位于程序拥有的`shared/world/world.json`及地图素材目录；课程包只引用稳定的map_id/object_id/building_id及受支持资源ID。教师可以选择对象或绘制交互区域，不编辑地形、碰撞、镜头、室内结构和传送落点；区域必须处于合法地图范围并通过可达性校验。NPC教学角色引用系统角色素材，不能借内容配置加载可执行代码。

入口箭头由系统根据具备室内能力的建筑入口自动定位和显示；素材、尺寸、偏移及锁定视觉状态不由课程包配置。当前portal_marker实际只定义统一素材与尺寸，位置已从portal派生，并非每个箭头单独配置位置。

建筑可进入须同时满足系统具有室内、课程允许使用、学生满足通行权限。课程定义默认开放与条件开放，学生存档保存已解锁建筑ID集合；解锁操作由服务端验证真实流程证据后幂等写入，按用户/班级/课程实例隔离。以建筑ID替代library_unlocked一类逐栋特设标记，迁移保留旧状态。出口保持安全可用，课程更新不能将室内学生困住。

### 公共流程、章节流程与条件

公共流程是不专属于某章的交互，不是虚拟默认章节；章节学习期间也可以使用。章节流程组织当前章节的教学过程。公共流程可按已完成章节、任务目标、活动结果、建筑解锁等服务端事实选择不同对白。编辑器提供如果/否则如果/否则及ALL/ANY等受限条件，不执行任意表达式或eval/exec。

例：居民交谈按顺序判断“第二章已完成→进阶对白；否则第一章已完成→第一课反馈；否则→欢迎对白”。只选择第一个满足的分支，提供兜底，不按文件遍历顺序决定结果。NPC的出现条件、建筑的开放条件放在对象属性，使用与流程相同的条件模型；领取钥匙等需要持久记录的行为才使用解锁操作。

交互路由：优先恢复仍有效且属于当前交互的等待/进行中会话；其他进行中会话须先显式结束，不能同时打开第二个主流程；活动suspended返回分支仍属于当前会话。没有待恢复会话时，依次选择：当前入口有可执行目标的task → 有章节public/ambient → 无章节public/ambient → 未完成但目标暂不在此入口的task → 已完成task。同层按priority从高到低，平局拒绝。校验重复入口与可冲突的同优先级规则，运行时也拒绝无法唯一决定的入口。章节切换、账户/班级切换及恢复均重新鉴权。

公共不等于无条件授权。打开图书馆只能看到当前用户有权访问的资料。纯日常对白不产生学习证据、成绩、解锁或AI调用；需要解锁的公共业务流程必须显式使用受验证的操作节点，与纯日常对白区分。完成第二章等案例仅演示通用能力，不恢复已退出的内置章节任务，内置主线仍只有arrival。

### 编辑器与运行模型

- 交互点：在哪里、怎样触发；引用对象或合法区域，绑定流程入口。
- 流程：触发之后发生什么；对白、选项、条件、界面操作、开始活动、等待真实结果、受限效果及结束。
- 活动：学习什么、怎么判定；资料范围、有序选题、完成规则与助教授权。
- 任务：有哪些目标及依赖；引用活动或流程的服务端证据，不复制完成状态。

典型流程：选择对象/区域→交互入口→条件判断→提示或对白→开始活动→等待真实完成→后续对白/解锁建筑→结束。打开图书馆、展示提示、进入建筑是操作，不创建虚假学习活动。等待节点持久保存并可恢复；正式判定完成后才继续，不以客户端关闭弹窗冒充完成。重复请求不能重复解锁、提交或发放证据；外部判题结果不明时等待对账。

编辑器分为地图交互、对象属性、流程图、活动、任务与内容库几个视图，读写同一模型。流程节点位置、分组、注释只属于编辑信息，不决定执行顺序。节点ID稳定，条件/选项有类型和边界；校验失联节点、无出口路径、自动执行循环与不可达引用，避免无等待循环。React编辑器通过类型化属性面板、条件树、流程画布与任务DAG维护上述模型；服务端再次校验全部引用。教师预览使用本班真实学生已有状态，只报告将命中的流程和首个停靠节点，不执行活动或写学习证据。

### 包目录与格式

采用章节组织流程、独立内容库复用资料与题目的混合结构。ZIP根目录直接包含manifest，采用以下布局。目录名和文件名仅用于组织，实体身份取自文件内稳定ID，导出器使用排序编号生成路径：


manifest包含schema_version、package_id、名称、package_version、created_at、updated_at、exported_at、课程入口、所需世界ID/资源契约版本和能力清单。创建时间不被每次导出重置；package_version只标记交换产物，schema_version表示格式兼容，不引入学生可选内容版本、教学快照或历史教材恢复系统。清单声明的能力缺失时拒绝激活，不能假装支持其他语言或学科活动。

课程及其条目使用包内稳定ID，数据库ID由班级实例映射；同一来源包导入不同班级不能共享可变定义。资料/题目与章节、题目与知识点使用结构化多对多关联，标签仅作搜索。活动题目与顺序只有一份关系来源；章节目录不复制题目/媒体，也不再维护另一份活动选题列表。页面保留稳定ID与页码，支持活动精确引用。跨包导入不能仅凭相同字符串ID覆盖另一个课程。

YAML用于可读配置与流程；JSONL每行一个对象，题库可分片，支持逐条校验与批处理；媒体保留原文件，不编码进文本配置。数百道题无需依赖YAML容量限制来设计，运行时仍由数据库分页检索。导入需对单文件、总量、条目数、嵌套、媒体类型、归档解压量和处理时长设置可配置上限，实际阈值见下方清单契约；当前ZIP上传默认2GiB（环境变量REBORN_COURSE_UPLOAD_BYTES），反向代理上限须同步；运行时分页与交换容量是不同边界。

题库来源仍仅ai_generated/imported；外部平台和手工录入归入导入，AI生成进入审核，不自动进入已发布活动。参考资料/页码为可选依据。PPT等可保留原件及转换结果，转换未完成或失败必须显式标记，不能把原件存在等同于学生可阅读。转录保留生成方式与审核状态，不伪造媒体或知识点证据。

完整导出覆盖当前课程实例全部有权导出的教学定义，包括未归类资料、未被活动选用的题目、待审核草稿和停用条目，以及私有答案、活动、任务、公共与章节流程、交互配置、助教教学配置、编辑布局及其合法资源依赖；不能只收集从活动或流程可达的内容。导入保留草稿/审核/发布状态，不自动开放给学生。缺失资源列入报告，不能标为可完整恢复；系统资源只写依赖清单，不能打包用户无权导出的共享素材。完整包是教师私有产物，secrets目录不是安全边界，整个包不得经静态学生路径公开。学生仅获得过滤后的授权运行DTO，不获得原包。

### 班级独立编辑与导入导出

每班持有一个当前CourseInstance。教师创建班级时选择有权使用的包，显式导入后生成该班级独立定义；修改甲班不影响乙班或原包。底层文件可以按哈希复用，但引用、删除和读取权限按班级验证。学生记录按用户/班级/课程实例隔离；共享源内容及现有教师私有内容如何迁入实例必须有明确映射，不能未经授权复制别人的课程。

挂载的data/course为私有交换区，保存待导入包和导出产物；不是Web静态目录，也不是运行时第二份权威配置。课程源已移至私有`data/course/legacy/`并从Git移出，整个data目录不进入Git或镜像；Compose绑定私有data/course交换目录，固定世界资源随程序发布。原文件移动保留，不删除原课程。上传读取、导出写入目录分权限管理，清理交换产物不得删除运行中私有媒体。

生命周期：选择/上传→暂存→格式、资源、引用、世界能力、流程及权限校验→差异与影响预览→教师确认→事务激活当前定义。运行时读取数据库与私有文件存储；后台编辑更新当前定义，显式导出再写包。直接修改挂载文件不自动生效；重启不导入。

已有班级可以在后台浏览私有交换区顶层的 ZIP 和带 `manifest.yaml` 的包目录，也可以重新选择本人曾为本班上传并仍然存在的 ZIP。所有来源均生成新的预览后才能应用。目录列表展示清单元数据，完整引用与媒体只在预览时校验。

导入按包哈希、目标实例及请求ID去重；使用并发修订检查，预览后内容已变化则重新预览。先验证完整资源再激活，失败保留原课程，未引用暂存文件不对学生开放。导出读取一致的当前定义视图，避免并发编辑造成一半新一半旧；导出读一致性不等于保存教学内容历史版本。

已有班级的同课程更新按稳定ID更新，不清学生、成员、任务证据、阅读进度、提交或成绩，不重新评分历史作答。影响正在进行的活动、已锁试卷、页面引用、等待流程、NPC与建筑权限时，预览具体影响；不能简单硬删被历史引用的数据，也不能复用旧ID表达不同考核。正在执行的流程、等待活动依赖、已有学习记录的任务结构及锁卷题集变化会阻止导入，预览列明阻断项。历史引用禁止硬删除；新增一次考核使用新活动或题目ID。已结束会话保留，不重新执行效果。

近期支持新班级导入、班内编辑、完整导出与同课程更新。有学习记录的班级直接换成另一门课程暂不支持；不能将旧成绩映射到新题或静默清档。后续若扩展需独立设计课程切换与历史访问规则。班级列表、导入/导出、文件下载和后台编辑均服务端授权，预览不授予写权限。

### 清单与资源预检契约

第一版必需manifest.yaml、curriculum/course.yaml、assets/index.jsonl；无媒体时资源清单可以为空。manifest必填schema_version=1、package_id、name、字符串package_version、带时区created_at、requires和entry；updated_at/exported_at可选且按时间递增。entry固定curriculum/course.yaml。requires为world_id=pythontopia-town、world_schema_version=1及不重复的capabilities列表，当前识别reading/video/practice/assessment/dialogue/tasks/library。能力名称匹配只属于格式预检，不代表整包可执行。

资源清单每行一个JSON对象，必填id、path、media_type、size_bytes、sha256、source、license；path是assets内POSIX相对路径，sha256为64位小写十六进制。资源必须存在、清单完整、ID/路径不重复、大小和哈希一致，类型声明与支持的扩展名相符；扩展名检查不是媒体内容解码、转换或许可真实性验证。

默认限额：manifest及入口文本各512KiB、清单16MiB、单文件2GiB、总量8GiB、目录条目20000、资源10000、目录深度32。限制以PackageLimits集中定义，当前CLI不提供放宽参数。拒绝路径穿越、绝对路径、反斜杠、Windows特殊文件名、大小写路径冲突、符号链接/重解析点、重复键、YAML锚点/别名及未知字段。该独立CLI只证明清单与资源完整性；完整ZIP导入另外执行解压安全、领域引用、流程、内容类型及本班学习影响检查。PDF/PPT等解析和转换采用受控处理器，真实转换服务的可用性需单独验证。
