# 内容配置与发布

## 当前配置与 YAML 导入（2026-11-07）

章节任务、NPC对白和活动绑定位于 `backend/content/chapters/`。`shared.yaml` 保存公共NPC和第一章共用练习（quests为空），当前唯一内置主线为arrival，旧第二章任务不再导入，`chapter01.yaml` 保存当前第一章任务与剧情。题目答案只在后端 `backend/content/questions/concepts.private.yaml`，不得进入前端或公开响应。

每个稳定ID只对应一份当前配置，没有材料、活动、题目、任务或剧情的内容版本和快照。修改YAML后运行校验与seed，同ID直接更新，新ID新增；重复导入不增加重复记录。不再填写version、activity_version或material_version。schema_version只表示文件格式，story revision只处理并发推进，均不是内容版本。

```sh
cd backend
python -m app.chapter_content --check
python -m alembic upgrade head
python -m app.seed
```

seed会更新课程源章节、知识点、文本、例题、题目及YAML定义，但不会删除学生、班级、任务节点记录、阅读进度、提交或成绩；手动上传的当前文件不会被种子文本覆盖。内置共享任务按当前YAML集合收敛，移除的旧任务不会继续分配或展示；教师自有任务和历史学习记录保留。删除其他课程资源条目不会级联删除学生内容。保持ID稳定：旧节点被移除后历史记录仍保留，但不会自动映射到新节点；修改题面/答案不会重新评分历史提交，已有accepted仍按题目ID计入通过。若需要独立的新一次考核，应使用新的活动/题目ID。已完成任务不因配置更新自动撤销。修改必读页后，读取进度和检查任务证据都按当前必读页与保留的访问页重新判定。没有旧版教学内容可供恢复。

剧情会话仍持久化当前对白/等待活动及revision。导入后若原节点或活动绑定已失效，会话结束，下次交互重新选择入口；任务进度、阅读和成绩保留。不要在学生进行中随意重用节点ID表达完全不同的教学要求。

镜像构建时复制YAML，运行中的容器不直接读取宿主机文件；修改后需要重建API。当前容器每次启动依次执行Alembic、seed和API，因此启动会检查/同步当前配置，错误会阻止API启动。无需专门编辑器，使用文本编辑、校验与独立预览即可。

章节包包含 `schema_version/id/chapter_id/quest/story/activities`。`quest` 仍使用既有任务DAG；节点可配置 `navigation_target` 指向NPC。`story` 包含：

- `bindings`：命名活动绑定，每项明确 `activity_id/goal_id`。
- `entries`：每个NPC有从上到下匹配的入口列表，最后一项必须为 `when: {always: true}`。支持 `goal_complete`、`goal_ready`、`activity_started` 和 `always`；反复访问通过重新选入口实现。
- `nodes`：本轮支持 `dialogue`、`activity`、`end`。对白含稳定ID、说话者、文本、next或带ID的选项。`checkpoint` 只能引用交谈目标，并由服务端确认。单次演出无环，缺失跳转和不可达节点拒绝发布。
- `activity`：引用binding，必须定义 `returns.completed/suspended/unavailable`。打开活动保存等待点，玩家主动关闭后由服务端检查证据决定返回分支；刷新直接恢复等待活动。
- `checkpoint_effects`：本轮只允许明确的 `library_unlocked` 门禁效果；欢迎对白完整确认后提前开放图书馆。

新第一章依次为：镇长欢迎→馆员介绍→指定阅读→教练介绍→概念练习→镇长测试说明→独立章节测试→章节总结。镇长重复拜访只提醒；馆员记录中途离开与重返；练习和测试分别保存正式结果。章节测试不开放助教。

每个活动显式固定 `content.question_ids`。新增题目直接更新当前活动题集；同ID题目导入时更新题面和答案，历史提交不重评。

`ch1-lesson` 绑定当前资料186，馆员作为教学身份；完成规则为 `content.completion.required_page_ids: [10715,10723,10724]`，对应真实第34、42、43页。界面提供指定页导航并说明这只是阅读参与目标，掌握情况由练习和测试判定。服务器按用户、班级、活动保存页码和参与页集合；单条participation记录、访问末页或关闭窗口不能替代完成规则。真实课程包的7份PDF已替换原纯文本课件，保留原材料、页面ID及页码；34份补充视频保留在资料库，不增加主线任务。学生通过私有阅读器查看PDF整页，不展示转换或提取文本；后台文本仍用于授权检索与引用。人工编写的文本资料仍按文本形式阅读。

## 学习目标与重点标记配置

活动仍一次绑定一份 `material_id`。多个资料的教学流程通过已有任务/剧情串联多个活动，不在一个活动中另建资料权限。新配置放在活动 `content.learning`；教师API使用顶层 `learning` 字段创建或更新，服务器写入同一内容字段。没有可视化目标编辑器。

阅读活动可以要求整份课件，或按原始页码指定闭区间。以下是活动 `content` 中的实际可用字段：

```yaml
content:
  question_ids: []
  learning:
    reading:
      scope: all
    highlights:
      pages:
        - start_page: 42
          end_page: 43
          label: 重点：计算思维
```

要求一段页码时，把上面的 `reading` 换成：

```yaml
reading:
  scope: range
  start_page: 34
  end_page: 43
```

`scope: all` 不能附带起止页；`range` 必须同时给出正整数起止页且顺序正确，首尾必须对应真实原始页码，目标集合包含该闭区间内实际存在的页面。进度分母为当前目标页集合大小，分子为其中服务端已记录的不同页面数；翻到末页不等于完成整份材料。原页面ID和既有访问集合继续保留，改变范围后按当前规则重新计算参与完成状态，不清空旧访问页或改动已完成任务与成绩。

视频活动绑定可靠时长、已就绪的实际视频资料；下面以资料193的中国计算机发展史视频为例（课程清单时长460秒）。

```yaml
content:
  question_ids: []
  learning:
    video:
      minimum_seconds: 180
    highlights:
      video:
        - start_seconds: 60
          end_seconds: 105
          label: 重点讲解
```

`minimum_seconds` 是1至86400的整数，表示累计有效播放秒数，允许实际重复观看，因此可大于视频单次长度；它不是唯一片段覆盖率，也不是知识掌握率。学生需要明确播放；服务端依据连续心跳、实际媒体位置增量和服务端墙钟计时，不把客户端直接上报的总观看时间或末尾位置当作完成证据。正常前端每5秒记录一次，并在暂停、跳转、结束和隐藏页面时发送边界状态。每次仅计入连续且不超过20秒的心跳间隔，计入值不超过墙钟时间和按前次播放速率折算的合理媒体推进时间；支持0.25–4倍速，倍速播放不会额外赚取有效秒数。改变播放速率时先记录边界，再开始新播放会话；跳播、暂停等待、长时间离线或不符合声明速率的过快推进不增加时长。

播放会话有UUID和递增序号，相同会话/序号/内容重试不会重复累计，序号复用不同内容或不连续会返回冲突；同时播放的另一会话在前一会话活跃15秒内不能抢占累计。每个请求核对当前活动绑定的材料ID，教师换资料后旧视频请求不能写入新视频进度。进度按学生、班级、活动隔离，视频累计另按稳定材料ID保存简洁秒数摘要（每活动最多64份），切回原资料可继续，旧会话不复用。同材料ID替换当前文件沿用稳定ID的参与记录约定，不保存旧文件或配置快照。

`highlights.pages` 与 `highlights.video` 只描述当前绑定资料的重点：每项必须有起止范围和1至200字 `label`，每种最多100项。页面范围首尾必须真实存在；视频片段必须有正长度且不超过可靠视频时长。它们用于目录标记与定位，点击重点不产生额外完成证据，不向学生展示后台提取文本。

一个活动的 `reading` 与 `video` 完成规则互斥。新完成规则也不能与旧 `content.completion.required_page_ids` 同时配置，避免两套条件相互矛盾；仅增加 `learning.highlights` 可以保留原必读页规则。当前内置主线继续使用原始34/42/43页ID，未因新增能力而要求阅读全部45页或增加视频任务。练习继续按当前已审核发布题集的服务端正式 `accepted` 提交判断完成，进度为不同已通过题数/当前题集数；运行公开样例和重复通过同题不增加计数。测验采用下述一次整卷提交语义。

YAML结构检查、seed真实资料解析、教师创建/更新与学生进度接口共用验证。更换活动资料时重新校验现有规则与重点范围；资料必须属于活动章节及当前授权范围。未知字段、布尔值冒充数字、起止倒置、无真实页码、未知视频时长、越界片段或错误资料类型均拒绝，不能静默降级为完成。缺失文件、暂停章节或未加入班级不允许记进度；教师预览不写学生记录。新视频状态保存在原 `activity_progress.media_progress` JSON，旧行只补空对象，已有页码/访问页/成绩不变，开发重玩仍按原活动进度表统一清理。
本轮尚未实现可视化演出编辑器、任意循环、卡片节点或脚本化镜头节点；跨地图自动导航已衔接小镇与图书馆，地图渲染仍使用现有适配器。未来扩展应增加受限指令和验证，不允许在脚本中执行代码。YAML拒绝重复字段、锚点、别名、自定义对象及过深/过大的数据。

权威 HTTP 字段见 api-contract.md。真实课程种子位于 data/course-pack-43/json；保留原始文档、页面、章节和知识点 ID。种子可以重复运行，不创建默认教师或班级。39道原编程题统一保留为后端未发布档案，当前主线使用独立的第一章概念练习和章节测试。后续若要开放原题，应先审查题面、来源与私有用例，再绑定当前活动；归档导入本身不等于发布。

## 教师操作

地图配置位于 `data/world/world.json`，与章节文本分工：地图定义建筑、门和地点，章节脚本引用稳定的NPC/地点ID。maps中的建筑必须配置中文label、purpose、status、object_name及可达anchor；open建筑绑定portal，未开放室内使用closed/landmark并给出真实用途，不能虚构可进入场景。portal声明from、to、required_flags和blocked_message；源/目标都必须落在可达位置，并提供返回路线。建筑anchor不再复制进interactions。调整后运行 `node scripts/validate-world.mjs` 与 `node scripts/audit-assets.mjs`，再重建前后端。新增地图仍需使用现有支持的renderer或增加相应渲染实现。

当前11栋建筑都有屋顶名称及地图工作区目标，屋顶不附加开放状态文字；入口/出口使用小型素材箭头。地图工作区固定当前图，右侧卡顶部筛选建筑/人物，前往才触发实际导航；预览只画逻辑地图，外围景观只保留在实际场景与登录背景。未开放建筑不显示E提示或未开放弹字。图书馆门禁在新版镇长欢迎后开放，室内家具布局位于library.json。

同一物件可用`points: [{map_key, tile_x, tile_y}, ...]`替代单点字段，1至64个唯一真实位置，不能混用两种形式。每个位置都须在可走区，并与美术对象的interaction_id及脚底锚点一致。图书馆10组书架统一绑定library_shelf，地图只显示一个语义项；点击柜体优先去该柜前，普通导航选择最近可达柜前。物件证据半径2，不能用一个大范围点覆盖整个房间。旧任务事件保持原值，显示名称别名由前端兼容。

地图可声明walk_bounds（可行走矩形）、render_bounds（景观及有界镜头矩形）与camera_mode（centered/bounded）。小型室内使用centered，角色保持居中；大型室外扩展render_bounds但不扩展walk_bounds。静态素材和碰撞须保持一致，出生、NPC、交互与传送位置均须在行走范围内，保留旧存档坐标。新增素材保留原始PNG和来源记录，用图集帧或图层配置排布。

管理员通过 CLI 显式创建教师账号。教师登录后台，创建班级并分发加入码；学生注册后加入。教师上传文件，等待 ready 或查看 failed 原因，再创建自己的教学活动，绑定章节、NPC 和材料。共享种子不能被教师原地覆盖；新内容使用自有活动和任务。

任务使用 JSON 节点列表编辑。先校验再保存，按稳定ID关联。节点支持 TALK_TO_NPC、PLAY_DIALOGUE、REACH_LOCATION、INTERACT_OBJECT、STUDY_LESSON、COMPLETE_PRACTICE、PASS_ASSESSMENT、REPORT_BACK。dependencies 是节点 ID 列表，aggregation 默认 ALL，可用 ANY；optional 是可选目标。学习/练习节点必须绑定实际 activity_id。

分支父节点给出 choices（id、label），子节点用 condition: {node, choice} 引用直接父节点。任务完成只要求实际选择的支路；不得用任意代码或 SQL 作为条件。effects 只接受 set_world_flag。重复 ID、悬空依赖、环、错误内容、非法效果应在保存前被拒绝。

NPC 的教学身份由活动 npc_key 配置决定，不创建第二套页面或 Agent。对白是确定性脚本，不调用模型。新增 NPC/活动/任务通过配置 API 完成。世界坐标须经地图可达校验，图书馆室内边界为18×14。

教师按班级发布章节，指定 published/paused、带时区 opens_at与可选前置。界面默认 Asia/Shanghai，服务端按当前时间即时判定。暂停不删除成绩；当前策略为暂停后拒绝继续访问该章，重新开放后从已保存状态继续。教师预览不可写入学生成绩。

## 媒体与安全

文本使用 UTF-8；PDF 支持私有阅读；MP4/WebM 支持鉴权文件流与 Range；PPT/PPTX 必须经过配置的隔离 LibreOffice 转换。未安装转换环境时保留失败状态，不能伪报成功。不要将私有材料复制到 frontend/public，不要把隐藏答案写进题干、公开样例或助教可见上下文。同material_id上传替换当前文件，绑定该ID的活动读取新内容；旧文件不作为历史版本提供访问。

## 自有章节与知识点

教师后台“课程与知识点”可新增和编辑自有章节/KC；共享的原7章/65KC只有管理员可修改。新增内容仍属于Python语言基础单一课程，并非另建多课程平台。无引用的自有条目可删，有活动、任务、发布引用时返回409。

活动可多选同章的共享/自有KC。绑定直接更新活动并保留真实来源编码与页码；不能引用另一位教师的私有KC。新增题目直接加入当前活动题集，任务只引用活动ID。

任务日志按主/支线和进行中/已完成筛选。侧线不隐式阻挡主线的章节前置。教学、练习与其他工作区共享同一实现，新增绑定不复制页面。

排课界面时区由frontend的VITE_TIME_ZONE或容器构建参数REBORN_TIME_ZONE配置，默认Asia/Shanghai。所有API时间戳带明确偏移，数据库保存UTC；DST不存在或重复的本地时刻会被界面拒绝，避免静默错排。

后台操作入口（2026-11-05修订）：课程结构通过「章节 / 知识点」子标签查看，每个列表独立搜索、筛选与分页；新增、编辑、删除在弹窗中确认。材料与题库默认每页10条，上传材料/新增题目通过弹窗完成，关闭后保留未提交草稿。章节管理直接在目标章节行设置解锁日期并保存，或立即解锁；所有安排使用当前任务定义。已有前置条件会显示在章节标题下，不会静默移除。题目保存直接更新当前活动题集；排课仅控制开放状态、时间与前置条件。活动/NPC/任务编辑本轮不改。高级JSON格式错误时保留原内容并阻止创建；刷新/退出后不保证草稿保留。


## 课程包PDF与补充视频导入（2026-11-07）

专用CLI `python -m app.course_media <archive.tar.gz>` 接入用户提供的课程包43媒体，只更新当前Material和私有文件，不调用seed、不创建Activity/Quest，也不修改学生阅读、任务、提交或成绩。无需新增数据库迁移。

7份PDF原位绑定材料186..192，保留现有content.pages中的561个原页面ID、页码、标题和提取文本，类型改为pdf。当前第一章仍使用材料186及原全局页10715/10723/10724（第34/42/43页）；提取文本继续用于检索和引用，界面展示真实PDF整页，不向学生展示提取文本。普通上传会重新生成页ID，不能替代此专用导入。

导入器先完整检查路径/链接/重复成员、文件与总量、源清单、PDF页数和原页面ID、MP4文件签名及34份SHA256，再将文件写入私有存储并事务更新材料。可信清单来自后端镜像携带的仓库JSON，不能由包内清单任意替换。当前文件使用内容哈希存储键，同键对象校验一致时复用，不一致时拒绝覆盖；数据库失败回滚，未引用文件不会发布。该CLI用于管理员导入已核查课程包，不是公共的任意归档上传端点。

## 练习与一次交卷测验

`kind: practice` 使用单题练习，学生可逐题提交、改错和再次提交；完成规则仍是当前题集每题至少一次正式通过。`kind: assessment` 使用同一个已审核题集，允许单题或整卷浏览，但只能填写完整后一次“提交试卷”。单题布局与整卷布局只是同一份答案的两种显示方式，切换布局不创建新考核或清空草稿。

测验草稿按学生、班级、活动持久化，revision仅防并发草稿覆盖，不是内容版本。正式交卷在一个事务中锁定答案并建立每题判定记录，随后不可改答案、重新交卷或再运行不同代码。成绩统一满分100分，使用整数公式 `答对题数 × 100 // 总题数`，始终向下取整：三题答对一题33分、两题66分、全对100分；未完全判定时score为null，不冒充0分。正确题数/总题数保留，旧Submission不改写或重判。隐藏答案和私有用例不进入学生响应。Python题仍只通过Judge0判定，状态未知时不盲目重发。

测验的“完成”和“全部答对”分开：整份已交试卷的题目都已获得学术判定即完成，可继续剧情，即使有错题；全部答对另以passed表示。既有节点名PASS_ASSESSMENT继续使用，但其服务端证据改为已锁定且判定完毕的整卷，不再要求错题可重交到全对。基础设施故障、尚待判定或外部分发状态未知不算测验完成；试卷保持只读，不能把服务异常当成答错。

升级不会批量生成试卷或重评旧提交。当前全部题目已有正式终态记录时，按每题最新真实记录只读恢复legacy测验；学生首次查看时仅收录真实题目ID、本人答案与判定记录ID，固定只读身份，不插入新成绩或重评。收录后追加当前题目不会解锁旧卷；新的独立考核应使用新的活动ID。其他world/progress/任务证据查询不暗中收录或提交事务，已有成绩与任务记录保留。若仅完成一部分旧题，将真实已有答案预填新草稿，允许补齐后首次整卷交卷；旧记录保留。仍在判定或状态未知的旧记录需先完成对账，不能盲目交第二份。已交试卷只保存题目ID、本人答案和判定记录ID等考试证据，不保存旧题面、旧资料或内容快照。

## 剧情条件、成绩回应与任务外日常

任务仍负责“要完成什么”，演出负责“人物怎么回应”，日常演出负责“没有委托也能聊什么”。三者复用受校验的对白节点，不把每次闲聊建成支线任务，也不需要编辑器。章节任务演出继续写在 `content/chapters`；任务外日常写在 `content/ambient`，导入时原位更新当前StoryDefinition。它们不会复制一份教材或建立内容快照。

条件用于NPC入口、branch分支、日常可用性和dialogue选项的when；所有判断在服务端读取当前学生、当前班级的授权证据，不能写Python表达式。顺序路由从上到下选第一项匹配者，最后必须有always兜底。可组合的条件包括：

| 条件 | 用途 |
| --- | --- |
| `always: true` | 无条件兜底 |
| `goal_complete` / `goal_ready` / `activity_started` | 保留现有任务演出的简写 |
| `goal: {quest_id, id, status}` | 指定任务目标的ready、complete、locked或skipped状态 |
| `quest: {id, status}` | 指定任务active或complete |
| `chapter: {id, status}` | 章节available（当前已开放）或complete（权威主线完成证据） |
| `assessment_score: {activity_id, min?, max?}` | 已判完测验的百分制闭区间，min/max至少填一项；未判完不命中 |
| `all_quests_complete: true` | 至少有一个当前可见任务，且全部完成；没有任务时使用always |
| `all: [条件, ...]` / `any: [条件, ...]` / `not: 条件` | 有界条件组合，无任意代码执行 |

例如在测验完成后放一个自动分支，正文节点由该分支选择。分支本身不增加任务或修改分数：

```yaml
- id: exam-ending
  type: branch
  routes:
  - when: {assessment_score: {activity_id: ch1-assessment, min: 100}}
    node: mayor-score-excellent
  - when: {assessment_score: {activity_id: ch1-assessment, min: 60, max: 99}}
    node: mayor-score-good
  - when: {always: true}
    node: mayor-score-encourage
```

本例是节点片段，引用的三个对白节点也必须在同一演出的nodes中定义，并能走到end。第一章内置剧情保留原总结和任务检查点，再按满分、60–99分、0–59分给出不同回应；成绩不足不会让一次交卷测验无法继续。

日常演出使用 `mode: ambient`，不绑定quest；仍属于真实chapter_id，遵守班级成员、章节发布和NPC距离权限。`bindings`必须为空，不能包含学习activity节点、任务checkpoint或解锁effects。`when`决定整段日常何时可用；例如 `quest: {id: arrival, status: complete}` 可让第一堂课结束后继续闲聊。任务当前有可执行目标或等待中的活动时优先，日常不能抢走教学进度。

选项可以附加条件，符合章节状态时才出现；隐藏选项不能靠手工发送choice绕过，提交选项时服务端再次检查：

```yaml
choices:
- id: next-chapter
  label: 下一章会学些什么？
  when: {chapter: {id: 180, status: available}}
  next: next-chapter-chat
- id: goodbye
  label: 下次再聊
  next: end
```

保留无条件离开选项，避免所有条件都不满足时无法退出。`random`节点用 `next: [对白节点ID, ...]` 配置候选，对每次新互动由服务端选取；所选对白位置保存在原StorySession，刷新、恢复或幂等重试不重新抽取。开始新的闲聊才会重新选择。随机节点依然遵守有界无环图，不能执行活动、写成绩或冒充AI对话。日常只保存对白会话，不写学习事件、任务目标、世界解锁标记或助教调用。
