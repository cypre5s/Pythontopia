# 无尽远征与 Learner Twin 调研、现状和设计

日期：2026-10-12
范围：Web / Java 后端 / Python Graph；本记录不包含 Android、Electron 或微信端。

## 当前实现核对

### 无尽远征

- 地图为 9 个常规层加 1 个 Boss 层，是可重复游玩的有限单局，不是无限生成的连续挑战。地图是分支 DAG；每日挑战按日期种子固定。
- KC 来自 pack 43 的 `kc_map`。选题已有画像弱项、最近发展区、掌握度、近期重复压制和后端真实练习时间间隔；难度结合掌握度、置信度和练习成功率。画像字段由服务端覆盖，前端传入的弱项/成功率不能覆盖服务端值。
- 题目路径已有限长预生成队列、同用户/同维度并发去重、READY 题复用、教师审核题库与 golden fallback。可进入挑战时走后端正式判题；Graph/LLM 不可用时能用兜底题继续。固定题型池限制为现有服务端可判题题型。
- 本轮使知识前沿选择同时接收 `kc_mastery.confidence`。置信度低时获得最多 8 分的有限探索加权，并解释为“证据待确认”；它不会覆盖弱项、最近发展区和间隔复习权重。该值是本项目按事件增减的启发式置信度，不是经过校准的概率。
- 单局最多记 12 个正式判题题目，与最多 9 个普通挑战层加 3 个 Boss 阶段的上限相符。分数、成功题数和连胜来自服务端判题 ledger；当前排行榜 `cleared` 从服务端 `over` run 与 Boss 节点状态推导。
- 新建 run 的地图、节点动作、HP、气势、遗物、事件选择和 Boss 阶段由服务端校验并持久化，前端快照不能覆写；结束结算原子化且同一 run 不能重复累计成绩。V204 前建立的活动局保留历史可变字段，但其来源不可追溯；不将旧快照声称为可信学习证据。
- `focusChapter=null` 的全局/每日 run 表示选题不限章节；服务端接受课程范围内任意章节，固定章节 run 仍拒绝换章。排行榜将 `verifiedDepth` 表示为正式判题通过题数，而不是地图深度。

### Learner Twin

- 当前是按用户隔离的只读周报，不是实时预测型数字孪生：它汇总最近 7 天权威学习事件、反思洞察、掌握度变化和资源运行记录，不调用 LLM。
- 本轮 Twin 的 KC 变化条目同时展示掌握度、周变化、证据数、来源和平台置信度。学生可把这些事实带入下一轮工坊提示。
- 权威练习结果由服务端事件驱动；来自客户端的通用事件不能冒充判题通过/失败。该模型不声称已覆盖八维画像的实时预测、长期行为序列建模或跨模块“模拟未来”。

## 调研结论与适用性

1. **BKT 与可解释性**：经典 BKT 为知识组件维护潜在掌握状态，并用练习观测更新状态，解释路径直接。现有系统已有按 KC 的服务端掌握值和正式练习事件，因此适合继续作为可解释的基础，而不是再加一个并行状态库。[Corbett 与 Anderson 的知识追踪研究](https://link.springer.com/article/10.1007/BF01099821)
2. **DKT / AKT 的数据门槛**：DKT 通过序列模型学习潜在知识状态；AKT进一步显式利用题目、知识点、答题结果、相似度和时间间隔，并报告其在公开数据集上的下一题表现。它们都需要足量、稳定标注的长序列和离线预测评估。当前远征中一部分题目是动态生成，历史题目标签与同题重复样本有限，现阶段引入深度模型会很难证明比现有规则更准。[DKT](https://papers.nips.cc/paper/5654-deep-knowledge-tracing.pdf)、[AKT](https://arxiv.org/abs/2007.12324)
3. **间隔练习**：关于分布式练习的元分析显示最佳练习间隔与期望保留周期共同变化；DAS3H 也指出需要同时看题目关联的技能和跨时间练习历史。当前采用正式练习时间及固定的 3/14/45 天分段，只是一个低成本近似；这些阈值不是论文验证出的最优值，应通过本项目长期留存结果再调参。[Cepeda 等人的元分析](https://pubmed.ncbi.nlm.nih.gov/16719566/)、[DAS3H](https://arxiv.org/abs/1905.06873)
4. **游戏化**：学习游戏化元分析报告认知、动机和行为指标总体有正向小效应，同时指出结果存在异质性和设计因素不确定性。它支持把分支选择、反馈和成长用于提高有效练习参与度，不能证明“加遗物/排行榜”本身会提升学习结果。[Sailer 与 Homner 的元分析](https://link.springer.com/article/10.1007/s10648-019-09498-w)
5. **Roguelike 结构借鉴**：Slay the Spire 官方商店描述确认其路线有风险/安全取舍，并让遭遇、事件和 Boss 随局变化。本项目只借用路线可读性和有限分支选择的通用结构，题目、人物、地图与素材仍由项目自有系统生成，不复制其专有内容。[官方商店页面](https://store.steampowered.com/app/646570/Slay?l=english)

### 2026-10-16 文献复核

- APS 的学习技术综述将练习测试与分布式练习评为高效用策略；因此本项目优先保证正式判题、复习到期和失败后的再练链路，不把“游戏化”直接等同于学习效果。[APS 综述](https://www.psychologicalscience.org/journals/pspi/1529100612453266/)
- 2026 年工程教育数字孪生系统综述指出多数研究仍属案例或探索性，经过验证的学习结果测量较少；因此 Twin 展示证据与不确定性，成效主张必须等待本项目的对照与延迟复测。[Frontiers 系统综述](https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2026.1955212/abstract)
- pyBKT 是可复用的 BKT 与扩展实现，适合有足够、稳定的练习序列后作离线基线；首期继续使用服务端已有 KC 状态和正式事件，不部署第二套在线状态。[pyBKT 项目](https://github.com/CAHLR/pyBKT)
- FSRS 将记忆状态表示为 Difficulty、Stability、Retrievability；本项目保留现有 ReviewStateService/FSRS-lite，不把三项名称当作可以直接估算的已校准概率，也不重写调度器。[FSRS 算法说明](https://github.com/open-spaced-repetition/fsrs4anki/wiki/The-Algorithm)
- Slay the Spire 的 GDC 设计与平衡演讲可参考其数据化迭代思路，但它不是教育成效证据；本项目只借鉴记录路线、事件、失败与选择结果后再平衡。[GDC 2019 演讲资料](https://media.gdcvault.com/gdc2019/presentations/Giovannetti_Anthony_SlayTheSpire.pdf)

## 设计选择

- 继续用可解释的规则排序，不新建第二套知识追踪数据库，也不把启发式置信度包装成概率。
- 优先薄弱知识点和最近发展区；对低证据点只加有限探索分，保留当局已用 KC 排除及最近练习惩罚；久未练习依据后端正式事件时间上浮。
- 现有掌握值可驱动难度，单次变化限在 1 档附近，避免仅因低置信度让题目突然升难。动态题目必须继续通过 schema、KC/章节、判题能力、grounding 和自测检查，无法生成时走经审核或 golden 题。
- Twin 继续以来源、证据数量和置信度解释观测值。未来只有在有足量、可复现的学习结果和校准评估后，才考虑基于长序列的预测模型。
- 将“无尽”定义为可重复开局，不宣称单局层数无限。要升级成长线模式，先需要可验证的服务器端节点/阶段记录及可观测完成率，不能从客户端快照推导排行榜通关。

## 服务端权威状态闭环（实施顺序与现状）

旧客户端快照不能因迁入服务端就自动成为可信事实。当前 Web 垂直切片已切换为有类型的服务端动作；每次动作在锁住 run 行后验证状态与合法目标并返回数据库中的 canonical snapshot：

1. `POST /api/world/expedition/run` 由后端读取学习前沿并生成 10 层地图；Web 客户端只收取快照。`PUT` 仅校验兼容旧客户端的身份/拓扑并返回服务端数据，不保存客户端 phase、节点状态、HP、气势、遗物或历史。
2. 节点进入、事件选项、宝箱/精英奖励、主动结束通过 `/api/world/expedition/run/actions` 执行。后端验证当前阶段、可达边、节点类别和合法选项，再持久化权威状态。
3. Boss 题目签发和预生成记录绑定 `runId + nodeId`。正式判题结算核对题目绑定与本人 verified ledger，再推进节点、HP、气势和 Boss 阶段；客户端不提交判题结果或资源增量。
4. 完成状态与排行榜分数/深度来自服务端动作和正式判题账本。V205 将每日挑战领取记录持久化为学生/上海日期唯一键，Web 本地日期只用于即时显示；排行榜记录从服务端 run 读取 daily 标记。

V204 不会把既有活动局的可变字段重置为新开局。迁移前的地图拓扑由此前服务端开局签发，但节点状态、HP、气势、遗物和历史曾可被旧 Web PUT 覆写；旧活动局这些字段的来源可信度无法追溯。迁移保留 run 和正式判题账本，用户应将新建局视为完整服务端权威路径。

## 本轮代码与验证

- Web 开局已改为接收服务端生成的地图、前沿、挑战配置和初始状态；后端创建请求只含章节聚焦与每日标记。服务端地图 DAG 与现有 Web node schema 兼容，后续快照不可改写地图节点数、连边、KC、题型、难度或每日标记，并由前后端定向测试覆盖。
- Web 的 `POST /run/actions` 现在承接节点进入、事件选择、领奖、判题结算和主动结束；兼容 `PUT` 只验证并返回服务端快照。Boss 题目与预生成题绑定 `runId + nodeId`，正式结算只读取本人已签发题目和 verified attempt；结算重复请求幂等。
- 续局时中断的挑战/事件回到地图并可重新进入当前节点；领奖阶段恢复三选一；判题结算超时可用同一题目重试。节点进度、HP、气势、遗物和历史不再从 Web 快照写入服务端。
- 远征 run ID 由服务端签发；客户端分数不再作为事实，排行榜分数与深度由正式判题记录计算，结算后锁定该局。
- Web 继续把局内游戏分和排行榜核验分分开：本地游戏分保留难度、气势、节点类型、事件、遗物和答题时长加成，仅作体验展示；排行榜只采用服务端正式判题账本中的分数。
- 选择器的输入现在含服务端 `mastery_score` 与 `confidence`。新增 Graph 纯函数排序回归与 Java 传参回归。
- 验证：后端定向 Maven 6 类 / 85 tests 通过，Testcontainers 空库迁移到 V204；前端全量 Vitest 254 files / 2500 tests、`npm run typecheck`、`npm run build` 和本次改动文件 ESLint 通过。全仓 `mvn spotless:check` 仍被其他 Java 文件的格式违规阻断，本次新增/修改的远征 Java 文件未出现在违规列表。
- 其他本轮安全/质量变更和对应回归记录见 [DeepSeek 导学安全与数据边界工作日志](./2026-10-12-deepseek-ai-tutor-security-worklog.md)。
- 代码检查和 targeted tests 不等同于基准测试。无尽远征 P50/P95、缓存命中率、题目重复率、失败恢复率和完成率仍待本地 Web 全栈与真实流程测量；本文件没有填估算值。

- Web 全栈主线导航与指南交互 3 项 Playwright 通过；DeepSeek 导师文本和图片输入、文本输出真实链路 2 次请求通过。

- 已修复同一远征题目重放引起的重复练习事件：首次失败与首次通过可各发布一次，已通过后的新 `attemptId` 不再重复发布；判定在 run 行锁内串行化。另以 KC、题面、样例和判题用例的 SHA-256 指纹合并同一局内不同 ID 的同题判分，保留原题 ID 供账本与实际签发记录关联。
- V202 前写入的活动局账本不做破坏性重算，旧记录的指纹为 NULL，仍只按原 `problemId` 去重；若这类旧局内同题被重新签发且旧题从未重判，仍可能多计一次。新开局和新写入记录使用指纹去重。
- Lecture 页的“已学习”只是本页视频进度或打开讲义后的会话状态，不是服务端媒体消费事件，不能作为 Twin 画像证据。
- 浏览器的页面文本传回 Python 侧已限制在预算内，但底层浏览器仍可能为大型 DOM 和资源消耗内存；实际压测尚未执行。

### 2026-10-13 功能优先复核

- Twin 前端把事件计数启发式从“置信度”改为“证据充分度”，鼠标提示与工坊提示都明确说明它不是答题正确概率；API 字段保留为 `confidence` 以避免跨端合同变更。
- Admin 用户列表采用已审核页的表头/行高、列宽和窄屏滚动密度，长账号名保留 title 全文；`/admin/users` ADMIN-only 路由加入回归覆盖。
- 画像尺度按 schema 修正：认知倾向使用 `-1..1` 正负值，场依存度从 `0..1` 映射到 `/10`。远征命题读取有足够证据的专业背景、目标类型/目标知识点、认知偏好与每日时长；目标加权只针对 pack 43 中尚未掌握的 KC，其他自评只作为表达/场景提示。
- 这些新提示是显式冷启动启发式，不是校准模型：目标 KC 加 28 分（低于最近发展区的 50 分），认知风格按 `0.35/0.65` 与 `-0.35/+0.35` 分段，短于等于 20 分钟时要求短题；未用学习结果数据声称预测准确率。
- Graph/Java 题型入口现在只接受现有 9 种题型，防止任意 `preferredKind` 文本被直接拼进 DeepSeek 命题提示。AI 场景提示收敛到图书馆、工坊、课堂和公告板，去掉与 R-14 不符的农场/作物例子。
- 地图生成保证 Boss 前至少出现一个可达精英节点。V205 使用上海自然日对每日挑战做服务端唯一领取，弃局不释放当日名额；结算成绩保留服务端 `is_daily` 标记，Web 在冲突响应后同步本地状态。
- 回归：Testcontainers 远征与计分 29 项、地图生成 2 项、远征服务单测 9 项通过；空库迁移到 V205。BossService 增加同题跨阶段与旧阶段题拒绝回归，相关后端五类测试合计 79 项通过。Web 远征 store 45 项、typecheck 与定向 ESLint 通过；Graph 评测/自测 31 项和 Ruff 通过。精英节点性质测试覆盖 256 个地图种子。
- Web 远征开局、节点动作、事件、遗物奖励、主动结束、题目节点绑定和判题结算已迁至服务端；`PUT` 退为只校验并返回 canonical snapshot。迁移前活动局的可变状态不做破坏性重置，可信度未知；Android/Windows 未改。
- 用户要求先完成功能、最后再测性能；本轮未启动 Web 全栈、未发 DeepSeek 请求。无尽远征 P50/P95、缓存命中、重复率、失败恢复率和通关率仍待本地全栈及可用 Piston 实际测量。
