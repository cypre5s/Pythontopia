# 无尽远征与 Learner Twin 调研、现状和设计

日期：2026-10-12
范围：Web / Java 后端 / Python Graph；本记录不包含 Android、Electron 或微信端。

## 当前实现核对

### 无尽远征

- 地图为 9 个常规层加 1 个 Boss 层，是可重复游玩的有限单局，不是无限生成的连续挑战。地图是分支 DAG；每日挑战按日期种子固定。
- KC 来自 pack 43 的 `kc_map`。选题已有画像弱项、最近发展区、掌握度、近期重复压制和后端真实练习时间间隔；难度结合掌握度、置信度和练习成功率。画像字段由服务端覆盖，前端传入的弱项/成功率不能覆盖服务端值。
- 题目路径已有限长预生成队列、同用户/同维度并发去重、READY 题复用、教师审核题库与 golden fallback。可进入挑战时走后端正式判题；Graph/LLM 不可用时能用兜底题继续。固定题型池限制为现有服务端可判题题型。
- 本轮使知识前沿选择同时接收 `kc_mastery.confidence`。置信度低时获得最多 8 分的有限探索加权，并解释为“证据待确认”；它不会覆盖弱项、最近发展区和间隔复习权重。该值是本项目按事件增减的启发式置信度，不是经过校准的概率。
- 单局最多记 12 个正式判题题目，与当前最多 9 个普通挑战层加 3 个 Boss 阶段的设计上限相符。结算分数、成功题数和连胜由服务端判题 ledger 汇总；`cleared` 暂时始终按 false 写入排行榜，服务端没有可信的地图移动/最终 Boss 击败证据。
- 后端签发 run ID，运行 ID 变化会被拒绝；结束时原子结算，旧局不能再次拿来累计成绩。存档中的地图节点、HP、遗物、事件历史仍是客户端快照，服务端不据此发放学习进度或排行榜通关奖励。它们目前影响 UI 和本地玩法；不能把这些字段称为服务器权威状态。
- `focusChapter=null` 的全局/每日 run 表示选题不限章节；服务端接受课程范围内任意章节，固定章节 run 仍拒绝换章。排行榜将 `verifiedDepth` 表示为正式判题通过题数，而不是地图深度。

### Learner Twin

- 当前是按用户隔离的只读周报，不是实时预测型数字孪生：它汇总最近 7 天权威学习事件、反思洞察、掌握度变化和资源运行记录，不调用 LLM。
- 本轮 Twin 的 KC 变化条目同时展示掌握度、周变化、证据数、来源和平台置信度。学生可把这些事实带入下一轮工坊提示。
- 权威练习结果由服务端事件驱动；来自客户端的通用事件不能冒充判题通过/失败。该模型不声称已覆盖八维画像的实时预测、长期行为序列建模或跨模块“模拟未来”。

## 调研结论与适用性

1. **BKT 与可解释性**：经典 BKT 为知识组件维护潜在掌握状态，并用练习观测更新状态，解释路径直接。现有系统已有按 KC 的服务端掌握值和正式练习事件，因此适合继续作为可解释的基础，而不是再加一个并行状态库。[Corbett 与 Anderson 的知识追踪研究](https://link.springer.com/article/10.1007/BF01099821)
2. **DKT / AKT 的数据门槛**：DKT 通过序列模型学习潜在知识状态；AKT进一步显式利用题目、知识点、答题结果、相似度和时间间隔，并报告其在公开数据集上的下一题表现。它们都需要足量、稳定标注的长序列和离线预测评估。当前远征中一部分题目是动态生成，历史题目标签与同题重复样本有限，现阶段引入深度模型会很难证明比现有规则更准。[DKT](https://papers.nips.cc/paper/5654-deep-knowledge-tracing.pdf)、[AKT](https://arxiv.org/abs/2007.12324)
3. **间隔练习**：关于分布式练习的元分析显示最佳练习间隔与期望保留周期共同变化；DAS3H 也指出需要同时看题目关联的技能和跨时间练习历史。当前采用正式练习时间及固定的 3/14/45 天分段，只是一个低成本近似；这些阈值不是论文验证出的最优值，应通过本项目长期留存结果再调参。[Cepeda 等人的元分析](https://pubmed.ncbi.nlm.nih.gov/16719566/)、[DAS3H](https://arxiv.org/abs/1905.06873)
4. **游戏化**：学习游戏化元分析报告认知、动机和行为指标总体有正向小效应，同时指出结果存在异质性和设计因素不确定性。它支持把分支选择、反馈和成长用于提高有效练习参与度，不能证明“加遗物/排行榜”本身会提升学习结果。[Sailer 与 Homner 的元分析](https://link.springer.com/article/10.1007/s10648-019-09498-w)
5. **Roguelike 结构借鉴**：Slay the Spire 官方商店描述确认其路线有风险/安全取舍，并让遭遇、事件和 Boss 随局变化。本项目只借用路线可读性和有限分支选择的通用结构，题目、人物、地图与素材仍由项目自有系统生成，不复制其专有内容。[官方商店页面](https://store.steampowered.com/app/646570/Slay?l=english)

## 设计选择

- 继续用可解释的规则排序，不新建第二套知识追踪数据库，也不把启发式置信度包装成概率。
- 优先薄弱知识点和最近发展区；对低证据点只加有限探索分，保留当局已用 KC 排除及最近练习惩罚；久未练习依据后端正式事件时间上浮。
- 现有掌握值可驱动难度，单次变化限在 1 档附近，避免仅因低置信度让题目突然升难。动态题目必须继续通过 schema、KC/章节、判题能力、grounding 和自测检查，无法生成时走经审核或 golden 题。
- Twin 继续以来源、证据数量和置信度解释观测值。未来只有在有足量、可复现的学习结果和校准评估后，才考虑基于长序列的预测模型。
- 将“无尽”定义为可重复开局，不宣称单局层数无限。要升级成长线模式，先需要可验证的服务器端节点/阶段记录及可观测完成率，不能从客户端快照推导排行榜通关。

## 本轮代码与验证

- 远征 run ID 由服务端签发；换 ID 的快照被拒绝。客户端分数不再保存为事实，成绩与深度由正式判题记录计算，结算后锁定该局。
- 选择器的输入现在含服务端 `mastery_score` 与 `confidence`。新增 Graph 纯函数排序回归与 Java 传参回归。
- 其他本轮安全/质量变更和对应回归记录见 [DeepSeek 导学安全与数据边界工作日志](./2026-10-12-deepseek-ai-tutor-security-worklog.md)。
- 代码检查和 targeted tests 不等同于基准测试。无尽远征 P50/P95、缓存命中率、题目重复率、失败恢复率和完成率仍待本地 Web 全栈与真实流程测量；本文件没有填估算值。

## 尚未解决

- 地图节点、移动顺序、HP、遗物和成功通关尚未由服务端状态机签发/验证。当前可信边界是判题 ledger、分数和受限判题次数，不是客户端 Roguelike 快照；排行榜也不授予 `cleared`。
- 当前画像规则没有把八维全部转成选题特征。当前真正参与 KC/难度或题目偏好的字段主要为易错 KC、自评基础、正式成功率、媒介偏好、韧性和偏好题型。缺少稳定历史数据的维度不应被算法伪装成已生效。
- 重放同一远征题目仍可能再次发布练习事件，导致 mastery / Twin 证据重复累计；账本按题目 ID 聚合分数，但尚无稳定 submission ID 与事件幂等约束。
- Lecture 页的“已学习”只是本页视频进度或打开讲义后的会话状态，不是服务端媒体消费事件，不能作为 Twin 画像证据。
- 浏览器的页面文本传回 Python 侧已限制在预算内，但底层浏览器仍可能为大型 DOM 和资源消耗内存；实际压测尚未执行。
