# DeepSeek 文字与图片问答设计

## 目标

让导师面板和工坊聊天都能提交文字与图片，由 DeepSeek 直接读取图像并以文字回答。

## 现状与方案

导师面板已有图片输入，工坊输入框目前只处理代码和文档。后端导师接口已有 `images` 字段，但 Java 中继先将图片交给讯飞识别，再把描述交给 DeepSeek。改为复用现有 `TutorAskRequest.images`：Java 将图片转发给 Graph，Graph 将图片内容块放入最终 TutorAgent 的用户消息，图像请求使用单独配置的视觉模型 `deepseek-flash`，不改变 NPC 快档。工坊仅为图片新增本地 Data URL 读取，现有文档上传和解析不变。

## 保持的边界

- 复用现有 `/api/tutor/ask`、RAG、流式输出、grounding 与 safety 审查。
- 仅将图片附加到 TutorAgent 的最终回答请求；图片请求不走无法消费图像的 debate 分支。
- 限制为最多 3 张 JPEG、PNG、GIF 或 WebP 图片，每张不超过 5 MiB；仅接受经过校验的 base64 图片，不接受远程 URL。
- 图片仅用于当轮请求，不新增图片存储或聊天历史持久化。
- DeepSeek 凭证留在被忽略的 `deploy/.env`；示例与操作文档只记录变量名和模型设置。

## 验收

- 导师面板的现有图片输入可由 DeepSeek 直接读取，答复仍为文字流。
- 工坊可将文字/文档/图片组合提交；图片进入导师问答，文档仍走现有文本解析。
- 仅当前回合图片输入改变模型选择；纯文本模型与已有安全审查继续工作。
