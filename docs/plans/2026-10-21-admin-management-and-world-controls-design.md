# 管理后台与 World 输入修复设计

## 目标

补齐管理员可用的账号学情、课程资源、AI 出题、资源消耗和班级管理入口；修复 World 中玩家角色无法正常响应 WASD、并补上点击地面移动。按用户要求先在本地实现并验证，再部署 ECS，最后推送 GitHub。

## 方案

沿用现有 Spring Boot 管理 API、课程包/判题/班级数据及 Vue 管理后台，新增最少的受 ADMIN 保护的查询与写入接口和页面；不复制出新的管理数据模型。学生学情复用现有画像、掌握度、提交和判题结果；班级总览复用现有看板查询。AI 出题沿用 `BossProblemReview` 生成与审核队列。课程包 43 的内置源数据和 7 文档、561 页、7 章、65 知识点、46 示例、39 题的初始化约束保持不变，管理页用可用状态覆盖控制资源是否呈现，不直接改写或删除源文件。

管理员页面覆盖：

- 账号：沿用搜索、状态筛选、启停；点击学生查看八维画像、按中文名显示的知识点掌握度、学习活动、提交/判题记录和班级。
- 课程资源：目录、搜索、预览、资源状态与索引健康；不提供删除内置种子文件。
- AI 出题：管理员生成候选题，查看待审/已通过/已驳回记录，审批并留下理由；学习者的正式提交仍走现有服务端 Judge。
- 消耗历史：聚合现存的模型运行 token、资源生成、媒体任务与正式判题记录，并按用户/日期/服务筛选。缺失历史数据不回填、不估算货币费用；之后的调用记录实际可得用量。
- 班级：浏览全部班级，查看教师、成员、任务与学习汇总；管理员可维护班级名称/说明和成员，不提供物理删除班级。
- AI 配置：仅支持现行生产契约允许的 DeepSeek 模型端点；密钥加密存储、脱敏读取、支持连通性检查及运行时应用。RAG 继续使用本地 hash embedder。部署环境提供独立加密主密钥。
- KC 编号：内部/API 主键保留；Web 用户可见文字统一显示课程知识点名称，未知编号也不原样回显。

## World 输入

先通过本地全栈浏览器确认 WASD 的失效条件，再针对共享输入/WorldScene 根因修复。点击地图地面时，把屏幕位置换算成世界 tile，并沿可通行格逐格移动；复用现有移动、碰撞、动画和存档写回逻辑，目标被地形或 NPC 阻挡时不得穿越。键盘输入优先于点击路径；用户再次点击时替换目的地。场景关闭时清除输入/点击监听和路径状态。

## 安全与兼容

新增管理员端点在后端显式要求 ADMIN，不依赖前端隐藏路由。学生隐私数据仅向管理员返回。密钥从不回显明文；模型连接测试会产生一次上游请求。迁移只新增配置/用量及课程资源状态所需表，不清理用户、课程、班级或数据库卷。正式 Judge 行为与请求契约保持不变。

## 验收

- 后端权限、字段校验、SQL 汇总及迁移测试覆盖管理员/非管理员、空数据和分页/筛选。
- 前端各管理页通过 API 真实数据展示与状态错误测试；用户界面不渲染 KC 编号。
- 本地浏览器验证 World 的 WASD 连续移动、点击可达 tile、阻挡 tile、再次点击改道、切页后不残留输入，并检查 console、pageerror 和失败请求。
- 本地完整构建/相关测试与课程种子校验通过后制作离线发布包；ECS 先备份并保留 PostgreSQL 卷，安装后核验服务健康、管理 API 权限及玩家输入。GitHub 推送安排在 ECS 验收之后。

## 取舍

以当前数据为事实来源，避免新增平行课程/用户/班级模型。历史中不存在的 token/费用以及不可追溯的内容不会伪造。World 点击移动不引入新游戏依赖，复用当前 tile map 和移动手感。
