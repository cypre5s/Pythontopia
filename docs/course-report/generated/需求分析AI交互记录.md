# Pythontopia 需求阶段人机协作交互记录

> 本记录整理自 Pythontopia **需求探索与构建排障阶段**的人机协作对话，聚焦真正塑造产品定位、需求边界与工程落地的关键轮次（节选 25 轮）。
> 记录中的每一条技术结论均已最终落到代码、《需求分析说明书》（`docs/需求分析说明书.md`）或构建验证实践，并以仓库现状为准——本记录展示的是“我们如何想清楚、如何排障”，而非“AI 替我们想”。
> 为便于复盘，AI 回应仅保留结论要点；本记录不是逐字聊天日志，而是面向答辩展示的协作方法整理。文末附“提示词方法论复盘”与“思考深度复盘”两节，显式拆解本轮协作中使用的提示策略与贯穿主线。

## 协作设定

| 项 | 内容 |
| --- | --- |
| 我的角色 | 产品负责人 + 架构与教研把关人（最终决策与质量责任在人） |
| AI 角色 | 按轮次指派：资深教育产品顾问 / 内容审稿人 / 架构师 / 比赛评审红队 |
| 协作原则 | 先证伪后立论；AI 不得顺着说；所有结论须可落库、可验证、可追踪 |
| 输出要求 | 结构化（表 / 编号 / 状态机）、给依据不替我做决定、明确“不做什么” |

## 交互记录（节选 25 轮）

### 轮次 1 ｜ 立项前提的自我证伪

> **我**：你现在是我的资深“教育产品 + 教研”双背景顾问。在我给你任何方案之前，先做一件事——用**最严苛**的视角质疑我的立项前提，不要顺着我说。
>
> 一线事实（随堂观察，非主观臆断）：高校 Python 公共课，逃课率高；留在教室的也有相当一部分“人到心没到”——点名一过就刷手机、赶别科作业，整节课没运行过一行代码。大班统一进度 + 单向灌输 + 零即时反馈，让零基础学生快速掉队，并陷入“这节没跟上 → 下节听不懂 → 畏难 → 干脆翘课”的恶性循环。
>
> 我的初步判断：**市场不缺网课，缺的是补位第一课堂的“第二课堂”**。
>
> 请按两步走：(1) **先攻击**这个判断——录播 / MOOC 为什么治不了？如果治不了，是“产品没做好”还是“品类天然不行”？(2) 若你最终也认同“第二课堂”，请给出它与“又一门网课”的**本质区别**，并收敛成一句能写进立项书的话。

**AI（节选）**：先证伪——MOOC / 录播本质解决的是“内容供给”，但掉队学生的真正缺口是“不想看、看不懂、坚持不下去”三个**动机与反馈缺口**；再多一门高质量网课也不补这三个缺口，所以这是**品类缺口**而非单品缺陷，你的判断成立。本质区别一句话：**第二课堂不取代教师线下授课，而是补位——让掉队学生按自己的节奏，在课外重走“看 → 学 → 练 → 测”的完整闭环。** → 后落为《需求》序言与 §1.3。

### 轮次 2 ｜ 定位一句话化 + 第一性原则锁定

> **我**：很好，接受。现在把定位**压缩**：用一句话定义产品（要能进封面），同时显式写出**边界**——它不做什么（首先就是“不取代第一课堂”）。
>
> 另外锁一条不可让渡的第一性原则：**教育优先，游戏承载**。请你据此**反向**列出：哪些常见的游戏化设计一旦引入，就会违背这条原则？我要的是“预防性约束”，省得后面被花哨玩法带偏。

**AI（节选）**：一句话——“面向高校 Python 初学者的多端像素学习小镇，补位第一课堂的第二课堂”。反向约束（违背“教育优先”的典型陷阱）：纯装饰性背包 / 货币 / 商店、与学习无关的好感度 / 送礼、靠体力值制造的人为门槛、为留存而留存的日常签到。→ 这条原则后来成为 §4.10 教育有效性 NFR 与 R-14 砍系统的唯一标尺。

### 轮次 3 ｜ 个性化：禁止伪个性化（强前提约束）

> **我**：个性化是这个产品的命门。我先下一个**强约束**：禁止“一次性问卷 → 静态推荐”这种**伪个性化**。
>
> 请在“画像必须可持续演化”这个前提下，设计画像的维度集合：要求覆盖**认知 / 情绪 / 行为**多个层面、不少于 8 维；并明确区分——哪些维度**只能被动**从学习行为推断，哪些**可以让学生自评**。给我一个**能落库**的结构（字段 + 取值域 + 置信度机制），不要营销话术。

**AI（节选）**：8 维 = 专业背景 / 知识基础 / 学习目标 / 认知风格 / 学习偏好 / 易错模式 / 实践能力 / 情绪与坚持度，统一聚合进 `learner_profile.dimensions` JSONB。客观维度（实践能力 / 易错模式等）由练习 / 判题 / 调试**被动**推导（`PassiveProfileService` 监听 `LearningEvent`），4 个主观维度可自评；置信度 `confidence = min(1, evidenceCount/8)`，`<0.3` 视为信号不足、不强断言；来源 ≥6 类。→ 后落为 §3.4。

### 轮次 4 ｜ 可信红线：宁可不答，不许编

> **我**：切换角色——你现在是一个**对教育内容质量零容忍**的审稿人。
>
> 强约束：面向初学者的 AI 内容，只要出现**编造的课件页码 / 章节 / 题目**，就等于教学事故。请设计一套“**宁可不答，也不许编**”的机制，并明确**失败时的行为**：是 fail-fast 直接报错，还是降级成普通聊天？给我**可验证的判据**（我要能写成测试用例）。

**AI（节选）**：① 检索增强 + 证据锚定：答案 / 资源必须带 `evidence_page_ids`；② 命中低于阈值或触发敏感词 → 统一 `no_evidence_found=true, hits=[]`，**诚实告知未找到**或显式标注“基于通识知识”，绝不编造引用；③ 末端 `GroundingCritic + Safety` 三审，**数字 / KC 未出现在证据中即节点 fail-fast**；④ Agent 故障 fail-fast，**不静默降级成普通聊天，不启用 ReAct**。可验证判据：查“for循环”必回非空证据页且可回链；训练场语境索要完整答案被护栏拒绝。→ 后落为 §3.8 / §4.3。

### 轮次 5 ｜ 真实练习：把“矛盾需求”逼成双轨

> **我**：我提一个**看似矛盾**的需求，别急着二选一：我**既**要前端秒级即时反馈，**又**要判题结果绝对可信、可统计、可进班级分析。
>
> 请设计能同时满足的方案。并回答两个**边界问题**（我要明确的“禁止项”）：(1) 前端即时预览的结果，能不能写进正式统计？(2) 隐藏测试用例，能不能下发到前端？

**AI（节选）**：双轨执行——Pyodide 浏览器内 WebAssembly 做**即时预览（非正式）**，服务端 subprocess 沙箱跑**隐藏用例做正式判题**。禁止项：① Pyodide 预览结果**绝不**写正式判题表；② 隐藏用例**绝不**下发前端（公开题视图 `/public` 去用例）。`verdict ∈ {AC,WA,RE,TLE,CE,MLE,SYSTEM_ERROR}`，正式提交联动掌握度。→ 后落为 §3.10。

### 轮次 6 ｜ 范围断舍离：以教育目标为唯一标尺

> **我**：坦白一个历史包袱：我们之前把它做成了星露谷式“5 图大世界”（农场 / 作物 / 播种浇水 / 货币 / 商店）。我现在判断这偏离了教育主线。
>
> 请你以**“每个系统是否服务教育目标”为唯一标尺**，对现有玩法做一次断舍离：列出建议**砍掉的**、建议**保留的**，并评估砍掉之后的**迁移与演示风险**。给我决策依据——**不要替我做决定**。

**AI（节选）**：建议砍（无教育落点）——农场 / 作物 / 播种浇水、货币 / 经济、商店 / 购买、体力、NPC 好感 / 送礼；建议留（有教育或叙事承载）——技能 / 对话 / 日历 / 存档、Bug 矿洞（错题支线）。收敛为**单一中央小镇 `town_hub`**。风险：① 旧 `mainQuest` 前端存档作废 → 演示断档（用 seed 一键灌新进度兜底）；② 残留表（inventory/currency/shop）建议**仅产品层退役、不立即 DROP**，端点退役即可。→ 后落为 §2.3.4 CON-OUT 与 R-14 决策。

### 轮次 7 ｜ 章末大测试：解一个“三难”

> **我**：章末测试我要同时满足**三个互相打架**的目标：(1) **个性化**（按画像 AI 出题）；(2) 考试期间**绝不卡顿**（不能让学生等 LLM）；(3) 题目**可信**（不能出烂题 / 不能泄答）。
>
> 请设计一个能同时满足三者的机制，并把**极端情况**讲清楚：生成失败怎么办？多人同时触发预生成怎么办？

**AI（节选）**：**画像驱动 AI 预生成入库 + 考试期零 LLM 调用**——把“贵且慢”的生成与“快且稳”的考试**解耦**。流程 `paper_designer → grounding_critic(证据校验) → sandbox_self_test(编程题跑参考解) → safety_critic` 入库；状态机 `PENDING→GENERATING→READY/FAILED`。极端情况：生成失败重试 ≤2 → 仍失败用每章**人工 golden 兜底题组**；并发预生成走 `@Async` + **信号量并发 ≤2** 队列削峰。防作弊（尽力而为且明示限度）：禁粘贴计数 / 失焦记录 / 路由守卫 / 服务端时限硬校验。→ 后落为 §3.6.3 / §4.1。

### 轮次 8 ｜ 星级体系：用不变量约束 + 正向激励

> **我**：设计一个章节星级。我先给**不变量**（不许违反）：必须**幂等、只升不降、单一权威、可审计**。
>
> 体验上有个原则：**补救要做成正向激励，不要做成惩罚**——掉队学生通过额外努力能把星补回来。请给出星级公式与**补星途径**，并说明补星如何防刷。

**AI（节选）**：0–3★，`chapter_star` **唯一权威**，所有变更走 `star_award_event` 审计，`ChapterStarService.recalc` 统一收口、**幂等、只升不降**。1★ = 章测最高分 ≥60；2★ = 1★ 且全 Stage 三件套过线；3★ = 2★ 且（章 KC 均掌握 ≥0.80 且测试 ≥85）。补星（正向）：错题复盘 `RESOLVED ≥3` +1、无尽单轮答对 ≥8 且正确率 ≥80% +1；防刷：每章每途径至多 +1、封顶 3★、每日每章至多记 1 次。→ 后落为 §3.6.4。

### 轮次 9 ｜ 遗忘：拒绝拍脑袋，要科学模型

> **我**：“学了就忘”是这个产品要**正面解决**的科学问题，不许用“固定 14 天复习一次”这种拍脑袋规则糊弄过去。
>
> 请用一个**有理论依据**的遗忘模型来驱动复习**时机**，并把“调试”本身做成学习过程（而不是直接给答案）。给我**可计算**的优先级公式，我要能复现。

**AI（节选）**：用 **FSRS-lite**（间隔重复）建模——`R(t)=(1+FACTOR·t/S)^(−DECAY)`，`due_at = last_review + interval(S,0.9)`，`now > due_at` 即到期，`decay_risk = 1 − R`，替代全局半衰期。复习召回区分“曾会现忘”（`mastery ≥ 0.45`）与“掌握薄弱”。调试做成 **Bug 矿洞 L1–L5 逐层揭示**（不一次性给答案）；入矿优先级 `mine_priority = 0.35(1−mastery)+0.20·decay_risk+0.20·recent_fail+0.15·profile_hit+0.10(1−confidence)`。→ 后落为 §3.11。

### 轮次 10 ｜ 多智能体：Agent 不是聊天机器人

> **我**：定一条**反类比**约束——**Agent 不是聊天机器人**。要求：所有 Agent **结构化输出**（禁止返回大段自然语言）、单一职责、故障 **fail-fast**、**禁用 ReAct**（除非我明确开启）。
>
> 再追问一个**信任边界**问题：学习总管怎么把“学生现在最该复习的东西”自动接进看 / 学 / 练 / 测计划？——我倾向**服务端注入**，不信任客户端上送。请说明为什么，以及取数失败怎么办。

**AI（节选）**：11 个默认 Agent（Profile / CurriculumMapper / ResourceDesigner / MindMap / Practice / CodeLab / Storyboard / PathPlanner / Debug / GroundingCritic / Safety）+ 扩展（Orchestrator / IntentRouter / NpcDialog / EvaluationNarrative / 章测 paper 流水线），全部 Pydantic 结构化、fail-fast、不启 ReAct。学习总管由**后端服务端注入** `decaying_kcs`（FSRS 到期最该复盘的前 5，来自 `BugMineService`）——服务端注入可防客户端伪造 / 绕过；取数失败**降级为空、不阻断对话**。→ 后落为 §3.18。

### 轮次 11 ｜ 教师看板：克制是一种能力

> **我**：关于教师侧，我的态度是“**克制是一种能力**”。请你**主动**列出：哪些教师功能“**容易过度设计、但我们这期坚决不做**”（比如实时监控大屏 / 复杂评分 / 协作编码 / 多课程后台），并解释**为什么轻量反而更可信**。然后给出真正该做的**最小看板集合**。

**AI（节选）**：不做——实时监控大屏、复杂评分系统、课堂协作编码、多课程后台（轻量 = 可维护 + 不越界 + 演示可信）。该做的最小集合：星级分布、章测通过率与分数分布、KC 掌握热力图、主线 Stage 进度、无尽活跃，外加 AI 出题抽样审查。性能目标 50 人班聚合 <500ms（快照表 + 5 分钟 TTL 缓存）。→ 后落为 §3.16 与 CON-OUT-06。

### 轮次 12 ｜ 多端：一处定义，多端消费

> **我**：我们要做 5 端（Web / Android / Windows / 微信小程序 / 微信小游戏）。我下一条架构约束：**一处定义、多端消费**——必须有**唯一权威契约**，**禁止**各端凭空发明端点或字段。
>
> 并且我要把“能力收敛”在**契约层强制**：收敛后**不存在的能力**（背包 / 货币 / 商店），各端**不得建 UI**。请说明如何保证不漂移。

**AI（节选）**：5 端共用同一套 Spring Boot 后端（`:18080` `/api` JWT Bearer），以 `docs/clients/api-contract.md` 为**唯一权威契约**，标注 `since R-15` 等版本；各原生 / 微信端**不复用** Web 端 Phaser / `tilemap.ts` / `frontend/src/api/*.ts`（语义一致、实现独立）。契约里**显式声明“不存在的能力”**章节，各端据此不建 UI。SSE 跨端：Web `fetch`+流、原生 OkHttp、微信 `wx.request({enableChunked})`。→ 后落为 §3.19。

### 轮次 13 ｜ 可观测性：资源受限下不丢可信

> **我**：比赛规模，别给我上 Prometheus / Grafana / Jaeger / APM 这种重型监控栈——**但可信和可解释不能丢**。
>
> 请在“**不引入重型可观测栈**”的前提下，**复用项目已有的数据**（审计表）设计一套“**够用 + 面向用户可解释**”的可观测方案。我要的是务实，不是炫技。

**AI（节选）**：走“**审计即可观测 + 面向用户的可解释性**”：① 每次 AI 生成写 `resource_run`（agent / 证据页 / safety / grounding / `graph_trace` / `correlation_id`）；② **决策玻璃盒** `DecisionTraceService` 取学生最近 ≤50 条决策、归一为“为什么 + agent + 证据页链 + 人话结论”；③ healthcheck（`/healthz`、`pg_isready`）；④ SSE 阶段事件。明确**不接** APM / 集中式日志（边界写进 NFR）。→ 后落为 §4.8。

### 轮次 14 ｜ 评审红队 + 反推可勾选验收

> **我**：切换成“**比赛评审 + 爱抬杠的架构师**”，对整套需求做一次**红队**：列出**演示当天最可能翻车**的前 5 个风险，每个配兜底；然后把“**7 分钟可复现演示**”**反推**成一条**可勾选**的验收主链路（我要能照着打勾）。

**AI（节选）**：Top5 风险 / 兜底——① 章测出烂题 → 三审 + 沙箱自测 + golden + 教师抽审；② LLM 不可用 → 预生成解耦 + dryrun/golden；③ 视频版权 → 仅限演示、公开发布替换 CC 资产；④ 计时被刷 → 服务端限频 + 可见性计时；⑤ 多端契约漂移 → 单一权威契约。验收主链路：空库 seed 计数 `7/561/7/65/46/39` → 注册 / 画像 / bootstrap → Stage 三件套 → 章测（零 AI）→ 星级 / 补星 → 训练场三类判题 → Bug 矿洞 + 遗忘回声 → 工坊 6 类 + 审计 → 教师看板。→ 后落为 §5.4 与各模块验收要点。

## 思考深度复盘（贯穿需求的几条主线）

1. **教育目标是唯一裁剪标尺**——“教育优先，游戏承载”从一句口号变成可执行的删减依据（轮 2、6、11），直接催生 R-14 世界收缩与“明确不做”清单。
2. **可信优先级高于功能丰富**——把防幻觉当成**红线（NFR）而非 feature**（轮 4、7、10、13），宁可不答不许编、考试期零 LLM、Agent fail-fast。
3. **用不变量 / 契约 / 单一权威约束演化**——幂等只升不降的星级、唯一权威 API 契约、能力收敛（轮 8、12），让系统在多端 / 多迭代下不漂移。
4. **用科学模型替代经验规则**——FSRS-lite 驱动复习时机、画像置信度量化信号强弱（轮 3、9），而非拍脑袋阈值。
5. **资源受限下的工程权衡**——预生成解耦削峰、单 worker + 队列、轻量“审计即可观测”（轮 7、13），在比赛规模下兼顾性能、稳定与可解释。
6. **全程保留证伪与自我批判**——从开篇要求 AI 攻击立项前提，到收尾要求红队与 TBD 清单（轮 1、14、15），把“想清楚”沉淀为可追踪、可验证、可被挑战的需求基线。
7. **主张必须可证明、可追踪**——个性化要能做对照实验、合规要能溯源授权、需求要能 RTM 反查影响（轮 16、17、19、20），拒绝口说无凭，让每个结论都落到可验收、可定位的工程资产上。
8. **把构建排障变成工程能力展示**——遇到数据库、类型、网络、Agent、Android 构建难题时，不让 AI 猜答案，而是要求日志、根因树、最小复现、分层门禁与最终验证（轮 21-25），体现的是“会指挥 AI 解决真实工程问题”的能力。
