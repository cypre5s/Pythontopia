## 6.5.1 覆盖范围与本片表清单

本片（D1）覆盖 Pythontopia 系统最底层的四个数据域：**M01 账号认证与权限**、**M02 学习画像与个性化**、**M03 中央小镇世界与存档**、**M04 NPC 对话与记忆**。之所以把这四域合为第一分片，是因为它们共同构成其余全部业务（主线、课件、工坊、判题、矿洞、复盘、任务、班级）的「数据地基」：`users` 是全库唯一的身份锚点，几乎所有业务表都以 `user_id` 外键挂靠其上并 `ON DELETE CASCADE`；`learner_profile` 承载 8 维统一学习画像（`dimensions` JSONB）；`world_session` / `player_state` / `save_slot` 构成像素小镇的「运行时 + 存档」三件套；`learning_event_log` 是被动画像演化与记忆流的统一事件源；`npc_*` 系列支撑「NPC 记住你」的个性化记忆。

字典遵循以下统一读法：表名、字段名一律 `snake_case`；主键多为 `BIGSERIAL`（自增 `BIGINT`），少数静态配置表用业务键（如 `skill_node.skill_key`、`npc_persona.npc_key`）作主键；时间列统一 `TIMESTAMPTZ DEFAULT now()`；半结构化数据用 `JSONB`，向量用 pgvector 的 `vector(n)`；枚举值不另建字典表，而以 `CHECK (col IN (...))` 内联约束实现。每张表字典后附「主键 / 外键 / 索引 / 唯一约束」小节与「来源 migration」一行；**凡被后续迁移 ALTER 的表（如 `learner_profile`、`profile_revision`、`world_session`、`player_state`、`save_slot`、`fast_travel_route`、`npc_dialog_state`），都已把后续版本新增 / 变更 / 删除的列并入当前字段集并标注来源版本**。所有字段、类型、约束逐条取自 `backend/src/main/resources/db/migration/` 真实 Flyway 脚本，未作任何臆测。

本片共展开 **23 张活跃表**。已被 R-14「世界收缩」废弃的历史表（如 `crop_tile_state`）不在此展开，仅在 §6.5.6 一句话指向 C06 附录。

## 6.5.2 M01 账号认证与权限

M01 在数据层只有一张表 `users`，却是全库的「根」。它既是 JWT 主体（`username` 唯一、`password_hash` 存哈希、`role` 决定授权），又是几乎所有学习数据表的外键父表。角色枚举随版本演进：V010 初建时只允许 `STUDENT` / `TEACHER`，R-12 引入后台管理需求后由 V112 放宽 `users_role_check` 增加 `ADMIN`，本字典已反映放宽后的最终枚举。

### users — 本地账号

**表 D1-2 `users` 字段字典**

| 字段 | 类型 | 约束/默认 | 说明 |
| --- | --- | --- | --- |
| `id` | BIGSERIAL | PK | 账号主键，全库 `user_id` 外键的目标 |
| `username` | VARCHAR(64) | NOT NULL, UNIQUE | 登录名，JWT subject |
| `display_name` | VARCHAR(128) | NOT NULL | 展示昵称 |
| `password_hash` | VARCHAR(128) | NOT NULL | 口令哈希（不存明文） |
| `email` | VARCHAR(128) | UNIQUE, 可空 | 邮箱，可选且唯一 |
| `role` | VARCHAR(16) | NOT NULL, CHECK IN ('STUDENT','TEACHER','ADMIN') | 角色；`ADMIN` 由 V112 增补 |
| `status` | VARCHAR(16) | NOT NULL, DEFAULT 'ACTIVE', CHECK IN ('ACTIVE','DISABLED') | 账号状态（启用/停用） |
| `created_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | 创建时间 |
| `updated_at` | TIMESTAMPTZ | NOT NULL, DEFAULT now() | 更新时间 |

- **主键**：`id`
- **唯一约束**：`username`、`email`
- **外键**：无（本表是被引用方）
- **索引**：`idx_users_role_status(role, status)`
- **来源 migration**：V010（建表 + 索引）、V112（`users_role_check` 增加 `ADMIN` 并补列注释）

## 6.5.3 M02 学习画像与个性化

M02 把「学生是谁、学到哪、错在哪、还能不能坚持」沉淀为可演化数据。`learner_profile` 是画像主表：V012 建表时按维度拆成多个列（`major` / `base_level` / `cognitive_style` …），R-12 M4 阶段的 `PassiveProfileService` 需要一个统一可被动更新的聚合，于是 V111 增加 `dimensions` JSONB（8 维聚合 + GIN 索引），旧列保留给访谈 upsert 流程，两者并存。`profile_interview` / `profile_revision` 记录画像的「采集会话」与「修订流水」，`profile_revision.source` 枚举随被动管线扩张（V091 加入 EVALUATION/PRACTICE_PASS/PRACTICE_FAIL/DEBUG_FIX，V136 再加 REFLECTION）。`kc_mastery` + `kc_mastery_event` 是掌握度的「当前值 + 追加日志」对。`learning_event_log` 是前端学习事件的统一落库点，也是记忆流（`learner_insight` 反思、`memory_embedding` 向量、以及 M04 的 `npc_memory`）的共同事件源。

## 6.5.4 M03 中央小镇世界与存档

M03 把像素小镇的「运行时」与「存档」落库。`world_session`（一人一会话）是运行时核心：V013 建表只有日/天气/分钟，V107 追加日历四列（月/星期/季节/时段）并新建 `world_event` 事件队列，V115 再追加能量三列——**注意写作总纲 §6.1 中的「world_calendar」「world_session_energy」并非独立表，而是 V107 / V115 对 `world_session` 的 ALTER 列组，本字典已并入下表**。`player_state`（一人一行）存玩家位置/朝向，`direction` 列在 V113 由 `VARCHAR(8)` 拓宽到 `VARCHAR(16)` 以容纳 8 向（如 `DOWN_RIGHT`）。`save_slot` 是显式存档槽（最多 6、`is_active` 唯一），V114 扩出场景/解锁建筑/时长/背包列，V120 加 `snapshot` 的 GIN 索引——**总纲所列「main_quest_save_state(V120)」同样不是独立表，主线进度持久化在 `save_slot.snapshot.mainQuest` JSONB 中；V120 另建的 `boss_attempt` 属 M10，见 D3**。此外 `skill_node`/`learner_skill` 为技能树静态定义与解锁，`world_festival` 为节日时间表，`fast_travel_route` 为快速旅行配置。另有只读聚合视图 `game_bootstrap_view`（V100 建、V107/V113 重建）一次性吐出 bootstrap 载荷，因属视图不在表字典展开。
