# 教学流程建议文档

## 先安排玩家的经历

先确定玩家在场景中遇见谁、为什么学习、如何尝试和怎样获得反馈，再把这段经历落成入口、对白、活动与结束节点。人物介绍学习的目的和情境，具体题量、知识点目录及完成条件由学习工作区展示。

对白使用自然的角色语言。避免在剧情里报出“共有多少道题”“本章有多少个知识点”等容易随课程编辑失效的信息。资料页码可以由工作区定位，人物重点解释阅读时值得思考的问题。

## 一张图可以有多个结束节点

每段交谈、暂时离开、拒绝邀请、活动中止和学习完成，都可以在附近放置自己的结束节点。节点ID必须唯一，可使用 `end-mayor-welcome`、`end-library-later` 等名称。结束节点表示本次互动结束，任务完成仍由服务端验证的活动证据和交谈检查点决定。

按人物和教学阶段分组布局，让结束节点靠近对应分支。只有确实共享后续行为的分支才合流。校验时分别检查每个入口能否走到活动或结束，以及条件不满足、暂时离开和再次进入时的路线。

## 用多轮对白逐步介绍

同一个对白节点可写多轮文本。后台每轮使用一个独立输入框，通过「添加对白」增加下一轮，也可删除单轮；已有多轮对白会自动拆入对应输入框。同一轮内部可换行；角色或实际分支发生变化时再使用独立节点。每轮集中表达一个意思，例如先问候，再引出情境，最后邀请玩家行动。课程包中的 `text` 仍以空行分隔轮次，无需迁移既有内容。

例如图书管理员可以依次说下面三轮。

> 欢迎来到图书馆。课件已经替你准备好了。

> 阅读时想一想，人们为什么不断改进计算工具，又怎样把繁重的工作交给机器。

> 遇到不理解的地方，可以停下来查阅资料。准备好了，我们就开始吧。

玩家点击继续后进入下一轮。选项在最后一轮出现，交谈检查点也在读完最后一轮并继续后触发。轮次保存在当前互动会话中，刷新或暂时离开后恢复；重复请求不会跳过下一轮。修改正在使用的对白仍需遵循后台的影响确认规则。

## 活动与反馈

人物给出简洁邀请，活动节点打开具体阅读、练习或测验。完成、暂停和不可用分别安排回复，暂停允许玩家稍后回来。测验反馈使用真实判定结果，低分可以引导复习；第一章旅程结束后仍可回到资料库和练习场。

## 目录课程包

当前课程包直接放在 `data/course/<课程包目录>/`，目录根部包含 `manifest.yaml`、`curriculum/`、`content/`、`world/`、`assets/` 等标准内容。后台选择目录后生成私有暂存副本、校验并展示差异，教师确认后应用。导出生成同一交换目录下的独立课程包目录，并返回路径。

ZIP上传入口当前关闭。课程包包含私有答案，交换目录应保持服务端私有。后台导出的目录只向当前班级授权教师展示；管理员放入的共享课程目录可供教师选择。课程包格式、内容约束与班级数据保护以[内容规范](content-authoring.md)为准。
