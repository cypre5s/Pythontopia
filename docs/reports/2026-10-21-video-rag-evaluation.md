# 视频与课件 RAG 优化评估

## 结论

不建议现在把 7 份 PPT 对应的课件页整体重新切片。当前 RAG 已按真实课件页切分，每块保留原页 `page_id`，索引文本带章节、页码和标题上下文，引用正文仍是原始课件文本。全量重切会增加重新索引与引用回归成本；本轮固定黄金集基线已达到 Recall@5 100%，没有证据支持盲目改变这条切分链路。

视频值得增加独立的时间戳检索层。它可以帮助原查询没找到课件页时定位视频章节，再从同章的真实课件页补充证据；字幕本身不进入回答证据或页码引用。

## 现有课件切片

- `chunk_page` 先按 Markdown 标题切分，再以 700 字符为目标、100 字符重叠滑窗；输入是一页课件，不跨页拼块。
- 嵌入与 BM25 文本附加课程名、章节、页码和页标题；`Chunk.text` 保持课件原文，引用仍指向真实 `page_id`。
- 这个结构适合保留 PPT 页码与引用来源。若后续标注集显示特定页面召回差，再针对这些页面调整标题/讲者备注抽取或分块参数。

## 视频数据与实现

- 课程清单有 34 条视频；字幕文件有 848 个时间片段，标记为 `machine_generated_unreviewed`。
- 新索引过滤 `avgLogProb < -0.6` 或 `noSpeechProb > 0.5` 的片段。本次 848 个片段全部通过该筛选；这只表示通过基础 ASR 质量门槛，不代表人工审核正确。
- 字幕通过 `videoId` 与视频清单关联，查询时返回最多两个章节的视频时间点。再用视频标题和代码标识符，在映射到的课件章节内运行现有页检索，并遵守原有 `chapter_ids` / `kc_codes` 过滤。
- 每次查询最多追加两条真实课件页。`hits` / `citations` 中只有课件页；`video_trace` 只返回视频标题、章节、时间范围、匹配分和审核状态，不返回 ASR 文本。
- 开发与生产 RAG 容器将课程数据目录只读挂载到 `/data/course-pack-43`。生产路径使用已有共享数据目录，数据库卷和共享数据不被清理或重建。

## 限制与后续评估

- 字幕目前未经人工校对，因此只用于检索路由；回答必须继续依据课件原文和页码。
- 57/59 只说明当前查询集能匹配到片段，尚未测出视频匹配精度；需要教师标注的查询/视频时间点集才能做 precision 或 NDCG 评估。
- 若真实课程问题出现召回缺口，应优先补充同页标题、PPT 讲者备注或经审核的视频关键词，再用真实页 ID 做 A/B；不应仅以更多切片数量作为效果指标。
